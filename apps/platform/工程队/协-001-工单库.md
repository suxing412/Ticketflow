## 二、四个决定

### 决定 1 · 状态机先做四态

```
草稿 ──► 待投 ──► 在途 ──► 完成
          ▲         │
          └─────────┘
           退回重投
```

studio 那套是八态加挂起族（`草稿→待投→在途→质检→待验收→初检→深检/核查→完成`），
在游戏产线上是被实战打磨出来的。但 platform 还没有一次真实派发，**照抄一套没跑过的状态机
只会把复杂度提前引进来**。先四态跑通，缺什么再加什么。

明确**本期不做**：挂起族（原位冻结/解挂/全树连带）、质检与验收分离、仲裁、上呈、
返修同号回炉、废弃。这些不是遗忘，是排期——`STATES` 与 `TRANSITIONS` 都做成表驱动，
加态是改表不是改逻辑。

> 依据：`plan.js` 的 `materialize` 只用到 `草稿` 与 `待投` 两态
> （`store.move(root, id, '草稿', '待投')`），四态足够它跑通。

### 决定 2 · 工单落业务私仓

工单是**业务数据**，不是产品代码。按 `docs/仓库总说明书.md` 第一章的切分判据——
「知道业务是什么」的层各归各家——它该和 studio 的工单一样住私仓，公开仓里只有机器。

落盘根目录由配置指定，**不入库**（机器相关）：

```jsonc
// config/工单库.local.json   ← *.local.json 已被 .gitignore 挡住
{ "根目录": "D:\\GitHub\\AI-DevPlatform\\工单" }
```

环境变量 `PLATFORM_TICKETS` 可覆盖。**两者都没有时不猜、不兜底**，直接让相关接口
返回明确的未配置错误——猜一个路径然后往里写业务数据，是比报错严重得多的事。

### 决定 3 · 工单库住 server 进程（我定）

`lib/工单库.js`，只用 `fs` + `path`，**不引 `child_process`**。

理由：工单落盘是纯文件操作，压根不需要 git。把它塞进工作区服务反而要多绕一次 http、
多一处失败面，换不来任何隔离收益——隔离是为了挡住"起进程"这个能力，而它不需要那个能力。

所以桩模式的物理保证不受影响，`test/接线契约.test.js` 那条传递闭包断言一个字都不用改。

**但它引入了一个新能力：server 进程可以往仓库之外写文件。** 这个能力和 git 能力是同一
量级的东西，不能因为"只是写文件"就不设防。故：

- 工单库自带**路径闸**：所有路径收窄到配置的根目录之内，越界即拒（与工作区服务同款）；
- 工单编号做**字符白名单**（`[A-Za-z0-9._-]`，长度上限），杜绝 `../` 与设备名穿越；
- 契约测试里加断言盯住这两条。

### 决定 4 · 本期不碰 git（我定）

工单落盘走 `fs`，与工作区服务**互不相干**。

`派活 → 执行 → 提交` 那条链最终要碰 git，但那是**下一张令**（协-002）的事。本期交付
到「工单能被创建、能流转、能被 `materialize` 落盘」为止，不含任何执行器接线。

工作区服务的写开关（`workspace.允许写`）**保持默认关闭**，本期不动它。

## 三、接口契约

必须对齐 `plan.js` 已有的调用点，这是硬约束不是设计自由度：

| 方法 | 签名 | 返回 |
|---|---|---|
| `find` | `(根, id)` | `{ id, state, file, fm, body }` ｜ `null` |
| `create` | `(根, id, fm, body)` | `{ ok:true, id, state:'草稿', file }` ｜ `{ ok:false, error }` |
| `move` | `(根, id, from, to)` | `{ ok:true }` ｜ `{ ok:false, error }` |
| `update` | `(根, id, mutator)` | `{ ok:true }` ｜ `{ ok:false, error }`；`mutator(fm, 工单)` 可返回 `{ body }` |

另需 `STATES` / `TRANSITIONS` / `list` / `parse` / `serialize`，供接口层与测试使用。

**目录即状态机**：`<根>/<状态>/<id>.md`，状态迁移 = 文件移动。这套借鉴 studio 的做法——
它的好处是状态永远可肉眼核查、可 grep、可 git diff，不需要额外的索引文件保持一致。

工单文件用 frontmatter + 正文，`parse`/`serialize` 自己实现（不引第三方 YAML 库，
运行时零依赖是本产品的既定口径）。

## 四、接口层（本期一并交付）

| 接口 | 作用 |
|---|---|
| `GET /api/tickets?state=` | 列工单，可按状态过滤 |
| `GET /api/tickets/:id` | 取单张（含 fm 与正文） |
| `POST /api/tickets` | 建单（落 `草稿`） |
| `POST /api/tickets/:id/move` | 状态迁移，非法转移拒绝并说明 |
| `POST /api/plan/materialize` | **把 `/api/plan/validate` 的下半场接上**：注入工单库落盘 |

全部走既有门禁三道闸，无新增例外。

## 五、验收标准

1. `npm run check` ✓、`npm test` ✓，且**新增一套 `test/工单库契约.test.js`**；
2. 桩模式断言原封不动仍绿（证明工单库没把 `child_process` 带进来）；
3. 路径闸反向验证：`id=../../evil`、`根目录` 之外的路径，双双被拒且报人话错误；
4. 非法状态转移被拒（如 `草稿 → 完成`），错误信息写明合法路径；
5. `/api/plan/materialize` 端到端：喂一份合法计划 → 子工单落进 `草稿` 再自动迁到 `待投`，
   父单 fm 写入 `计划生成`；重复喂同一份**幂等**（已开工的子单不被覆盖，对齐
   `plan.js` 现有的 `retained` 语义）；
6. 未配置根目录时，相关接口返回明确的未配置错误，**不猜路径不兜底**；
7. 私仓路径不得出现在任何入库文件里（配置走 `*.local.json`）。

## 六、风险与预案

| 风险 | 预案 |
|---|---|
| 工单写进错误目录（配置错） | 路径闸 + 未配置即拒；开机日志打印实际根目录 |
| 与 studio 工单库形态分叉，日后难合 | 接口签名刻意对齐 studio 的 store，将来若抽 `packages/core` 迁移成本最小 |
| 四态不够用 | 表驱动，加态改表；本令明列了本期不做的项，不是遗忘 |
| server 获得仓外写能力 | 见决定 3 的三条约束，契约测试盯住 |

## 七、不做什么（明确边界）

- 不碰执行器、不起任何 AI 进程，桩模式边界不变；
- 不动 `workspace.允许写`，本期它保持 false；
- 不改 studio 任何文件，不动 `packages/`；
- 不实现挂起/仲裁/返修/废弃/质检验收分离。
