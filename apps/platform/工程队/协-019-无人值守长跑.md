# 协-019 · 无人值守长跑（可在线服务级）

- 提出：2026-08-23
- 拍板：仓主选「单机无人值守长跑」——**仍绑 127.0.0.1，不动认证与暴露面**
- 参考：studio 0.26.14~0.26.17 的三条实证（闸注册表换轴 / 端点级实跑测试 / 拒因去重静默窗）

## 背景

平台今天能跑，但**只在有人看着的时候能跑**。六条具体的：

1. **一个子进程死了就全停**（`开机.js` 的现行策略）。这条在有人盯着时是对的——半个产品比
   全停难查。可无人值守时它的意思变成了：**凌晨三点执行器崩一次，整台机器停到早上**。
2. **告警没有出口**。`巡检` 是纯函数，只在 `/tick` 被调用时现算现报；没人调 `/tick` 就没人算。
   而 `呼叫/inbox.jsonl` 至今 **0 字节**——这条机器信道从产品出厂到今天没有任何一处往里写过。
3. **没有「现在欠人几笔」的单一谓词**。要人自己翻看板猜哪张单在等自己。
4. **Ctrl-C 会把在跑的活丢下**：在途单没有任何标记，重启后它永远停在在途
   （`巡检.js` 自己的注释里就写着这条成因）。
5. **流水无限长**：`journal/provider-runs.jsonl` 已 90KB 且只增不减，呼叫信箱会是第二个。
6. **配置错误要等到用的时候才炸**：`/api/selfcheck` 存在，但没人在开机时跑它。

## 范围

① `lib/呼叫.js`：平台侧的机器信道（`呼叫/inbox.jsonl`，append-only + 游标水位）。
   **自带去重**：同指纹在静默窗内只记一笔——直接抄 studio 08-20 的实证教训（品味锁把同一个
   切换拒了 265 次、九天死循环表现为一条不动的红标）。**去重的是记账不是判断**。
② `lib/闸注册表.js`：`等我()` 谓词 + `/api/attn` 只读端点。定义域是**闸**不是工单状态。
   响应型才进清单，发起型 `判据: null`（无队列的动作不可能有 pending，硬塞进去只会造假账）。
③ `开机.js` 转守护：子进程崩溃 → 指数退避重启（不再一并停），重启事件进呼叫信箱；
   **连败熔断**：短窗内连崩 N 次才全停并发急报——自恢复不能变成崩溃循环。
④ 优雅停机：`SIGTERM/SIGINT` 时执行器把在跑的工单标记「服务重启中断」并落盘，不静默丢活。
⑤ `/api/ready` 就绪探针（区别于 `/api/health` 的存活）：工单库可读 / 公用件可载 /
   工作区与执行器可达 / 配置自检无致命项。开机时自检跑一遍，致命项进呼叫信箱。
⑥ `lib/轮转.js`：jsonl 按大小切分归档，保留 N 份。
⑦ 端点级实跑测试那一格（**照 studio 0.26.16 立的规矩**）：新端点必须有真起服务打一遍的断言。
   本单补 `/api/attn`、`/api/ready`，并**补上协-018 欠的 `/api/quota`**——那次只有 lib 层断言。
⑧ `scripts/自启.js`：注册 Windows 登录自启计划任务（照 `watchtower:install` 先例）。

## 不要做

- **不动认证与暴露面**：仍绑 `127.0.0.1`，仍是单令牌。多用户/公网是另一轮，且要先出威胁模型。
- **不动真跑四闸**，不改额度闸/预算闸的判据。自恢复只恢复进程，不代人同意任何花钱的事。
- **重启不重派**：崩溃重启后不自动把中断的工单重新派出去——那是花钱的决定，留给人。
- 不引入新依赖（无 pm2、无 winston、无 cron 库）。
- 不做告警外发（邮件/webhook）。信箱是出口，谁来取是另一件事。

## 验收标准

□ 杀掉执行器进程 → 5 秒内自己回来，呼叫信箱多一条「执行器重启」
□ 连续崩溃 5 次（60s 窗）→ 全停 + 一条「急」级呼叫，说明为什么不再重启
□ `Ctrl-C` 时在途单被标记「服务重启中断」，重启后巡检能认出它，且**不自动重派**
□ `/api/attn` 报出欠人的每一笔，带 `gateKey` 幂等、按停摆时长降序、逾期升格
□ 同一条告警重复发生 100 次，信箱里只有一笔（静默窗内），状态变化时才落新的一笔
□ `/api/ready` 在工单库缺配时报 503 并说清缺什么；`/api/health` 照旧 200（存活≠就绪）
□ 三个新端点各有一格**真起服务**的断言（不是 lib 层单测）
□ `npm test` 全绿（既有 242 项一条不许红）
