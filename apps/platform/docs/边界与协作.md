## 二、五条口径

1. **预算池归 `packages/budget`，robinwang2 主导**——按量计费与预算统计的公共逻辑落该包，
   接口仍走双签；两侧产品各自消费，不各造一套。
2. **动对方 app 先对齐**——任何一方要改对方产品目录（`apps/studio`↔`AI-DevPlatform`），
   先经信箱/协作施工令层面对齐，对方点头才动手；紧急也不例外。
3. **施工令命名空间**——跨方协作事项用 `协-NNN` 序列，与两侧内部序列（`施工令-NNN`）不混编，
   避免同号撞车与归档混淆。
4. **公用件唯一家 `packages/`**——凡两个产品都要用的逻辑，唯一正本只能住 Ticketflow
   `packages/`；发现重复实现，以 packages/ 为准收编，另一份删除。
5. **PR 双签、作者合并**——公用件的 PR 由双方评审签核，签核齐后**由作者本人合并**；
   不代合、不抢合。

## 三、信箱协议（全文）

两座瞭望塔、一个交换仓（Ticketflow），不发明新信道。

### 收发匣约定（跨方信件，走 git）

- 给对方的信写成 **md 文书**，落在 **Ticketflow 仓** `docs/信道/` 下对方的收件匣，提交推送：
  - 给 robinwang2 的信 → `docs/信道/收-robinwang2/`
  - 给总监的信 → `docs/信道/收-总监/`
- 路径带「信道」，对方瞭望塔的远端信源（`git fetch` 只侦察不合并）自然把触文认成信道文书。
- 文书命名建议带日期与主题（如 `2026-08-09-交接回执.md`），一事一文。

### 本平台侧分拣（已出厂预配，`config/规则.json`）

| 触文位置 | 处置 |
|---|---|
| `docs/信道/收-robinwang2/` | **急** + 弹通知 + 记未读（有我的信） |
| `docs/信道/收-<别家>/`（含 `收-总监/`） | 只记流水（旁听不打扰） |

本方名 = `robinwang2`（`config/瞭望塔.config.json` 同名字段）。

### 本地信箱（自己人/本机流程投递）

往 `呼叫/inbox.jsonl` 追加一行 JSON：

```json
{"t":"<ISO时刻>","级别":"急|常","类型":"<类型>","摘要":"一句话"}
```

`级别=急` 默认弹通知，其余按规则表分档；会话不在场的积压落 `watchtower-out/未读账本.jsonl`，
回来 `npm run watchtower -- --unread` 看账、`-- --ack all` 清账。

### 守护纪律

- 守护对被盯仓**只 fetch 不 pull/merge**，工作区零改动；断网自动暂歇、恢复即续。
- 瞭望塔正本住 Ticketflow `packages/watchtower`（公用件口径 4），本仓只带配置与启动器。
