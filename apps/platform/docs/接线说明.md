## 一、装守护

```
npm run watchtower                 # 前台起守护（试跑/调试用，Ctrl+C 停）
npm run watchtower:install         # 注册登录自启计划任务（任务名 AI-DevPlatform瞭望塔）
schtasks /Run /TN AI-DevPlatform瞭望塔    # --install 只登记不当场启动，补这句拉起
```

任务名带平台前缀，避免与同机其他瞭望塔任务（如监制台侧的「瞭望塔」）撞名互踩；
卸载：`npm run watchtower -- --uninstall`（启动器会自动补同名 `--task-name`）。

验收三连：

- `npm run watchtower:status` → `在岗:true`，且心跳段 `在跳:true`（`watchtower-out/心跳.txt` 每 30s 覆盖写，断更即守护不在）；
- `npm run watchtower -- --toast-test` → 桌面弹出测试通知（BurntToast→气泡→msg 三档回落）；
- 看 `watchtower-out/瞭望塔流水.log` 有「瞭望塔上岗」行；
- 加一条平台侧的：开着 `npm start` 刷新 `http://127.0.0.1:4370`，在岗灯绿。

## 未接线（1/6）——是决定，不是遗漏

**`workspace/worktree.js`** — 它 `require('child_process')`。接进 `server.js` 就等于让这台
服务能起真实进程，`server.js` 头部那句「任何路径都发不起真实 CLI 进程，零计费」当场失效。
这是出厂时刻意锁定的边界，要突破得是显式决定，不能顺手带进来。契约测试里有一条传递闭包
断言盯着，谁接谁红。

### 已解决：plan.js 的跨产品依赖

它原先 `require('../../../studio/lib/core/store')`，直接伸手进**另一个产品的内部模块**——
`docs/边界与协作.md` 定的规矩是公用件唯一家在仓根 `packages/`、双签共建，对方的内部实现
不是可依赖的 API（studio 改自己的内部结构时根本不会知道我们在用）。

**改法是把 store 变成注入**，而不是去动 studio：`materialize(root, cfg, parent, plan, store)`
由调用方把工单库递进来。于是纯计算的五个导出（`extractJson` / `configuredPlanFile` /
`resolvePlan` / `normalizePlan` / `bodyOf`）不再有任何跨产品依赖，当场可接线；落盘的
`materialize` / `consume` 等 platform 有了自有工单库再用，缺 store 时明确抛错，不静默降级
（悄悄什么都不写比直接失败难查得多）。

> 该盲区已补：`test/公用件契约.test.js` 新增一条断言，把相对 require 解析成真实路径后
> 判断是否跑出本产品目录且不在 `packages/` 下，跨产品直引即红。原先那条依赖面断言
> 认的是 `packages/xxx` 形态，`../../../studio/lib/...` 完全不在它雷达上。

## 排名的区分度：如实自曝，不假装有判断

`/api/routing/rank` 三家分数仍然全平。这不是缺陷，是**还没有可依据的数据**：
`providers.<名>.scores` 出厂留空（厂商孰优孰劣不该由出厂配置替仓主拍板），
`journal/provider-runs.jsonl` 也还没有战绩（桩模式不写账）。

处置不是编几个分数糊上去，而是让接口**自己说清楚**：响应新增 `有区分度` 字段，平局时
说明里写明「当前顺序仅按名称字母序，不代表评估结论」，并给出三条让排名产生信号的途径
（显式 `scores`、`routing.roles.<角色>.prefer` 偏好、或积累实际战绩）。

把「字母序第一」当成「评估最优」比没有排名更危险——它看起来像个判断，实际零信号。

`config/platform.config.json` 同批补了两段：
- `roles` — 角色词表。不是随手起的，是 `plan.js` 的既有契约（它按 roles 的键校验子任务
  角色，并对 reviewer 设了只读约束）。缺这段时任何计划都判「使用未知角色」。
- `routing.weights` — 加权策略。数值与 `router.js` 的内置默认一致，**填上不改变当前行为**，
  只是把隐式默认变成显式声明，让公式可见可调。

# 五、门禁（2026-08-10）

## 挡的是什么

`server.js` 绑 `127.0.0.1`，挡得住局域网里的别的机器，**挡不住你自己浏览器里的页面**——
浏览器就在 localhost 上。而 `收体()` 不看 `Content-Type`，拿到什么都直接 `JSON.parse`。

两件事凑一起就有条路：用 `Content-Type: text/plain` 发 JSON 属于跨域**简单请求**，
不触发 CORS 预检，于是你随手打开的任何网页都能往 `127.0.0.1:4370` 发 POST 并被执行到底。
浏览器只拦住它*读取*响应，请求本身照发不误——对会改状态的接口来说，伤害已经造成。

这条路是实测确认的，不是推演：伪造 `Origin: https://evil.example` + `text/plain`，
接口照收，返回 `"ok": true`。

补门禁之前它不构成风险，因为三个 POST 全是纯的（echo 是桩、review/parse 与 plan/validate
只算不写），最坏结果是白算一次。但这正是接 `workspace/worktree.js` 之前必须先补的东西——
那个模块会 `git commit` / `git merge`。

## 三道闸

按从便宜到贵排：

| 闸 | 规则 | 挡谁 |
|---|---|---|
| ① Origin | 带 `Origin` 且非本站来源 → **403** | 浏览器里的跨站页面 |
| ② Content-Type | POST 非 `application/json` → **415** | 「简单请求」免预检那条路 |
| ③ 令牌 | 缺/错 `Authorization: Bearer` → **401** | 本机其它进程 |

`curl` 与瞭望塔守护不带 `Origin`，前两道对它们天然放行——它们本来也不在威胁模型里。

## 三件配套决定

**门禁在路由之前。** 放在之后的话，未知路径的 404 会泄露「哪些接口存在」。未授权者不该
有能力区分「这条不存在」和「这条存在但你进不来」，所以未授权时一律 401。

**`/api/health` 免令牌，且只此一条。** 瞭望塔守护按 `config/瞭望塔.config.json` 的心跳
地址探它，而守护住在仓根 `packages/`（双签共建），我们没法单方面让它带令牌。它只吐
版本/端口/路径，跨域又读不到响应，例外成本可接受——Origin 与 Content-Type 两道闸对它
照样生效。契约测试钉死了这份名单，加条目必须是显式决定。

**令牌随首页注入，UI 一行不改。** 服务发 `index.html` 时在 `</head>` 前插一段脚本，
包住 `window.fetch` 给同源 `/api/` 请求自动补上 `Authorization` 与 JSON 头。
跨站页面读不到本页内容，也就拿不到令牌。

## 用法

令牌落在 `config/接口令牌.local.json`（被 `.gitignore` 的 `*.local.json` 挡住，不入库），
开机日志会打印路径。浏览器打开首页无需手工填；`curl` 需要自己带：

```
curl -H "Authorization: Bearer $(node -p "require('./config/接口令牌.local.json').令牌")" \
     http://127.0.0.1:4370/api/providers
```

令牌落盘复用不每次重生成，否则存下来的 curl 别名每次重启都失效。**要轮换就删掉那个文件
再起服务。**

## 还没做的（接 worktree 前的剩余三步）

门禁只是第 1 步。`workspace/worktree.js` 仍未接，后面还有：

2. 只读的先接（`worktree list` / `diff` / `changedFiles`），风险与现在无异；
3. 写操作（`worktree add` / `add -A` / `commit` / `merge`）单独隔离，不进 `server.js`
   的依赖闭包，让那条传递闭包断言继续守着 server 本身；
4. 改断言而不是删断言——把「禁止 child_process」调整成明确的例外清单，
   让下一次误接仍然会红。

# 六、工作区隔离（2026-08-10）—— 接 worktree 四步的第 2/3/4 步

## 先纠正一处判断

第五节末尾我把剩余步骤写成「只读的先接，风险与现在无异」。**那句不准确。**

`worktree.js` 里所谓的只读函数——`isGitRepo` / `repoTop` / `worktreeList` / `changedFiles`——
底下全是 `spawnSync('git', ...)`。读 git 状态**照样要起进程**。所以「只挑只读的接」并不能
绕开「server.js 任何路径都发不起真实进程」这条保证，它只是不改仓库而已。

结论：绕不过去，只能隔离。

## 方案：把 git 能力挪出 server 的进程

```
浏览器 / curl
     │  /api/workspace/*      （带令牌）
     ▼
server.js ──── http 转发 ────► scripts/工作区服务.js ──► git 子进程
（只用 http，                  （唯一持有 worktree.js
  永不 spawn）                   的地方，独立端口 4371）
```

`server.js` 的依赖闭包依旧零 `child_process`，所以**那条传递闭包断言一个字都没改**。

这就是第 4 步的答案：不是「把禁止改成例外清单」，而是**根本不需要例外**。
实测确认：故意把 `worktree.js` 直接 require 进 `server.js`，原断言当场点名
「lib\workspace\worktree.js 引入了 child_process」。

## 接口

隔离进程自己也有门禁（同一个令牌文件），**没有免令牌例外**——瞭望塔不探它，
没有非带不可的理由。

| 经 server 的路径 | 作用 |
|---|---|
| `GET /api/workspace/health` | 服务自述：仓根、写开关状态 |
| `GET /api/workspace/repo?dir=` | 是否 git 仓、仓顶在哪 |
| `GET /api/workspace/worktrees?repository=` | worktree 清单 |
| `GET /api/workspace/changes?dir=` | 已改动文件清单 |
| `*/write/*` | 写操作，默认 **403 未启用** |

路径一律用 ASCII。中文路径踩过坑：`new URL().pathname` **不解码**百分号编码，
而浏览器与 curl 都会编码，于是 `路径 === '/仓库信息'` 对任何规范客户端都匹配不上。

## 三道防线

**路径闸。** 传进来的 `dir` / `repository` 一律收窄到仓根之内，越界即 400。
不做这关的话，带令牌的调用方可以拿 `dir=C:\` 把本机的 git 仓库探个遍。
实测：`dir=../../../Windows` → `路径越界：只允许仓根 D:\Ticketflow 之内`。

**写开关。** `config/platform.config.json` 的 `workspace.允许写`，默认 `false`。
把 `git commit` / `merge` 挂到 HTTP 上是一项**独立的授权决定**，不该由「服务起来了」
顺带获得。开启后也只回 501 未实现——具体哪个写操作要暴露、以什么形状暴露，逐个决定逐个做。

**优雅降级。** 隔离进程默认不随 server 启动。没拉起来时转发返回 503 并说明
`npm run workspace`，而不是把 500 甩给调用方。

## 用法

```
npm run workspace     # 拉起隔离进程（默认 4371），要用工作区接口才需要
npm start             # 平台服务照常，不依赖上面那个
```

两个进程互不阻塞：工作区服务没起，平台其余接口一切照常。

# 七、工单库（协-001，2026-08-10）

`lib/工单库.js` + 五条接口。施工令全文见 `工程队/协-001-工单库.md`。

## 目录即状态机

```
<私仓>/工单/
  草稿/  待投/  在途/  完成/     ← 状态迁移 = 文件移动
```

状态永远可肉眼核查、可 grep、可 git diff，不需要额外索引文件保持一致。

四态：`草稿→待投→在途→完成`，外加 `在途→待投` 退回。表驱动，加态改表不改逻辑。
本期不做：挂起族 / 质检验收分离 / 仲裁 / 上呈 / 返修同号回炉 / 废弃。

## 根目录必须显式配置

工单是业务数据，落业务私仓。二选一：

```jsonc
// config/工单库.local.json  （*.local.json 已 gitignore）
{ "根目录": "D:\你的私仓\工单" }
```

或环境变量 `PLATFORM_TICKETS`（优先级更高）。

**两者都没有时不猜、不兜底、不建默认目录**，相关接口一律 503 + 人话修法。
猜一个位置往里写业务数据，等发现写错地方时数据已经散在两处了——比直接报错严重得多。

## 为什么住 server 进程而不是工作区服务

落盘是纯文件操作，压根不需要 git。塞进隔离进程只会多绕一次 http、多一处失败面——
隔离是为了挡住「起进程」这个能力，而它不需要那个能力。桩模式断言因此一字未改。

**但它确实引入了新能力：server 可以往仓库之外写文件。** 三条约束顶上：

| 约束 | 实测 |
|---|---|
| 根目录必须显式配置 | 缺配置 → 503，且报错路径上不建任何目录 |
| 路径闸收窄到根之内 | 越界 → 拒 |
| 编号白名单 + 设备名黑名单 | `../../evil`、`CON`、`a/b` → 拒，且仓外无文件产生 |

## JSON frontmatter（与 studio 的取舍）

studio 用 `gray-matter`（第三方），本产品运行时零依赖引不进来。自己手搓 YAML 又是坑：
`plan.js` 往 fm 里写的 `routing`、`计划生成` 都是**嵌套对象**，手写解析器处理
嵌套/转义/多行是经典的静默出错来源，而这里存的是业务数据，错了不一定当场发现。

改用 JSON frontmatter：内置 `JSON.parse/stringify`，往返精确、不可能歧义。
代价是格式与 studio 不同；但真到抽公共件那天，写个格式转换器是**小而明确**的活，
远小于「手搓 YAML 静默损坏嵌套字段」的风险。

> 接口签名（`find`/`create`/`move`/`update`）仍**刻意对齐 studio 的 store 形状**——
> 那是 `plan.js` 调用点的硬约束，且将来迁移成本最小。

## 五条接口

| 接口 | 作用 |
|---|---|
| `GET /api/tickets?state=` | 列单，可按状态过滤（未知状态 400） |
| `GET /api/tickets/:id` | 取单张（fm + 正文） |
| `POST /api/tickets` | 建单，落 `草稿`（201） |
| `POST /api/tickets/:id/move` | 状态迁移，非法转移 409 并写明合法去向 |
| `POST /api/plan/materialize` | 把 `/api/plan/validate` 的下半场接上：注入工单库落盘 |

全部走既有门禁三道闸，无新增例外。

# 八、执行链（协-002，2026-08-10）

**这是平台第一次具备真的花钱、真的改文件的能力。** 施工令全文见 `工程队/协-002-执行链.md`。

## 三个进程，各管一种能力

```
server.js  ──http──► scripts/工作区服务.js   git
（只转发，   ──http──► scripts/执行器.js       拉起 AI CLI
  永不 spawn）
```

两个隔离进程**默认都不随 server 启动**，可以单独关掉任意一个。
`server.js` 的依赖闭包依旧零 `child_process`——那条传递闭包断言第三次不需要例外。

## 真跑三闸（拍板 C）

缺一即拒，三条各自独立、不互相替代：

| 闸 | 配置/参数 | 防的是 |
|---|---|---|
| ① 请求体 `{"干跑": false}` | 默认干跑 | 手滑 |
| ② `执行.允许真跑: true` | 默认 `false` | 「服务起来了就能花钱」 |
| ③ 该池在 `预算.池` 配了上限 | 默认空 | 没有刹车就上路 |

干跑走**完整链路**（选人、组装调用、写战绩），只是不 spawn，零计费。
**干跑不流转工单**——演练不该改变状态。

## 权限白名单（拍板 A3）

```jsonc
"执行": { "权限": {
  "放开": ["backend", "frontend", "integrator"],
  "受限参数": ["--permission-mode", "plan"]
} }
```

判据只看角色不看项目。**白名单之外一律受限，缺配置即最严不是最松**——
契约测试专门钉了「没有 `执行.权限` 段时 backend 也必须受限」，因为这条错了就是默认放开。

受限模式会把适配器默认的 `--dangerously-skip-permissions` /
`--dangerously-bypass-approvals-and-sandbox` **从调用参数里剥掉**，换上受限参数。
实测 `reviewer` 的调用里 `--dangerously-` 剩 0 个。

## 四条加固（决定 2）

照 studio runner 的行为重写，不复制代码（跨产品直引已被禁）。四条都是产线上真炸过才补出来的：

| 加固 | 语义 |
|---|---|
| 软超时验尸 | 到点先看**还有没有活口**；仍在输出就续命，真静默才杀，验尸报告带活尾巴 |
| 判官失败不打整单 | 判官崩溃/零输出/无结论 = **判官的**失败，工单维持原状待重判 |
| 空输出不作数 | 退出码 0 但零输出是静默失败，记成功会**污染路由战绩** |
| 候选链降级 | 首选被冻结就顺位取，但**必须留痕**，否则账单与战绩对不上号 |

## 闭环：战绩 → rank 有区分度

`routing/history.js` 接线很久了但**从没有人写过**，所以 rank 一直全平。执行链是第一个写入方。

⚠️ **但施工令验收第 7 条（「战绩写入后 有区分度 变 true」）本期并未真正满足**：
干跑写的是 `dry` 行，而 `history.summary` **有意**过滤掉 dry——否则 rank 就成了
「谁演练得多谁排前面」。那一条**只有真花钱才能满足**。

本期改用合成的非 dry 战绩证明机制本身是通的（写进去 → summary 认 → 分数分开），
并反证了干跑刷 20 条也不产生任何区分度。**真实花钱那条路径至今未跑过，如实记录。**

## 一处继承来的限制

codex 不是 stream-json 输出，`budget.usageOf` 取不到它的 usage，**其消耗不计入预算账**。
这不是本期引入的缺陷，但本期是第一个真会花钱的使用方，所以执行器在选中 codex 且非干跑时
会在回执里显式写明「本次消耗不计入预算账」——**闷着跑等于账目失真**。

## 账本根必须两边一致

执行器写战绩、server 的 rank/history 读战绩，两边用的根**必须是同一个**，
否则写进 A 读的是 B，闭环从一开始就断。默认都是平台根；`PLATFORM_JOURNAL`
只为测试隔离而存在，改它必须两边同改。

# 九、产线化（协-004，2026-08-10）

把「手动一张张点」变成「知道该派谁、并且知道为什么没派」。

## 依赖集成：DAG 写在工单里就得被执行

`plan.materialize` 生成的子单带 `fm.依赖`，但**此前没人检查过**——子单可以在依赖还没
干完时就被派出去，拿到一个缺半截的工作区。DAG 写在工单里却不被执行，等于没有 DAG。

现在派活前查依赖：**必须全部「完成」**，否则拒派并逐个点名卡在谁身上
（`D-1(草稿)`），不是笼统一句「依赖未就绪」让人自己去翻。

### 一处必须补的契约缺口

`worktree.integrate` 靠依赖单的 **`fm.workspace.commit`** 取检查点。而协-003 只写了
`fm.检查点`——两者不是一回事。不补的话 `integrate` 会把每个依赖都判成
「没有可集成的检查点」而 **静默跳过**（`skipped` 而非报错），DAG 就断在这里，
**且全程没有任何错误信息**。

现在 `落单` 写 `fm.workspace`，完成时回填 `commit`。

## 调度：算得出该派谁，也说得出为什么没派

`GET /api/exec/tick` 只**算**不派：待投多少、在跑多少、本轮可派哪几张、
每张跳过的**逐条原因**。

排序按优先级 → 创建时间。同级先来先服务，防新单插队把老单饿死。

**并发上限默认 1**，这是有意的：并发是加速手段不是默认姿态。一次一单最容易分诊，
出事时也只烧一份钱。要并发是显式决定（`执行.并发.<池>` 或 `执行.并发.默认`）。

### 有意不做后台自动连跑

`/tick` 只算，真派仍要一张一张 `POST /run`，每张独立过真跑三闸。

**让一个能自己花钱的循环在后台无人值守地转，是另一个量级的授权**——
那要单独一张令，不该由「加了调度模块」顺带获得。`/health` 里 `自动派发: false`
就是这个事实的自述。

## 巡检：找出「没人会主动告诉你」的那类问题

要找的都是**安静的失败**：不报错、不中断，只让活停在那儿。

| 类型 | 级别 | 抓什么 |
|---|---|---|
| 在途超时 | 急 | 派出去没回来。执行器挂了/进程被杀/服务重启丢了在跑的活——工单会**永远**停在在途并一直占着并发额度 |
| 零派发 | 急 | 有待投却一张没派。单看每张的拒派理由都「合理」，但**整体停摆**是另一回事 |
| 依赖缺失/成环 | 急 | 依赖的单不存在，或两张互相依赖——**永远不会就绪**，会一直躺着 |
| 预算冻结 | 常 | 闸住是设计行为，但人得知道，否则会以为平台坏了 |

告警都带**后果说明**，不只报现象——「已在途 59 分钟」后面跟着「会永远停在这里并
一直占着并发额度」，人才知道为什么该管它。

零派发的原因做**聚合计数**（`依赖未就绪×2；池 claude 已达并发上限 1×1`），一眼看出主因。

## 驾驶舱：产线状态

一个空的工单看板有两种可能——**没活干**，或者**有活但全被闸住了**——
而这两种的处置完全相反。产线状态面板就是回答这个问题的。

上线当场就抓到了真东西：首次真跑留下的 `R-1` 在途 59 分钟未归（它没有「项目」字段，
所以只跑不提交、停在在途），而它占着并发额度，导致新单 `UI-1` 一直派不出去。
两条告警连起来正好是完整的因果链。

## 质检（协-004）

在途干完**直接判完成，等于没有人验收**——AI 说自己做完了就算做完。这在真花钱的产线上
不成立：它可能只改了一半、可能改错了地方、可能什么都没干但输出了一段像模像样的报告。

### 状态机加一态，靠改表不改逻辑

```
草稿 → 待投 → 在途 ─┬─► 质检 ─┬─► 完成
                    │         └─► 待投（判不过，回去重做）
                    └─► 完成（免检时直达）
```

协-001 决定 1 承诺的「表驱动，加态是改表不是改逻辑」在这里兑现了：
状态机代码**一行没动**，只改了 `STATES` 与 `TRANSITIONS` 两张表。

**判不过回「待投」不是失败终态**——同一张单可以再跑一轮。

### 默认要检，跳过必须显式

反过来（默认不检、要检才配）会让「没配 = 没人验收」，那是最危险的默认。
三条显式免检：配置 `质检.启用: false`、工单 `QA: 关`、角色在 `质检.免检角色` 内。

另有一条硬免检：**reviewer 自己的产出不再送检**——判官判判官会无限递归。

### 跨厂避让

判官走「评审」类别，router 的 `crossProviderReview` 会优先挑**别家**。
同源盲区是真的：同一个模型往往看不出自己的错。

⚠️ 这里踩了一个坑：**必须把工单递给 `选派`**，router 靠 `task.fm.执行池` 才知道
「原执行方是谁」。不递的话跨厂避让整个失效，**而且不会报错**，只会安静地挑回同一家。
实测：修之前 `跨厂: false`（claude 判 claude），修之后 `跨厂: true`（codex 判 claude）。

### 判官失败 ≠ 被评审方不合格

判官崩了、零输出、输出里找不到结论——都是**判官的**问题，工单维持原状待重判，
不因此打回。这是加固②在质检环节的直接应用。

### 独立接口，不塞进 /run 的尾巴

`POST /api/exec/qa/<工单>` 单独一条。质检是一次**独立的付费调用**，应该能被单独触发、
单独看回执、单独失败重来。混在 `/run` 里，「执行成功但质检挂了」会变成一个说不清的复合结果。

判官一律**受限权限**：它只该读和判，不该改任何文件。

## 三条未跑路径的验证（2026-08-10）

协-004 提交时如实标了三条「代码通了、真实路径未验」。全部验完，**每一条都验出了 bug**。

### ① 依赖集成的 git merge —— 通过，但先撞出一个转发 bug

造两张有依赖的单，上游做真实检查点，下游 prepare 时集成：

```
集成: {"merged":[{"id":"DEP-1","commit":"b414f74d"}],"skipped":[],"conflicts":[]}
下游 git log: 4a9c26a Merge commit 'b414f74d' into studio/project/DEP-2
下游工作区:  README.md  index.js  util.js   ← util.js 是上游的产出
```

**撞出的 bug**：`/api/workspace/*` 那条转发写的是裸 `代理.end()`，**请求体被整个丢掉**。
经 server 调任何 `/write/*` 都收到空 body，报「项目(空)不在注册表里」。

之前没暴露，是因为执行器直连 4371 绕过了 server——**这条路径压根没人走过**。
`/api/exec/*` 那条一直是对的（`req.pipe`），两条实现不一致才是根源。
契约测试补了一条：每条转发都必须有 `req.pipe(代理)`。

### ② 并发闸 —— 通过

上限设 2，四张待投：放行两张，其余明确跳过并说明「池 claude 已达并发上限 2」。
排序也对：更老的单先走。

### ③ 质检真判 —— 三个 bug

**第一个是闸拦对了**：跨厂避让把判官选成 codex，而 codex 没配预算上限，第三道闸拒绝。
这是设计意图，不是缺陷。

**第二个是真 bug：受限参数没按适配器分。** 原先写死一套
`['--permission-mode','plan']`——那是 claude 的 flag。注给 codex 后：

```
error: unexpected argument '--permission-mode' found
```

判官退出码 2，**每次质检必挂**。而且不会有人发现是参数错了——加固②会把它归类成
「判官失败」，看上去像判官不稳定。

**一个厂商的 flag 拿给另一个厂商用，这个错在「跨厂评审」这个设计下必然会踩**，
因为正是跨厂让执行方与判官不同源。现在按适配器分，旧的数组写法保留兼容但**响亮告警**。

**第三个是输出提取缺了一层。** 适配器声明了 `outputFormat`，但此前没人用它——
质检直接拿**整条 JSONL 流**去解析，于是 `review-opinion` 把流事件当成了评审正文：

```
问题: ["{\"type\":\"thread.started\"...}", "{\"type\":\"turn.started\"}", ...]
```

判官明明工作正常、结论也格式良好，回执却是一堆垃圾。新增 `lib/输出提取.js`
按格式抽出 agent 的最后一段话。抽不出来时**回退原文而不是返回空**——
空会让上游误判成「零输出」，进而把一次成功的运行记成失败、污染路由战绩。

修完之后的真判回执：

```
判官: codex   跨厂: true   结论: 不过   正文来源: codex-jsonl
问题: ["验收标准要求"未产生任何文件改动"，但实际改动了 index.js。"]
证据: ["工单记录的实际改动文件为 index.js，与验收标准直接冲突。", "本次质检未修改任何文件。"]
工单状态: 待投      ← 判不过回待投重做，不是失败终态
```

# 十、驾驶舱深化（协-005，2026-08-11）

## 消耗报表：钱花在哪

`budget.view` 早就有，但**一直没有消费方——账记着没人看，等于没记**。

点编号出详情，把这些串成一页。出问题时不用再去 `D:\AI-DevPlatform\工单\*\*.md` 里翻。

## 踩了一个特别隐蔽的坑

用脚本改 HTML 时把 `'\n'` 写成了真换行，字符串断在半路。后果是：

**页面照常渲染，但所有数据永远停在「读取中…」**——因为整段 `<script>` 根本没执行。
不看控制台就会以为是后端没响应，而后端一切正常。

补了断言：`new Function(内联脚本)` 必须不抛。手写脚本改 HTML 太容易出这种事，
而这类错**不会让页面报错，只会让它安静地什么都不做**。
