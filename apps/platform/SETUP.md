# AI-DevPlatform 安装指南

一条从工单到真实代码提交的流水线：**建单 → 派活 → 真跑 → 质检 → 提交**。
你负责开单和拍板，路由选人、隔离工作区、执行、跨厂质检、检查点、合并、记账由它自动跑。

## 前置要求

| 项 | 说明 |
|---|---|
| Windows 10/11 | 也能在 macOS / Linux 上跑，只是 `部署.bat` 是 Windows 的，别的平台直接 `node scripts/首装.js` |
| Node.js 18+ | 本产品**零第三方依赖**（只用 node 内置模块），但它本身是 node 程序。`node -v` 出版本号即可 |
| Git | 提交链要建 worktree、打检查点、快进合并。`git --version` 能出即可 |
| claude CLI（Claude Code） | 执行引擎之一。装在 `~/.local/bin/` 或 PATH 均可（按绝对路径解析，不依赖 PATH） |
| codex CLI | 执行引擎之二，**也是默认判官**。跨厂质检要求判官和执行方不同源，两个都装才有意义 |
| CLI 登录 | `claude auth login` / `codex login`。没登录 = 真跑必挂，而且挂得很像「平台坏了」 |

**只装一个 CLI 也能跑**，但质检会退化成同源兜底（自己判自己），回执里会如实标出来——
那时质检的含金量是打折的。

## 安装

```
双击 部署.bat
```

它做三件事：验 node → 跑 `scripts/首装.js` 配置 → 起服务。
非 Windows 或想看清每一步：

```bash
node scripts/首装.js      # 问答式配置
npm start                 # 起服务
```

批量铺机器 / CI 用非交互：

```bash
node scripts/首装.js --yes \
  --工单库 "D:\你的私仓\工单" \
  --项目名 靶仓 --项目路径 "D:\Github\靶仓" \
  --真跑 --允许写
```

**首装可以反复跑。** 已经配好的一律保留并说明跳过了什么——升级或补配都直接重跑。
它只写 `config/*.local.json`（不入库），不动任何代码。

## 拿到的是 exe（打包件）

没有源码、没有 node 也能用。双击 `AI-DevPlatform.exe`，然后：

1. **第一次开机会把配置模板放到 exe 同级的 `config/`**，一排 `xxx.local.json.示例`。
   把某个模板的 `.示例` 三个字去掉就生效，里面写了每个字段干什么、不配的后果是什么。
2. **工单库根目录和项目注册在界面上就能配**，不用碰文件（首页输入框 / 设置页「项目注册」）。
3. 改完 `config/` 里的文件要**重启一次**才读得到。

为什么模板要「播」出来而不是直接躺在包里：`.示例` 原本在 `app.asar` 内，
而 asar 是只读的、文件管理器也打不开——不播出来的话，
除了工单库那一个，其余配置对拿到 exe 的人**根本没有入口**。

exe 同级还会有一份 `SETUP.md`（就是本文件）。

> **`config/` 是 exe 同级那个，不是 exe 解压出来的那个。** portable 目标每次把自己解到
> `%TEMP%\<随机>\` 再启动，写进去的东西下次就没了。产品已经按
> `PORTABLE_EXECUTABLE_DIR` 落在原始 exe 旁边（见 `lib/配置位置.js`），
> 所以**别把 exe 单独拷走**——它旁边的 `config/` 才是你的配置。

还需要 `packages/`（公用件）在 exe 同级，或用 `平台配置.json` / `TICKETFLOW_PACKAGES` 指路；
四条解析序都不中时程序会弹窗说清缺什么，不会静默启动。

## 验收标准只有一条

**自检显示「全链路就绪」。**

首装结尾会打一遍；起服务后也能随时看：

```bash
curl -H "Authorization: Bearer $(cat config/api-token.txt)" http://127.0.0.1:4370/api/selfcheck
```

七格全绿即整条链可用。哪格红了，那格自己写着缺什么、怎么补——
自检**只报事实不做修复**：自动补配置意味着替你决定业务数据落哪、要不要花钱，那些不该由它拍板。

> 第一次配置完、**还没开过机**时，「命令行调接口」是红的。这是正常的：
> 令牌与 `config/api-token.txt` 由第一次开机自动生成，开一次就绿。

## 要配的东西（首装会逐个问）

| 配置 | 不配的后果 | 也可以在哪配 |
|---|---|---|
| `config/工单库.local.json` | **未就绪**。工单接口一律 503 | 界面首页有输入框，当场生效 |
| `config/项目.local.json` | 提交链没有目标仓。它同时是**写操作白名单** | 设置页「项目注册」 |
| `config/执行.local.json` | 只能干跑（零计费），全链路仍走得通 | — |
| `config/预算.local.json` | 没配上限的池一律不许真跑 | — |
| `config/workspace.local.json` | 提交链 403：agent 能干活，成果回不到你的仓 | — |

每个都有对应的 `.示例`，里面写了字段含义和为什么这么设计。
**文件名即段名**：`workspace.local.json` 的内容就是 `workspace` 段的段体，不要再套一层。

## 三个进程

`npm start` 一条命令全起。切分是按**能力**来的，不是按模块：

| 进程 | 默认端口 | 能力面 |
|---|---|---|
| `server.js` | 4370 | 只转发。闭包里没有 `child_process`，物理上起不了 CLI |
| `scripts/工作区服务.js` | 4371 | 唯一被允许起 git 进程的地方 |
| `scripts/执行器.js` | 4372 | 唯一被允许拉起 AI CLI 的地方 |

端口都能在配置里改（`server.port` / `workspace.port` / `执行.port`，或环境变量
`PORT` / `WORKSPACE_PORT` / `EXECUTOR_PORT`）。改了开机横幅会跟着报真端口。

不想让执行器活着（纯看板模式）：`PLATFORM_NO_EXECUTOR=1 npm start`。

## 真跑要过四闸

执行器进程活着**不等于**已经在花钱。真跑必须同时满足：

1. 请求体 `{"干跑": false}`
2. `config/执行.local.json` 的 `允许真跑: true`
3. `config/预算.local.json` 里那个池配了上限
4. 额度闸没把那个池冻上（订阅池的 5h / 周窗口百分比）

任何一条不满足就是干跑：跑完、有回执、零计费。

## 常见问题

- **自检说「连工单都没地方放」** → 没配 `工单库.local.json`。重跑 `node scripts/首装.js` 或在界面上填。
- **提交链 403** → `workspace.local.json` 的 `允许写` 没开，或目标仓不在 `项目.local.json` 注册表里。两者都要。
- **端口被占** → 配置里改 `server.port`（或设 `PORT`），重启生效。开机横幅会报改后的端口。
- **质检老是「验不了」** → 判官跑不动验收命令。多半是工单的 `需要依赖` 漏了目录——
  平台会在喊人消息里**列出**审阅区里没装依赖的包，照着补进工单再判一次。
  注意扫全仓的验收命令（`typecheck` / `unit` 常常如此）**要把所有 workspace 列全**，不能只列这张单改到的。
- **判官是 claude 时命令型验收判不动** → 这是有意的限制。claude CLI 只有全盘绕过那一档能让命令跑起来，
  平台不拿它当「工作区内可写」使。要判这类单，把判官派给 codex。
- **想换机器** → 拷走整个目录即可（`config/*.local.json` 带着走），或在新机器上重跑首装。
  工单不在这里——它在你自己配的那个业务私仓里。
