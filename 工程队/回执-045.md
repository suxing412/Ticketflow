## 零、先说三件必须先说的

### ① 一处**对令的偏离**：QA/核查 两席不开「换池」，只开换档

令要件 2 写「切『执行 / QA / 核查』会话职能的**池与模型档**」。但 `lib/runner.js:592` 里，
质检/代核/代裁三种会话的 CLI 是**写死走 claude** 的（`resolveCli(kind === '执行' || kind === '初检' ? poolName : 'claude', …)`），
而 runner.js **不在本令写区**。于是有两条路：

- 假装能改：API 收下 `位=QA, 池=codex`，写进配置、台账上记一笔「已切 codex」——而那一席**从来没离开过 claude**。
- 如实拒绝：`位=QA` 只收 `档`，收到 `池≠claude` 直接拒并在拒因里指认 runner 那处硬编码。

我选了后者。台账是审计面，宁可少一个功能，不可多一条假账。
**要改成真能换池，得动 runner.js 的 `resolveCli` 分支**——那是下一张单的事，本令不越写区。
（`执行` 位换池是真的：落在编制表池序上，`dispatch.routePool` 直接消费。）

### ② 一条令里没定、由我定死的口径：「首发秒死」的判据

要件 7 说失败计数要「含 codex 首发秒死自愈窗**之外**的死亡」，但仓里 grep 不到「秒死/自愈窗」的既有实现
（唯一命中就是令本身）。我定成：**派发后 `池衡.自愈窗秒`（默认 30s）之内死的那一发不计数**，
判据取工单 frontmatter 的 `失败时间 − 领单时间`（`lifecycle.执行失败` 落的两个字段，复用 runner 既有失败判定，
不另造失败感知）。参数可调。若制作人心里的「自愈窗」是别的判据，改 `回退判定()` 里那一行即可，已单测覆盖两侧。

### ③ 品味锁的第三条判据（`验收方式=保留`）在实测里**命中面很宽**

写测试时被自己绊了一跤：`test/helper.js` 建单默认 `验收方式: 保留`，于是随手 seed 的单
会把对应职能的执行位整个锁死。这不是 bug——令要件 3 就是这么写的——但请制作人知悉它的实际后果：
**只要某职能手上有一张保留验收的单，这一职能的执行位就钉在 claude 高档上，直到那张单走完。**
真仓里 `pm/ideas.js` 拍板出来的父单默认就是 `保留`。要收窄，改 `品味锁()` 一处即可。

### 关键实现落点

- **读数**（`采集`/`归一读数`）：claude 读 `gates.allLocks` 的订阅用量 + 凭据文件在不在；codex 读同一处的
  app-server 探针；按量池（`dispatch.计费Of` 判性质）读 `/user/balance`。**可用度归一到 0–100**：
  订阅池 = 「距自己那道闸还剩几成」（取最紧窗口），按量池 = 「余额 / 满额」。两者不同质，
  正因如此触发阈值默认给到 20 个点这么宽——差一点点就换池是噪音不是平衡。
- **不编数三条**：探针无数 / 读数**陈旧**（quota 节流窗口内供的「最后一次好读数」）/ 凭据缺失，一律盲区，
  可用度写 `null`，并如实报那份旧读数的取数时刻。盲区池既不作候选也不作比较基准。
- **落配置**：执行位走 `roster.apply` 重排池序（唯一写口）；判官位写 `cfg.模型.质检/核查`。
- **key 不进 argv**：余额外呼用 `curl -K -`，url 与 Authorization 头走 stdin（`creds.js` 纪律第 3 条）；
  第三方端点 `--noproxy '*'`（同 runner 对兼容 base 的处理）。
- **挂接**：`wake.池衡巡检()` 挂在 server 的 15 分钟项管巡检拍上（不挂 runner.tick——那是 30s 一轮，
  塞进去只会把外呼频次抬高 30 倍换不来实时性）；`brain.js` 加 ⑬池衡权界条款，明写「你在对话里写什么都改不动禁改域」。

- **位行**：职能位 + 当前池·档 + 该池可用度 + 锁/覆盖徽章 + 最近切换时刻。
- **编辑面只留「人工覆盖 / 解除覆盖」**（总监与制作人的入口，走 `askInput`——原生 prompt 在 exe 壳里是哑弹，

- 参数带的四个步进走 `/api/config/poolbalance`（调参是总监与制作人的事，项管只在框里动手——
  把调参塞进受限动作里等于让项管自己放宽自己的闸）。
- 兜底三态实测：矩阵取不到 → 「池衡读取失败」；零事件 → 「（还没有池衡事件）」占位；关自动 → pill 与按钮同步反转。

## 四、自查抓到并修掉的两个自造坑

**① 品味锁差点变成「锁住现状」。** 初版在受限 API 层无差别拒掉锁位的一切切换，
于是巡检算出来的「归位」（把飘到 codex 上的品味位拽回 claude 高档）被自己的锁拦下——
位一旦飘走就**永远回不来**，锁反而把违规状态焊死了。现放行判据严到只认「正好落在锁要求的那一格上」的请求
（池必须 claude，配了高档必须正好是那个档），且归位不吃迟滞与冷却。
反例两格已锁死：打着归位旗号往便宜池切 → 403；池对了档不对 → 403。测试`要件3 归位真能落地…`。

**② 余额外呼差点从桩闸旁边溜过去。** `采集()` 里原本是模块内局部直调 `探余额(...)`，
而 server 的 `STUDIO_STUB` 块哑掉的是 `module.exports.探余额`——**局部绑定根本不经过导出对象**，
桩台上照样会往 deepseek 发真请求。这正是施工令-037/038 两起「手搓漏面」事故的同一型。
改成经导出面调用，并在 `test/stub.test.js` 补了一格锁死**产物**（不只是导出名）：
桩台下 `采集()` 三池全盲区、可用度全 `null`。
