## 要件

1. **差量探测纯函数**：输入=工单库快照（含 fm 父单/状态/单号）+ 台账粒清单；输出=差量动作列表——
   - 新单挂粒：父单类型∈{专项,战役} 的子单（含 返工自/推翻 新号）无对应粒 → 登粒（批名=父单专项名或承袭原粒批，题=单题，单号挂链，依赖照 fm）；
   - 状态随单：单已派发而粒仍 计划/起草中 → 推进到 已成单；单归档/完成 → 粒 完成；单废弃 → 粒 撤销（已成单不可直撤的按状态机走 完成+说明=废弃闭合，沿用 TK-144 先例口径）；
   - 粒指单不存在 → 报异常不自动删（人裁）。
2. **执行器**：差量动作走 schedule.js 既有 CAS 通道逐条落，失败重试一轮后入信箱告警；每次同步落台账事件（类型=台账对齐，含动作数）。
3. **挂拍**：① 事件驱动——journal 增量里出现 成单/派发/归档/废弃/推翻 即触发一次同步（去抖 30s 合并连发）；② 5 分钟例行拍兜底（挂 wake 既有巡检环，不另起线程）。
4. **首跑回填**：上线首拍对全库做一次全量对齐（会把编辑器专项 156-161 六粒补齐）——回执附首跑动作清单。
5. **测试**：差量函数各分支（新单挂粒/返修承袭/状态各迁移/废弃口径/孤粒告警/去抖合并）；全量 npm test 零回归。
