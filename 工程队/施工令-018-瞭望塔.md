# 施工令-018 · 瞭望塔（统一监视守护，制作人 2026-08-08 01:12 批准）

裁决：集中所有监视器为一个——一个常驻进程收口全部信源与定时唤起，与总监会话/VPN/CLI 生死解耦。

## 范围（仓：D:\GitHub\Ticketflow，工区：套件/瞭望塔/，去项目化）

1. **守护进程** `套件/瞭望塔/watchtower.js`（node，单文件优先）：
   - 信源①流水：tail 部署工作区 `journal/<当月>.log`（月切自动跟随）；
   - 信源②信箱：tail `呼叫/inbox.jsonl`；
   - 信源③时钟：规则表里的定点（默认 09:03 晨报 / 23:26 晚报 / 00:00 切夜班）到点自产一条时钟事件；
   - 信源④心跳：每 5 分钟探 `http://127.0.0.1:4270/api/board`，非 200 连续两次→「监制台失联」事件。
2. **规则表** `套件/瞭望塔/规则.json`（部署时可覆盖）：每规则={匹配（信源+正则）, 动作:[记流水|记未读|弹通知], 级别}。默认：急件/三振/失联/时钟→弹通知+记未读；完成/失败/上呈/告警→记未读；其余→仅记流水。
3. **输出**：
   - `瞭望塔流水.log`（统一事件流，一行一事件带信源标）——总监会话唯一 tail 对象；
   - `未读账本.jsonl`（会话不在场时积压；提供 `--ack <时间戳>` 清账命令）；
   - Windows toast（BurntToast 不可用时回落 msg/PowerShell 原生通知，再不行落文件不炸）。
4. **自启**：`--install` 注册计划任务（登录即启，工作目录=部署区）；`--uninstall` 反注册；重复启动自检（pid 文件互斥）。
5. **部署配置**：CLI 参数或 `瞭望塔.config.json` 指定部署工作区根（默认 D:\GitHub\AI-GameStudio\监制台）。

## 不要做
- 不做云端；不做 GUI；不改监制台任何代码；不打包不提交；AI-GameStudio 只读+写它的两个输出文件（流水/账本放部署区 `瞭望塔/` 子目录）。

## 验收标准
- [ ] 假部署区实测：journal/inbox 各注入样例→流水+未读+（急件类）toast 三路正确；规则表改动生效
- [ ] 时钟事件到点产出（用近分钟规则实测一发）；月切跟随（改月份文件名模拟）
- [ ] 心跳失联两连报一次、恢复后报恢复；--ack 清账；pid 互斥
- [ ] --install/--uninstall 计划任务真实注册/清除（取证 schtasks 查询）
- [ ] 单元测试≥8 例（规则匹配/tail 断续/账本读写/参数）全绿；完工纪要逐条证据
