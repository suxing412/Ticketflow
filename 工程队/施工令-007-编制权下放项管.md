# 施工令-007 · 编制权下放项管（H85）

制作人裁决（2026-08-06 21:15）：「（agent 编制管理区）可以去掉了，编制只需要存一单数据放在项管那让项管自己管理就好了。」用工权随派单权归项管（H57 延伸）。
案源：美术-A 唯一编制挂冻结 codex 池仍显「在岗」全绿，制作人亲自发现假健康（2026-08-06）。

## 范围（apps/studio）

1. **参数页删除「agent 编制 · 执行池」管理区**（下拉框、在岗徽章、整个交互面）。参数页保留额度双池卡与模型档等其余内容。
2. **项管页新增只读「编制快照」**：一行一 agent（职能/池/档位/可用性），可用性按池锁实算——池冻结显「池冻结·⽌派」黄标不显绿。纯展示，无编辑控件。
3. **编制数据归项管**：config.agents 保留为存储位（迁移成本最低），但语义变更为「项管所辖数据」；新增 `/api/pm/roster` POST（体：{改动:[{id,执行池?,模型?}],理由}）——写 config.agents + 项管台账记账 + journal「项管编制调整」。仅供项管调用与总监代劳，不做前端编辑界面。
4. **派发死局自愈**（lib/pm/dispatch.js 或 runner 派发段）：挑单时若该单职能的**全部**编制都挂在被额度锁冻结的池上 → 自动改派该职能编制中第一个可用池（临时改挂，写 fm.临时改池 标记 + journal + 台账），无可用池才滞留并走零派发告警。测试覆盖：唯一编制冻结→自动改挂；多编制部分冻结→用可用者不改挂；全冻结且无可用池→滞留告警。
5. **项管切单提示词**（lib/pm/brain.js）：补一句用工语境——编制数据与调整权在项管，池路由按编制快照与额度实况定（grep 验证生效）。

- 不删 config.agents 数据结构；不打包不提交；不碰 AI-GameStudio。
