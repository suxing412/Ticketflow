# 施工令-021 · 预算闸（额度锁的按量计费孪生）

- 提出：2026-08-08
- 背景来源：《交接-2026-08-08-探针与凭据托管》遗留③ / 《协作回执》第四节认领表
- 归属：凭据托管同族（回执已确认「你的」）

## 背景

2026-08-08 落地了凭据托管与「套餐用完降级到 key」（`dispatch.降级Of`）。
降级本身是通的——池序顺位即路由，`claude` 冻结就落到 `claude-key`。

**但现有的全部成本刹车都建立在「订阅有一个会重置的用量窗口」之上**：
`执行池.*.阈值 / 周阈值` 比的是 `quota.js` 从订阅端点读回的 5h / 周百分比；
`额度.沟通保留` 比的也是它。API key 是按量计费，**没有这个窗口**，
`gates.poolLock` 对 key 池永远算不出 `fivePct`，于是恒不锁。

结论：**当前 key 池等于没有任何成本刹车**。降级一旦触发，跑多少烧多少，
唯一的止损手段是人盯着。这是不能上生产的状态。

## 范围

① 新增 `lib/budget.js`：按池按窗口（日/月）计量，判「是否超预算」。
② 计量口径：从会话的 stream-json 事件流提取 usage（输入/缓存/输出分列——
   缓存读计费约为常价 1/10，混进合计会虚胖，`pm/brain.js` 已有同款教训）。
③ 账本落 `<root>/预算账.jsonl`（只追加，明文即事实源，与 journal 同纪律）。
④ 判据接入**不改 `poolFrozen` 签名**：由调用方把预算冻结结果并进 `gatesInfo`，
   于是池序降级、编制快照可用性、UI 三处自动跟着走，零额外接线。
⑤ 配置段 `config.预算`：每池的 日/月 上限（token 或金额）+ 可选价目表。
⑥ 超预算与额度锁同级——都是「这个池现在一张都不许派」。

## 不要做

- **不碰订阅侧的额度锁逻辑**（`gates.poolLock` / `quota.js` 一字不改）。
  订阅归订阅、按量归按量，两套判据并存，不做语义合并。
- 不改 `dispatch.poolFrozen` / `routePool` / `pickNext` 的函数签名。
- 不做费用的精确对账（厂商账单口径各异）——本闸是**保险丝**不是财务系统，
  估算偏保守即可，宁可早刹一点。
- 不做 UI 的预算编辑器（本单只出 API 与判据；参数页卡片另单）。
- 不引入新依赖。

## 验收标准

□ `lib/budget.js` 存在，纯函数部分（判据/汇总）可离线单测
□ 输入/缓存/输出三者分列计量，缓存不计入常价合计
□ 账本只追加、坏行容错、缺文件返回空汇总不抛
□ `超预算()` 支持 token 上限与金额上限两种表达；两者都配时任一触线即超
□ `冻结池()` 产出的结构可直接并入 `gatesInfo`，使 `poolFrozen` 无需改签名即生效
□ 未配预算的池永不被本闸冻结（不配 = 不管，绝不臆造上限）
□ 新增测试套件全绿，且 `npm test` 整体不因本单变红
□ `工程队/状态.json` 更新
