# 施工令-045 · H99 池衡控制面（Q5）

案源：制作人 2026-08-11 决议 H99——「项管拥有读额度切模型的权力，他应该做到平衡才行」；codex+deepseek 均可用于工作。现状：池/模型全靠人手改 `/api/config/*`，项管无读数无切换通道，池间失衡只能等总监发现。

写区：`apps/studio/lib/pm/`（新 `poolbalance.js` + `wake.js`/`brain.js` 挂接）、`apps/studio/server.js`（受限动作 API）、`apps/studio/public/`（池位矩阵卡）。禁碰：门禁配置、放行工具白名单、人闸/裁决链路。

## 要件（红队校准，逐条即验收断言）

1. **额度读数真实源**：项管可读三池状态——claude（订阅态/凭据有效性）、codex（app-server 探针）、deepseek（key 余额接口）。读不到的池报「盲区」，禁止编数或沿用旧值充数；读数带取数时刻。
2. **切换权界**：项管仅可切「执行 / QA / 核查」会话职能的池与模型档。项管永远不可改：门禁、放行工具、人闸设置、总监/制作人/项管自身的角色模型、并发上限。
3. **品味锁**：命中任一条即锁 claude 高档、项管切换请求被拒且记台账：工单带 `品味敏感: 是`；职能=美术；验收方式=保留。锁的判定在受限 API 层做，不依赖提示词自律。
4. **派发时快照**：切换只影响此后新派发的会话；在途会话沿用派发时快照（与超时闸同口径），不中途换马。
5. **迟滞防抖**：同一职能的池位切换设最小间隔（默认 30 分钟）与触发阈值（池间可用度差异显著才切）；参数入 `studio.config.json` 可调。
6. **审计入台账**：每次切换/被拒/回退记项管台账事件（时刻、从→到、触发读数、理由），晨报可对账；事件类型区分「项管自动」与「人工覆盖」。
7. **失败回退**：切入池连续派发失败（复用 runner 既有失败判定，含 codex 首发秒死自愈窗之外的死亡）自动回退原池，记「回退」事件，且该池进入冷却（迟滞计时重置）。
8. **并发安全**：切换写配置走 CAS（读版本→校验→写），与 UI 手改并发时后写拒绝重试——排程台账（施工令-040）同款教训，不许后写覆盖。
9. **UI 可见**：参数页新增池位矩阵卡（职能 × 当前池 × 模型档 + 最近 5 条切换事件 + 各池读数/盲区标识）；总监/制作人手动覆盖入口保留，人工覆盖优先并冻结项管自动切换（直至人工解除）。
10. **越权硬拒**：项管的切换必须走受限动作 API（枚举白名单动作），brain 提示词自由文本不能直接改 cfg；测试构造越权动作（改门禁/改白名单/改人闸）断言 4xx 拒绝 + 台账留痕。
11. **可测结构**：决策逻辑（读数→是否切→切到哪）抽纯函数入 `lib/pm/poolbalance.js`，单测覆盖：品味锁各命中分支、迟滞窗口内拒切、阈值不足拒切、失败回退、CAS 冲突、盲区池不参与平衡。
