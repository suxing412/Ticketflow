| 1 | 起跑记时刻；收尾核 mtime ≥ 起始时刻，否则 status=error（stale_results，绝不报数） | 起跑：`enginectl.js` unity-test 分支在 `discoverAttach` **之前** `startedAtMs = Date.now()`（`isTest` 才进，见要件2）。收尾：`freshnessGate(results, startedAtMs)` 取代原来「拿到路径就 `readCounts`」那一步——`mtime < startedAtMs` 或**文件根本不存在**（无 mtime 可核，同样不许报数）即拦下，出口 `{ ok:false, status:'error', error:'stale_results：…', listenerStatus:<监听器自己的说法>, resultsMtime }`，**输出对象里根本不构造 passed/failed/total 三个键**（测试用 `!('passed' in json)` 逐个锁死，不是锁成 null）。判据无容差：起跑时刻取在挪件之前，本轮真跑出来的件 mtime 必晚于它；早于它只有一种解释——不是本轮的。边界 `mtime === startedAtMs` 按 `≥` 放行，单测有格 |

## 三、四处自主判断（都写进代码注释，便于日后追责）

**① `enginectl.js` 加 `require.main === module` 闸 + `module.exports`。**
原文件是「一路读到底、末尾 IIFE 自动跑」的脚本，算子无从单测。改成 `async function main()` + 末尾
`if (require.main === module) main()`，并导出 `freshnessGate`/`stashStaleResults`/`statMtimeMs`/`readCounts` 等。
命令行调用路径一字未变（E1 探测冒烟 + E6 六格文案原样锁死）；被 require 时一行都不执行。

**② 缺件也判 `stale_results`，不另发明错误码。**
令面「否则 status=error」——「读不到文件」和「读到旧文件」在结论上是同一件事：**没有可核的 mtime，
就不许报数**。多一个错误码只会让消费方多写一个分支，报错原文已分别说清是哪一种。

**③ 保留 `listenerStatus`。**
拦下时 `status` 被我们改写成 `error`，监听器自己说的 `passed` 若就此消失，事后排查会缺一环
（到底是监听器没跑，还是跑了没落盘？）。故原样留一个字段存证——只存证，不参与任何判定。

**④ `package.json` 的 `test` 从「探测冒烟」升为真自测（外溢一处，2 行）。**
原 `test` = `node enginectl.js 探测`，本令的三分支测试若不挂进 `test`，就永远不会被总监台的测试链跑到
——等于白写。故 `test` 改指 `node test.js`（探测冒烟已作为 E1 收进去，一格不少），原命令保留为
`npm run probe`。这是本令唯二外溢之一，另一处是 README 的纪律要点与测试节。
