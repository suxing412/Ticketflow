## 三、三处判断（令面没写死、我替它拿的主意）

### ① `schedule.js` 没增查询口

令面写「如需增查询口」。核下来不需要：`现态()` 已经给全量粒，`取()` 给单粒，
`转移()`/`登记()` 就是写口。**为对齐专开一个查询口，等于给这个实体开第二条读路径**，
而 040 那份令的第一条硬口径就是「事件流折叠是唯一现态来源」。所以本令对 `schedule.js`
**零改动**——它是被复用的，不是被扩的。

### ② 「已归档」按有无 `归档原因` 分岔

令面写「单归档/完成 → 粒 完成；单废弃 → 粒 撤销」，但工单侧**废弃的物理落点也是已归档**
（`lifecycle.废弃` = 任意非终态 → 已归档 + `归档原因:'废弃'`）。一刀切认「已归档=完成」，
被废弃的单会在台账里显示成交付；一刀切认「已归档=撤销」，正常交付后整理性归档的单会被撤掉。
判据取仓里**既有**的落袋口径（`dispatch.depsDone` / `chain` 都是这一条）：
**无因归档 = 正常交付 → 完成；带因归档（废弃/验收打回/定夺打回/返工替代/推翻替代）→ 撤销**。
映射表见 §四，九态逐格有测试锁着。

### ③ 接线点落在 `runner.tick` 的**派发制/领单制两条分支之外**

`wake.checkCloseouts`/`checkChainFailures` 那一组挂在 `if (dispatchMode)` 里面。本令这一拍
**没有跟着挂进去**：台账对不上账跟用哪种派发模型无关，挂进 `if` 就等于领单制那半边永远不对齐。
接线实证那一格特意用**领单制** CFG 跑真 `runner.tick`——挂错了这一格必红。
（这一行落在 `runner.js`，是令面写区之外的**一行**接线；不加它整个功能不会被调用，
如实报一句。「挂接点错了而单测全绿」正是 039 那类事故的温床，所以宁可多这一行也不拿 mock 冒充。）

## 四、状态映射表（改一格就是改协议）

| 工单态 | 粒目标态 | 说明 |
|---|---|---|
| 草稿 / 待投 | 起草中 | **待投仍算起草中**：派发钩子（`schedule.挂钩派发`）落在 待投→在途 那一刻，这里若把待投也认成已成单，同一张单会被两条路各成一次单，口径就分叉了 |
| 池 / 在途 / 质检 / 待验收 / 待定夺 / 执行失败 | 已成单 | 单已经发出去了 |
| 完成 | 完成 | — |
| 已归档（无 `归档原因`） | 完成 | 正常交付后的整理性归档（落袋口径） |
| 已归档（有 `归档原因`） | 撤销 | 废弃/验收打回/定夺打回/返工替代/推翻替代，都不算交付 |

两条硬规矩压在映射之上：

- **只前进不倒退**。目标态若在状态机里从粒现态**不可达**（H65 返修同号回草稿 → 已成单要退回起草中），
  一律不动；粒已是终态（完成/撤销）也一律不再随单动。账不倒着写，真要回滚由人走 API。
- **已成单不可直撤**（040 状态机第 3 条）。单被废弃而粒已成单时，按 **TK-144 先例**走
  `完成 + 末次说明「废弃闭合（已成单不可直撤，沿用 TK-144 先例）」`——账面收口，理由写在粒上，
  工单那边该废弃照样废弃。测试里这条是**真落一遍**验的，不是只看动作清单。

## 六、留给总监的三句

1. **换装后什么都不用做**。服务起来第一拍（30 秒内）自动全量对齐，`journal` 会出一行
   `台账对齐（首跑）：登粒 N · 状态随单 M（补登：TK-…）`，项管台账事件流里同步落一条
   `台账对齐`。真库的首跑清单以那一行为准——§二 是夹具演练值，不是真库实测值。
2. **信箱里可能会来两类新告警**：`台账孤粒`（粒挂的单全库找不到——**机器不删粒，等人裁**：
   要么改挂单号要么撤粒；同一条粒只报一次，不会每 5 分钟淹信箱）与 `台账对齐失败`
   （重试一轮仍败，多半是粒被人同时改了，下一拍通常自愈；连着报就该看了）。
   首跑之后孤粒告警若一次来很多条，那是**迁移进来的老粒挂着别的仓的单号**，属预期，不是故障。
3. **手工登粒从此是补救不是常规**。H102 之后总监再手工登粒，只会撞上判重跳过（来源+题）
   或与自动粒并存两条；真要人工介入的场景只剩两个：**排未来的计划粒**（还没成单的活，
   机器无从探测）与**孤粒人裁**。日常「单开了记得登一粒」这件事，可以从总监的检查表里划掉了。
