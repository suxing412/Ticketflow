> 【总监代劳条款豁免】验收标准中凡载明「总监代跑/代劳实测后誊入/不判失分」或指向 enginectl

### 2. 测试补例

`test/runner.test.js:432-453`，一格「总监代劳条款：质检+代核两卷都带豁免规则（施工令-043）」，
按施工令要的形状造场景：

- **验收标准**含代劳条款：`1. gates 冒烟 500 案全绿——**总监代跑**，代劳实测后誊入本单，执行方不判失分；`
  外加一条对照项 `2. 单测零回归（执行方自跑）。`——只放代劳条款测不出「其余条目照常判」的语义边界；
- **回执**标「待代跑」：`1. 待代跑（总监代劳条款，执行方不可得）` + `2. ✓ 37/37 绿`；
- 同一份工单/回执同时喂 `buildQaPrompt` 与 `buildAuditPrompt`，**两卷跑同一组断言**（循环体，
  失败信息带卷名）。纯文本断言，不起会话不烧 token。

六条断言，一条一个失效模式（不是六遍同一句的复读）：

| 断言 | 挡住的失效 |
| --- | --- |
| `【总监代劳条款豁免】` | 规则整段被删/漏注入某一卷 |
| `执行方标注「待代跑」即视为该条**应答完备**` | 判据句被改写软化 |
| `不得以「数字缺/未跑」为由打回或列为缺陷` | **TK-138 死锁正是卡在这句**，单独钉 |
| `判词中该条记「待总监代跑」` | 判词写法丢失 → 豁免了但账上看不出来 |
| `冒填数字` | 反向闸丢失 → 豁免变成「许人编数字」 |
| `总监代跑` | 卷面不复述触发措辞 → 判官认不出哪条该豁免 |

跑通输出（`node test/runner.test.js`，第 29 行即本格）：

```
  ✓ 总监代劳条款：质检+代核两卷都带豁免规则（施工令-043）
...
全部通过：53 项
```

（本文件由 52 项 → 53 项，即本令新增的一格。）
