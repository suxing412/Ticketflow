# 施工令-008 · 编制去岗位化（H85 补章）

制作人裁决（2026-08-06 22:44）：「-A/-B」是常驻岗位时代遗物；派发制下执行者因单而生，同编制无头 CLI 想开几个开几个。**编制表=每职能一行**，不再有同职能多岗位（程序-A/程序-B 之类）。

## 数据模型

新形态 `config.编制`（数组，每职能一条）：
`{ 职能:'程序', 池序:[{池:'codex',档:''},{池:'claude',档:''}] }`（档空=池默认）
- 池序即路由优先级：派发挑池=顺池序取第一个未冻结池；池序内切换不算改挂；**池序全冻结**才借调 config.执行池 其余可用池并打 `fm.临时改池`（007 三态语义保持）。
- 旧 `config.agents` 兼容迁移：读盘时按职能分组、池按原序去重合并、各池取该池第一个显式档位；迁移后写盘落新形态，旧字段删除。迁移幂等、损坏容错。

## 范围（apps/studio）

1. lib 层：编制读取统一走新模型（建 lib/roster.js 或并入 dispatch）；dispatch.rosterPools/routePool、runner 的 QA 挑人（原 agents.filter 职能==='QA'——改为按编制存在性判定，会话标签用职能名不用假人头号）全部改造。
2. /api/pm/roster：GET 按职能行出快照；POST 改动体改 `{改动:[{职能,池序?}],理由}`，校验+整批落盘+台账 journal 照旧。
3. 项管页快照 UI：每职能一行（职能/池序带优先级箭头/各池档位/可用性=首个可用池绿、全冻黄「止派」）。
4. 测试：迁移（多岗位→归并）、幂等、路由按池序、007 三态回归改造后仍全绿；journal 旧号不追改。
