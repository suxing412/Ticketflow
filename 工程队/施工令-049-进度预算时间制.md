# 施工令-049 · 进度条预算时间制（H100 落地·代码面）

案源：制作人 2026-08-12 21:13 裁决 H100——过程打点退役，进度按预算时间推算；质检等判官阶段进度冻结是直接痛点。历史：施工令-004 立锚点结构、041 §四砍时间口径保打点——本令反向收敛到时间单口径，锚点结构保留。

写区：`apps/studio/lib/progress.js`、`lib/runner.js`（如需取领单/阶段起始时刻）、`public/app.js`+`style.css`、`test/progress.test.js`。

## 要件

1. **阶段内插值改时间口径**：填充 = 该阶段已耗时 ÷ 该阶段预期时长，封顶阶段上限、不回退不越级；打点解析退役（`[进度 k/n]` 不再参与进度；tail 原文保留仅作诊断显示）。
2. **阶段预期时长来源**（优先级）：① 报表滚动均时（同职能×同阶段近 N 单中位，报表已有均时数据）；② `studio.config.json · 阶段均时` 手配缺省表；③ 执行阶段兜底=工单 `预计时间`。判官阶段（质检/初检/核查）从此有活的进度。
3. **超时表现**：已耗时超过预期时长 → 该段条变警示色 + 显示「超预期 X%」，不回退不装满。
4. **活跃动效**：当前活跃阶段的条带呼吸/流动动效（制作人点名「质检中看不到进度条闪烁」），reduce-motion 尊重系统设置。
5. **诚实纪律不变**：永不显示 100% 直到真落袋；无任何时长数据的阶段停在锚点。
6. **测试**：progress 纯函数单测改写（时间口径各分支：正常插值/封顶/超时/无数据锚点停），删除打点口径用例并在注释记 H100 案源；全量 npm test 零回归。
