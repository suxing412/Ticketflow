# 施工令-022 · 判官直连 API（待评审，未开工）

- 提出：2026-08-08
- 来源：《协作回执-2026-08-08》第四节——「好方向，我们很认。想认领请先出一页施工令式说明对齐」
- 状态：**方案待红队评审**。评审通过前不动一行代码。

## 背景

判官（质检 / 初检 / 核查 / 仲裁）现在与执行会话走同一条路：`spawn` 无头 CLI。
但**判官和执行是两种截然不同的工作**：

| | 执行 | 判官 |
|---|---|---|
| 需要工具循环 | 是（读写文件、跑命令、导航仓库） | **否** |
| 需要上下文管理 | 是 | 否（一次喂全，一次要结论） |
| 输出 | 自由文本 + 副作用 | **一行机器可读结论** |

判官只需要「喂一段文本、要一个结论」，却背着整个 agent 运行时的重量与故障面。代价是实打实的：

1. **CLI 内部错误对判官链杀伤最大。** 2026-07-31 `海投王-0-20`：集成活干完了、产出交了，
   质检的 codex 会话连报三次 `ERROR codex_models_man` → 三振进执行失败 → 无人分诊 →
   **整个集成停摆一周**。执行本身一点问题没有。
2. **`settleClose` 里堆着一层经验性防御**，全都是在跟 CLI 的输出形状搏斗：
   空输出不作数、光板结论判摆烂、质检报告找不到「结论」标记按失败重试、
   `extractClaudeText` 从 stream-json 里捞真报告（TK-35「闲聊尾巴吞掉真报告」案）。
   直连之后这些大部分可以退化成一次 JSON 响应解析。
3. **判官成本不可见。** 预算闸（施工令-021）对 codex 取不到 usage；
   直连的 response 自带 usage，判官花了多少一目了然。

## 范围

① 新增 provider 薄层：一次 `POST /v1/messages`，无工具、无流式，拿完整响应。
② **四类判官改走直连**：质检 / 初检 / 核查 / 仲裁。
③ 结论解析保持现有契约不变（`结论：通过|不过`、初检的 ```json 块、仲裁的 `方向：`），
   但判读对象从「CLI stdout 刮出来的文本」变成「响应的 content 文本块」。
④ 失败语义对齐现状：HTTP 4xx/5xx / 超时 / 解析不出结论 → 复用现有的
   `判官重试上限` 计数与「判官失败不打整单」纪律，**一个字不改**。
⑤ usage 直接进预算闸记账（施工令-021 的 `budget.记`）。
⑥ 保留回退开关 `执行器.判官直连 = false` → 走回 CLI 路径。

## 不要做

- **不碰执行会话。** 执行需要 agent 的 C 层（工具循环/文件读写/Bash），
  直连意味着自己造那一套——明确不在范围内，长期也不做。
- **不改判定语义**：通过/不过的判据、三振上呈、保留项豁免、自修轮次全部原样。
- **不改订阅额度纪律**：`quota.js` 的 ≥5 分钟间隔、失败退避、节流持久化不动。
- 不做流式（判官不需要活尾巴，它只要终局结论）。
- 不引入 SDK 依赖——沿用 `curl` 或 node 内置 `https`，与 `quota.js` / `netprobe.js` 同口径。

## 待评审的两个真问题（红队请重点打这里）

**① 判官用什么凭据？** 现状判官跑在 claude **订阅**登录态上（CLI 自己持有）。直连需要一个可放进 `Authorization` 头的东西，三条路：

- (a) 用 `~/.claude/.credentials.json` 的 OAuth accessToken 直连——`quota.js` 已经在用同一个 token 打 `/api/oauth/usage`，链路是通的。**但那是给 usage 端点用的，拿它打 messages 端点是否被允许、是否稳定，需要确认。**
- (b) 要求判官池配 API key（凭据托管已支持）——语义干净、成本可计，但**判官从此按量收费**，用户得为"以前免费的复核"付钱。
- (c) 两者都支持，`模型.判官凭据 = 订阅|key` 选择。

倾向 (b)+(c)，但这是**成本模型的改变，属制作人裁量**，不由本单自决。

**② 兼容端点的判官怎么办？** 现有兼容池（deepseek 等）通过 CLI 的 `ANTHROPIC_BASE_URL` 接入。
直连需要各端点的 `/v1/messages` 兼容度一致——已知 deepseek 兼容，其余厂商需逐个验。
建议：直连只对官方端点开，兼容端点判官继续走 CLI，`执行器.判官直连` 支持按池配置。

## 验收标准

□ 四类判官各有一条直连通路，结论契约与现状逐字一致（同一份回执，新旧两路判读结果相同）
□ 回退开关生效：`判官直连 = false` 时行为与今天完全一致（老测试全绿即证）
□ 判官失败语义不变：重试计数、封顶、「判官失败不打整单」三条各有测试
□ 响应 usage 进预算账，判官成本在 `budget.view()` 里看得见
□ 至少一条对照实测：同一张单、同一份回执，CLI 路与直连路结论一致
□ `npm test` 全绿
