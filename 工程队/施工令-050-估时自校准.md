# 施工令-050 · 估时自校准归项管（H101 落地·代码面）

案源：制作人 2026-08-12 21:14 决议 H101——预计时间/token 每次切单派单按历史「预估 vs 实际」偏差校准，归项管职能，制度化固定流程。章程正本：AI-GameStudio/协议库/C-规章/项目管理章程.md「估时校准步」（四步：取历史→算偏差→校估值→落痕），实装以章程为准。

写区：`apps/studio/lib/pm/estimate.js`（新）、`lib/pm/brain.js`（起草/切单提示词挂步）、`lib/pm/wake.js`（如切单链需挂）、`test/estimate.test.js`。

## 要件

1. **纯函数 `lib/pm/estimate.js`**：输入=历史完结单样本（职能、单型、预计时间/实际耗时、预计 token/实际消耗）+ 新单基准估值；输出=校准后估值 + 校准记录（样本数/偏差系数/校前→校后）。规则照章程：滚动中位比、样本 <3 用全局系数、系数夹 [0.5,3.0]、粒度取整 0.25h / 万 token。零 I/O。
2. **历史样本取数**：从台账/报表现有数据取（完结单的预计与实际字段已在账——实际耗时可由 领单→交产出 时刻差得，实际 token 用 047 流计量账；claude 外池无计量的单只校时间不校 token）。取数层薄封装可注入，便于测试。
3. **挂接**：`brain.draftTicket` 与切单链在成单前必过校准步——提示词写明「估值须引用校准输出，不得自由拍值」，且机器侧最终落 fm 前用 estimate.js 复核（提示词自律+机器兜底双层）。
4. **落痕**：每次校准记项管台账事件（类型=估时校准，含样本数/系数/校前→校后），晨报可对账。
5. **测试**：estimate 各分支（正常校准/样本不足回退全局/夹逼/粒度取整/无 token 计量只校时间）；brain 提示词含校准步文本断言；全量 npm test 零回归。
