## 一、数据模型与迁移方案（令面要件1 指定：先给方案，再动码）

### 1.1 实体形制——对齐管线注册表（H52 实体分立律）

`lib/specials.js`。一个专项 = `<仓库根>/专项/S-n.md` 一个文件，frontmatter 即 schema：

| 字段 | 含义 | 备注 |
|---|---|---|
| `id` | `S-1` 起递增 | 与管线 `P-#` 同族，**全局唯一一套号**，不带项目前缀 |
| `名称` / `目标` | 容器叫什么、要做成什么 | 名称必填，其余可后补 |
| `管线` / `项目` | 归属（H51 管线章 / D42 多项目视界） | 子单缺章时**从这里继承**（见 §三④） |
| `单号前缀` | 将来**子单**的派号前缀，缺省 `TK` | 专项号是 `S-n`，子单绝不能跟着叫 `S-n` |
| `状态` | `立项 / 进行 / 收口 / 关账` | 见 1.2 |
| `别名` | 实体化前的伪工单号（`TK-150`） | **迁移幂等的钥匙** + 子单归属兜底 |
| `履历` | 每次转移一笔 `{t,从,到,因,操作者}` | 基线变迁的一半来源 |
| `立项/收口/关账时间`、`关账签字`、`收口报告` | 时点与签字位 | 关账签字空 = 还没人签 |

**容器身上一格执行者字段都没有**——没有 `QA`、没有 `验收方式`、没有 `预计时间`、没有 `父单类型`。
TK-146/150 的病灶正是从这些字段开始的（单测锁死了这一条：见 §四「想法拍板」那格）。

### 1.2 状态机

```
立项 ──首子单派发──▶ 进行 ──全子单落袋──▶ 收口 ──✍ 制作人签字──▶ 关账（终态）
                       ▲                    │
                       └────── 复工 ─────────┘   （H65 返修：子单同号回草稿）
```

- 前三跳全是**机器按实况推的**，`关账` 是**唯一人闸**：`转移()` 里硬判「到 关账 必须署签字人」，
  绕过 `关账()` 直接调 `转移()` 一样被拦——人闸判据长在状态机里，不长在调用方的自觉上。
- `收口 → 进行` 这条回头路是本令加的、令面没写的一条：H65 返修让子单同号回草稿，容器若卡死在
  「收口」就是在说假话。复工同时**抹掉台账的收口去重旗**，不然复工后再落袋永远出不了第二版收口报告。
- 幂等：转到已在的态返回 `{ok:true, 幂等:true}` 且**不刷履历**——巡检拍 30s 一轮，每拍一笔痕就是把履历刷成噪声。

### 1.3 子单清单 = 反向聚合，不在容器里手维护

判据 `属于(专项, 子单fm)` 两路：
① 正路 `fm.专项 === S-n`；② 兜底 `别名.includes(fm.父单)`（迁移把子单的 `专项` 章补上但**不动 `父单`**，
所以万一某张漏补，别名这条路还认得出它）。容器里手抄一份子单号 = 给自己造第二个事实源。

**聚合视图** `聚合(root,id)` 三段：
- **进度**：`{总数, 落袋, 归档, 在办, 未起, 百分比}`。归档单**留在分母里**（废掉一张不该让完成度凭空变好看）；
  零子单 = **0%，不是 100%**（切单还没出结果的专项不许显示「做完了」，同 `progress.js` 的诚实纪律）。
- **预算**：实耗 h 走 `领单时间→交付时间`（与 `report.aggregate` 的 `实际h` 同源）、实耗 token 走
  `report.parseReceipt`——**不另立一把尺**。
- **基线变迁**：容器履历 + 子单集合的增删事实（返工 / 推翻 / 撤销）。

### 1.4 迁移方案

签名 `迁移(root, 计划, {演练, 操作者})`，计划形如 `[{单号:'TK-146', 名称?, 管线?, 项目?}]`，
缺省 `默认迁移计划 = [{单号:'TK-146'},{单号:'TK-150'}]`。**参数化而非写死两个号**：工单库住项目仓
（本会话够不着，见 §六①），迁移必须能对着任意一份仓库跑、能演练、能重跑——写死就只有上线那天能用一次。

每张伪单四步，缺一步都算没迁完：

| 步 | 动作 | 纪律 |
|---|---|---|
| ① | 建容器 | 名称/目标/管线/项目 从伪单 frontmatter 与正文原样搬，`别名` 记原 TK 号，正文头部加追溯链 |
| ② | 子单挂链 | 每张子单补 `专项: S-n`，**`父单` 章原样不动**（追溯链保真） |
| ③ | 推到「收口」 | 走 `立项→进行→收口` **三跳状态机**并留履历，因写「迁移」——**不许直接把状态字段写成「收口」**，那是给自己开后门 |
| ④ | 伪单归档不删 | `待验收 → 已归档` + `归档原因` + `迁移至专项: S-n` + `专项: S-n`。令面明写「归档不删」：纸面可考，工单板从此看不见它 |

- **幂等钥匙 = 别名**：重跑只补没做完的步，不再造新号；实测第二跑连容器文件的**一个字节都不改**（§四）。
- **默认演练**：API `POST /api/specials/迁移` 不带 `{执行:true}` 一律只算不写。迁移动的是工单 frontmatter
  与目录，一个手滑得靠 git 捞回来。
- **伪单不在本库 → 跳过不报错、更不凭空造容器**（工单库不可达时的正确姿势就是这一档）。

## 六、四件要报备

**① 真工单库够不着，迁移是「排练过的」不是「跑过的」。** 工单库住项目仓（`D:/GitHub/TK`），本会话
只够得着 Ticketflow 仓。所以本令把迁移做成参数化 + 默认演练 + 幂等可重跑的函数，并在**复刻现状的
演练仓**上跑完了全程（§三）。真库上执行是一条命令的事，且因为幂等，跑砸了重跑即可。

**② 存量「专项父单」工单的定稿钩子，本令按令面「迁至」二字**摘掉了**。** `server.js` 的 定稿 钩子
从此只认 `父单类型: 战役`（战役号明写不迁移，那条老路得留着）。若真库里除 146/150 外还有别的
`父单类型: 专项` 伪单，它们定稿时**不再自动切单**——但不会静默：会落一条 journal 并在返回里明说
「专项已实体化，请走专项页迁移或立项」。要不要把它们一并迁过来，是制作人的一次点单（迁移计划是
参数，加个号即可），我没替你决定。

**③ 加了一条令面没写的状态转移：`收口 → 进行`（复工）。** 理由与实现见 §一 1.2。不加的话 H65 返修
会让容器卡在「收口」说假话，且复工后再落袋永远出不了第二版收口报告。这是为了状态诚实而加的退路，
不是新语义——如果你认为容器一旦收口就不该再回头，说一声，删掉 `转移表.收口` 里的 `'进行'` 即可，
`收口自检()` 那一支会自然失效。

**④ 专项号是全局一套 `S-n`，不带项目前缀。** 旧 `ideas.拍板` 用的是 `<项目>-S#`（如 `TK-S1`，H86 考古
注记里那个漂移失传的旧例）。本令按令面「S 系列号（S-1 递增）」的字面取全局一套，与管线 `P-#` 同族；
项目归属改由 `项目` 字段承载，`单号前缀` 则专管子单派号。多项目共号是刻意的：容器登记册是一册，
不是一项目一册。
