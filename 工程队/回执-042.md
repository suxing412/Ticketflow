## 二、项目归属：本令唯一需要你复核的一格

施工令写「按管线字段过滤，含无管线的项目相关批」。落地时撞上一件事：**管线实体身上没有项目字段**
（`lib/pipelines.js` 的 schema 是 名称/阶段/状态/规格），管线与项目之间唯一的绳子是**工单**。
于是归属这样判（`项目视界()`，服务端 `工单语境()` 供佐证）：

1. 粒挂在**本项目工单出现过的管线**上 → 收；
2. 粒无管线但**已回填的单号是本项目的单** → 收（成了单之后，单号比管线更硬）；
3. **批传染**：同批只要有一粒认亲成功，整批同收——这正是「含无管线的项目相关批」。
   但明确挂在**别的管线**上的粒不被传染进来（跨项目共用批名时不许串味）。
4. 项目为空（单项目部署 / 未选项目）＝ 不过滤。

**已知盲区，不藏**：一条**刚注册、还没有任何工单**的管线，其计划粒判不出项目，会落进「未归属」。
（041 在流程页撞过同族的洞：行由「有单或已注册」生成，只有计划粒的管线整条隐身。）
我没有静默丢——`未归属` 计数如实下发，页面顶部出一句「另有 N 粒未归属本项目视界」并指向流程页。
**若你要的是「宁可串味也不漏看」，回一句，我把注册管线全量并进管线集**（多项目下会互相看见对方的计划粒）。

## 三、依赖置灰判据（§一 那半句话的展开）

- ref 是**粒ID** → 该粒 `状态==='完成'` 才算满足；ref 是**单号** → 工单态 `完成/已归档` 才算。
- 规则分两组判：`全部完成` 组逐条都要满足；`任一完成` 组有一条满足即放行（全不满足才整组回报）。
- **认不出的 ref 不据此置灰**（沿用流程页 `depsOf` 对无法解析依赖的既有处置）——一条指向早被清掉的旧单的
  依赖，若按「未满足」算，会把一条其实可以开工的活永久钉死在灰里。但不静默：`未知依赖` 原样回报，提示里写明。
- 置灰**只打在未成单的粒上**：已成单的粒有一张真工单，它的依赖是工单流程的事（流程页在管）；
  已完成/已撤销的更没有「在候谁」可言。

## 四、主页工程队队列卡（§二）

`hub` 的工程队状态卡扩成队列卡：顶行仍是 041 的直读施工令（逻辑一行未动），其下挂 Q 队列精简行
（批·序 / 徽章 / 题 / 候 / 预估），封顶 8 行，**余数如实写「…另有 N 项，去队列页看全」**。
队列取不到（老服务端）就整段不出，卡退回 041 单行样——不让整卡消失。

**这里冒烟抓到一个真洞，已修**：我起初按流程页「监制台维护队列」的口径取「无管线的待办粒」，
实跑发现一条**产品批里还没排线的粒（批C·3）跑上了这张卡**，冒充「监制台自己要修的活」。
在流程页那是可接受的（那一行标的就是「无管线归属的计划粒」，如实），在这张卡上就是撒谎。
改成**按批判**：本批只要有任何一粒挂着管线，整批就是产品线的活，不上工程队卡（`工程队队列()`）。
不写死批名字符串「Q队列」——批名是人手起的，改一次名这张卡会默默变空，那种空查不出来。
**流程页的既有口径本令未动**（不在令内）；两处从此差一格，差在哪、为什么，代码注释里写着。
