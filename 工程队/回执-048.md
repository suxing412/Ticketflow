## 零、先说三件

### ① 根因比令的描述再深一层：整页重建之外，还在**叠轮询**

令里写的病灶（令牌逐拍皆变 ⇒ 每 3s 整页重绘）属实，但现场还有第二层，不修的话
增量化之后会更糟：**`pollLoop` 的守卫是「同 id 的元素还在页上」**，而 `route()` 换的是
`innerHTML`——换完页上立刻又有一个同 id 的新元素。于是旧轮询**根本不会退出**，
每整页重建一次就多挂一条。视图函数里每次渲染都会 `pollLoop(...)` 一次，
繁忙半小时后同一块地方有几百条 fetch 在抢着刷（`viewQueue` 早年自己发号躲过这坑，
是唯一的幸存者——它那句注释「页面重画十次就有十条在跑」写的就是这件事）。

原地重绘保留节点，守卫元素更是一直在，不收这个口子等于把泄漏坐实。故 `pollLoop`
加了**同 guardId 只留最新一条**的代际号（`_loopGen`），一处改动、九个调用点全收。

### ② 三态不是「事后补救」，是**根本没被碰过**

令的要件 1 给了退路（做不到细粒度就保住滚动/展开/焦点三态）。本令没走退路：
`morph()` 拿新 HTML 与现有 DOM 逐节点比对，**整枝一字未变就整枝跳过**
（`o.outerHTML === w.outerHTML` 那一行是全部价值所在）。节点没被换过，
挂在它身上的滚动位、`<details>` 展开态、焦点、选区、进行中的动画就一个都不会掉——
不需要「先存后还」那套补救，也就没有补救本身会漏的那些边角。

判据也照这个来：morph 的实弹测试一律验**节点对象身份（`===`）**，不验 HTML 字符串——
字符串相等证明不了「没重建」，而没重建才是不闪的充要条件。

### ③ 为什么 `style.css` 一个字没改

令允许「+必要的 style.css」。实测**没有必要**：频闪是 DOM 重建带来的，不是样式问题；
视图淡入 `.vin` 本来就只在换视图时加一次，原地重绘不碰 `#view` 自身的属性，天然不参与。
写区能不动就不动。

## 二、morph 实弹：拿节点身份验，不拿字符串验

仓里没有 jsdom，本会话浏览器/Electron 也起不来。按既定手法（前端探针）自造了够 morph 用的
最小 DOM（`test/minidom.js`，只实现 morph 触碰到的那一小圈 API），把 `morph/morphKids/morphNode/morphAttrs`
从 `public/app.js` **原样抽出**跑在上面。九格实况：

```
✓ 整枝没变：一个节点都不重建（滚动位/动画/展开态天然存活）
    同一份 HTML 重放 → 全树节点身份逐个 ===，节点上的 scrollTop=480 原样在
✓ 只有一个数字变：只动那一个文本节点，其余身份不动
    <span class="n">3</span> → 4：外壳、span、隔壁 span 三个身份全部不变，只有文本节点的值换了
✓ data-live 元素原样不动：详情页秒表不被脉冲拨回 --:--（要件3）
✓ 正在敲的输入框：值与焦点都不许被新数据盖掉
    焦点在 #q、已敲入「我正在敲的字」→ 新 HTML 带 value="服务端旧值" → 焦点还在、值没被盖
✓ 没在敲的输入框：该同步的值照样同步（不是一律不管）
✓ 增删卡片：只增删该增删的，留下的兄弟身份不变（FLIP 与展开态都靠这个）
✓ 折叠态换了：改类不换节点（抽屉照旧是同一个抽屉）
✓ 画布不碰：wiki 图谱不会被脉冲擦成白板
✓ 标签换了才真替换（span → div 这种结构变化不能糊过去）
```

## 四、顺带修掉的三处「重绘会重复干」的副作用

原地重绘会把视图渲染函数**再跑一遍**，函数里那些渲染副作用于是会重复施加。
三处逐个上了幂等记号（记号写在**节点属性**上，`morph` 只管 HTML 属性，碰不到它）：

| 处 | 不修会怎样 | 修法 |
|---|---|---|
| 工单板横向滑块 `link()` | 每 3s 多两条 scroll 监听，挂几百条后横向拖动明显发涩 | `b.__hsLinked` 只接线一次 |
| 在途时间轴 `tlscroll` | 每次重绘把滚动位钉回最右——制作人往左看历史，每 3s 被弹回去一次 | `el.__tlHomed` 只在首次落地时钉右 |
| Wiki 图谱 `wkGraph` | 力导向模拟重跑=从环形起点重弹一遍，站定的图每 3s 被抖散（频闪最刺眼的一处） | 节点/边签名没变就不重弹 |
