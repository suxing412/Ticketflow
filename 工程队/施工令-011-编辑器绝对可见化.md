# 施工令-011 · 编辑器绝对可见化（制作人 2026-08-07 00:38 拍板，无应急孔）

裁决原文：「只要电脑进程还在就必须给我拉起带我可见窗口的编辑器」。系统内**只允许存在带可见窗口的 Unity 编辑器**，`-batchmode` 无头编辑器整族退役，无任何例外旗标。
设定考古（H86）：推翻 009 刚立的「全量冷 batch 净室」——净室语义改写为「可见编辑器重启后首跑」；TK-103 监听器的 batchmode 伪装缺陷随本令根除（isBatchMode 守卫仍留作保险）；H64 编辑器锁语义随之死亡（监制台侧按钮拆除另单，本单不动监制台）。

## 范围（仓：D:\GitHub\Ticketflow，工区：套件/enginectl/ + 套件/执行技能模板/）

1. **拆除 batchmode**：unity-test / unity-run / unity-build 的 `-batchmode` 启动路径全部移除，`--no-attach` 旗标退役（报错提示改用新旗标）。
2. **可见拉起**：探测无活监听器时——启动**可见 GUI 编辑器**：`Unity.exe -projectPath <工程>`（绝不带 -batchmode/-nographics，窗口正常展示）；Unity.exe 路径发现顺序：env `ENGINECTL_UNITY_EXE` → 工程 `ProjectSettings/ProjectVersion.txt` 版本号拼 Unity Hub 默认安装路径 → 找不到即人话报错。启动后轮询 `.enginectl-attach.json`（监听器上线），就绪即投递；等待上限默认 5 分钟（首次导入可能长，`--boot-timeout-min` 可调），超时人话报错**不回落无头**。
3. **净室新语义**：新增 `--fresh` 旗标：投递前先请求监听器执行「排空队列后自退出」（协议动作 `restart`，TK-103 侧返修实装；监听器不支持时本旗标人话报错），编辑器退出后重新可见拉起再投递——「重启后首跑」即净室。
4. **契约同步**（套件模板 pre-work/post-work）：「冷 batch 净室/--no-attach」字样全部改写为「可见编辑器；净室=--fresh 重启后首跑」；grep 验证零残留。
5. 已在跑的可见编辑器永不被 enginectl 杀死或抢占——只投递或（--fresh 时）礼貌请求自退。

## 不要做

- 不动 TK 仓（监听器 restart 动作由 TK-103 返修实装，本单只发协议请求并容错）；不碰 AI-GameStudio；不打包不提交。
- 不留任何隐藏无头旗标——灾难场景的答案是「修显示器」，不是无头。
