# Ticketflow 协作简报 · 通用软件开发方向

> 写给最早那位提第一个 PR 的朋友——你当时立的「通用软件开发平台」骨架，现在长成了下面这个样子。这份简报带你十分钟摸清现状，然后把「通用」这一翼交还给你来飞。
> 仓库：github.com/suxing412/Ticketflow（公开）· 当前 0.26.0 · 测试 32 套件 279 用例全绿

## 一、它现在是什么

**工单驱动的多 agent 软件开发控制台**（Electron + Node，零框架单文件前端）。人类制作人拍板与验收，AI 执行编制（多家模型 CLI 无头会话）按工单干活，审检链自动核验。过去一个月它作为一个真实游戏项目的产线跑了 100+ 张工单，全部制度都是实弹撞出来的。

核心机制一览（均有测试与实战案底）：

| 机制 | 一句话 |
|---|---|
| 工单生命周期 + 派发制 | 草稿→待投→在途→质检→待验收→完成；依赖就绪自动派发，执行者因单而生完成即销毁 |
| 审检三席 + 两检 | 质检（opus）→ 初检（廉价模型核格式）→ 深检（opus 核内容）→ 代签或留人 |
| 评审台（`packages/review-panel/`） | 多厂模型红队评审：三张立场卷轮换（可行性/不变量/成本）+ 击杀制，厂商缺席如实记录 |
| 瞭望塔（`packages/watchtower/`） | 会话外守护进程：流水/信箱/时钟/心跳/远端五信源 → 统一事件流+未读账本+桌面通知+心跳戳，计划任务自启 |
| wiki 知识总库 | 五分区：设计事实词条（带溯源链）/策划案（定案分层）/调研方案/技术方案/美术标杆 |
| 协同文档（codoc） | 块级三方协同编辑（人在 UI 改、AI 走文件改），每块作者戳可视，保存即单文件 git 提交 |
| 编制与并发项管化 | 职能×池序路由、死局自愈、并发配额动态调，全部走记账 API，无硬编码人头 |
| enginectl（`packages/enginectl/`） | 引擎通道抽象：任务投递给活编辑器（可见化）或拉起新实例，子集过滤、基线归档（现挂 Unity，接口即通道抽象点） |

## 二、仓库地图

```
apps/studio/          控制台本体：server.js（Express API）+ lib/（纯函数模块，全部可 node 直测）+ public/（单文件前端 app.js + 语义令牌 style.css）
apps/studio/test/     node 直跑测试链（npm test），32 套件——改任何 lib 必须全绿
packages/             公共件唯一的家：enginectl / review-panel（评审台）/ watchtower（瞭望塔）/ skill-templates / role-protocol-templates / core / providers（施工令-024 起，套件/ 仅留转发壳）
工程队/               施工令档案——每次平台改造的需求书+验收标准，读它 = 读平台的设计决策史
docs/                 设计与协议文档
```

## 三、公私分界（重要）

**本仓只放通用平台**。具体项目（游戏工程、工单数据、部署配置、密钥）全部在私有部署区，靠「项目注册」机制接入。你写任何东西请守住：不引用具体项目路径、不硬编码职能/厂商清单（一律读活配置——这条我们用血换过三次）、密钥零入库。

## 四、邀请：通用方向是你的

产线这条翼（游戏项目定制）由我们跑；**通用软件开发平台这条翼交给你主导**。眼下账上最有价值、且天然通用的方向（按我们实战痛点排序，全部可独立成章）：

1. **异步任务票据制**（头号痛点）：执行会话有「等不了长任务、子进程随会话死」的结构病——需要「投递即返票据、后续凭票取结果」的任务代理层（enginectl 与守护进程之间），这是所有长任务（编译/测试/构建）的通解。
2. **长任务/编辑器生命周期守护**：常驻工作进程归守护管理（瞭望塔已开了守护先例），任务排队投递，谁也不许拉自己的实例。
3. **引擎通道插件化**：enginectl 现在 Unity 一家，通道抽象已在——第二家（哪怕是 `make test` 的纯命令行工程）接上就能证明通用性。
4. **多厂模型接入抽象**：执行池/评审台的厂商发现与配额处理可以再抽一层（新厂零代码入席是目标，评审台已做到一半）。
5. 你自己看出来的任何方向——本仓的传统是：**先写一页施工令（背景/范围/不要做/验收标准），认可后动手，测试全绿交付**。`工程队/` 里有二十份样例。

## 五、协作方式

- PR 进 main，`cd apps/studio && npm test` 全绿是硬门槛（改 packages/ 也请带自测或取证说明）。
- 大改动前发一页施工令式的说明（issue 或 md），对齐了再写——我们这边有多模型红队评审台，可以帮你的设计免费挨几轮打。
