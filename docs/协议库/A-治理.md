# A 级 · 治理与主权

> 修改门槛：制作人逐条决议（口述 → 复述确认 → 写入历史库 → 誊入本典）。
> 条文末括号 = 历史库决议号（H 系列；H1–H45 即旧 D1–D45）。

## 一、决议机制

1. 协议级修改唯一路径：制作人口述 → AI 复述确认 → 记入历史库 → 誊入协议库。**问句不是决议**；未经此流程的实装视为越权，须撤回（H39 教训条款）。
2. 历史库只增不改；每条决议记录背景、原话要点与裁决理由。
3. AI 在治理层的角色：起草建议、执行决议、维护文档一致性——无裁决权（宪法·人本化）。

## 二、人闸体系（人保留的审批点）

全系统仅五个人工审批点，其余全自动（H16）：
①投池放行 ②待定夺拍板 ③保留单品味终审（不可代签，H11） ④入库/入标杆（精选制，H12） ⑤撤回/废弃。
派生规则：销毁性判断（打回归档）永远归人——代裁只能裁「给方向/上呈」（H43③）。

## 三、协作疆界（monorepo，H45）

1. 两产品一仓：`apps/studio`（游戏工作室，suxing412 主导）与 `apps/platform`（通用平台，robinwang2 主导），互不干预对方设计。
2. `packages/core`、`packages/providers` 为共享地基，改动双签（CODEOWNERS 落地）。
3. 分支纪律：feature 分支 → PR → main；main 永远可用（禁强推/禁删除）；版本以 per-app tag 收敛（`studio-vX` / `platform-vX`），不代对方发版。
4. studio 的协议文档（本协议库 + 部署工作区岗位协议）只经制作人决议修改，PR 不能改宪法。

## 四、发布纪律（H40/H41）

1. 公开仓只有工具：项目专有内容（项目命名、定制协议、配置实值、工单数据）永不入公开仓；套件内容全部通用默认。
2. 安全披露置顶且诚实：agent 拥有仓库写权限、无头 CLI 旁路权限、凭据文件读写、自动 git——两产品的对外文档同等标准。
3. 版本发布：调教好的存档点打 tag 出 Release；Release 附件用 ASCII 文件名。

## 五、商用红线

正式产出（游戏资产等）只准使用商用许可干净的生成通道/模型；非商用模型仅限草稿探索，产物不得入仓；地区性许可限制随通道注册表如实标注（H46 前置实践）。

## 六、数据与工具分离（H41/H45）

工具源码正本在公开仓；作战数据（工单九态/回执/journal/定制协议/配置实值/部署产物）在私有工作区。升级 = 换工具，数据原地不动。
