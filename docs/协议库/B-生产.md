# B 级 · 生产核心规则（studio）

> 修改门槛：制作人逐条决议。条文末括号 = 历史库决议号（H = 旧 D）。
> 本典是监制台（apps/studio）现行运行规则的蒸馏；设计脉络见历史库。

## 一、工单本体

1. 一切皆工单，差异三维：职能 → 产出物 → 验收方式（H4）。.md 工单是唯一任务形态，无口头任务（H1）。
2. 两平面：控制流（工单+回执，只归档不修改）/ 资产（住项目仓库，被工单反复打磨）。
3. 工单必备：范围 / 不要做 / 验收标准 / 完工要求；验收标准三档——程序 GWT 机器可判、美术客观段+主观段、策划可勾选要点；禁止不可核验项（维度 2b；宪法·透明化附款二）。
4. 编号 `前缀-序号`（支持中文前缀）；阶段章 `阶段: L0/L1/L2…`（H43）。

## 二、状态机与流转

5. **目录即状态机**：九态目录（草稿/待投/在途/质检/待验收/待定夺/执行失败/完成/已归档），状态=所在目录，frontmatter 不设状态字段（H5/H13/H19/H31；**H49 修订：「池」退役为项管台账隐态**）。
6. ~~投池人闸+拉取制~~（H2/H3/H17，**已被 H49 改判**）→ 见第七章「派发制」。
7. 返工铁律：旧单永不复活，打回=归档+带返工链新单（H6）；返工时下游依赖自动改指新单（2026-07 补）。
8. 执行失败为独立态，分诊三出路（重投/上呈/废弃），绝不悬空（H31）。
9. 滞留只告警不自动撤回（复查 R3）。

## 三、执行器与模型

10. 执行器内嵌于 app：断点恢复→自动领单→质检派发→委托代核→委托代裁，逐轮扫描（H30/H34/H43）；试跑零额度，实弹须显式解锁（人闸，H32）。
11. 模型分级：便宜模型干体力、贵模型当裁判；解析顺序 个体覆盖>池默认>CLI 默认；质检/代核/代裁走裁判档（H38）。
12. 就绪排序：优先级 > 红链（关键路径加权，孤节点不算链）> 创建时间（H43⑤；H49 后由项管台账执行）。
13. 额度纪律：账号级限流敬畏——查询硬间隔+失败退避+节流持久化+完工急刷；用量超阈自动冻结领单（双闸：暂停闸门+额度锁，H26）。
14. 判官纪律：判官失败不打整单（原地重试三振）；exit 0 + 空输出视同判官失败而非裁决；代核不过留待验收等人裁，代裁只裁给方向/上呈（H43③ 及补丁）。

## 四、质检与验收

15. QA 是单内可选关卡：不过→自修（≤上限）→修不好上呈四件套（H8/H10）。
16. QA 第〇步产出存在性核验：要求的文件不存在直接不过，回执写得再好也不过（章程 v2 铁律）。
17. 验收两轨：可核验项可委托（代核通过自动完成）；品味与方向只有制作人能签（H11/H34）。

## 五、阶段化生产（H43）

18. 阶段字典项目可配（默认 L0 原型/L1 正式化/L2 打磨）；阶段验收标准住 `阶段标准.md`（阶段×职能），起草选阶段自动带入。
19. 系统×阶段父单惯例：碎单全委托自动流转，父单末子为收尾单（保留）——"验父单"=验收尾单实物；升阶=开新单链到前阶。
20. 无硬阶段门：各系统独立推进，视图提示滞后/超前。

## 六、拆单纪律（H44）

21. **调研先行**：新系统开工前必须先开调研单（仓内盘点已有实现 + 竞品拆解 + 带锚号《设计原则》，保留验收）；此后拆单以其锚号为唯一依据。
22. 拆单明写：全新 / 复用 X / 替代 X。

## 七、追溯与联动

23. 四链：父子（母单为容器不进池）/ 返工 / 依据（文档#锚号）/ 依赖（未完成不可领）（H15）。
24. 上游变更联动人工制：锚号改版→受影响未完成单标待复核，三重拦截，机器只提示不自动改单（H36 与 R5）。

## 八、协作与写权

25. agent 间无私聊：池子+资产即全部交接协议（H14）；异议写回执不拒单，agent 只有记录异议权（H18）。
26. 写权限矩阵：职能写区结构性不重叠（策划=文档区、程序=Scripts/Tests、美术=资产文件、装配=拼接面独占、QA 只读）——并发隔离的根（H20/H39）。
27. 主办人制：领单者为唯一责任人，可单内自组临时团队，对外一份回执（H7）。

## 九、风格记忆（H12）

28. 精选制：策划标杆（提炼式公理）+ 美术库（精选范例），入库是制作人审批动作（审批点④）；agent 领单先对齐；条目随项目归属（H42）。

## 十、多项目（H42）

29. 一份监制台管所有项目：项目注册表+工单项目章；多项目先落启动页，驾驶舱按项目过滤；池/编制/额度/执行器全局共享（额度本是账号级）。

## 七、派发制与单元工单（H49，2026-08-03 立宪）

30. **派发制**：工单派发即拉起专属 agent，完成即销毁——一人一单一生命周期；确定性调度（依赖检查/槽位/拉起销毁）归执行器代码，判断性调度（切单/分诊/简报/并发策略）归项目管理职能，事件唤醒（单落袋/失败/新父单）。改判 H3/H29 拉取制（立论基础已随项管职能出现而消失）。
31. **单元工单机制**：1 单元 = 单一写区 + 恰好一个可核验产出 + 实耗与 token 基准（数值住 config，现值记 D 级惯例）；标准单 1 单元、顶格 2、估 3 必拆；报表每 20 单校准基准，偏离 ±30% 项管提议→Claude 审→改 config。
32. **双域分割**：想法池（制作人层域：轻量卡片，无验收标准无排期压力）→ **拍板**（唯一人闸：补边界+验收标准，成为父单）→ 项目组域（项管切单派发）。验收按父单收口（H43 升格）。
33. **沟通护城河（代码级保险丝）**：claude 池余量低于保留线时强制停拉生产单，制作人层对话与遥控通道永不受挤压；其余额度全权由项管排期调配，台账按父单归集成本。全局并发上限同为代码级保险丝，项管仅可在保险丝以内调。
34. **agent 装配清单**：拉起时注入 章程 + 协议选段（按职能/产出物类型摘条文）+ 上游依赖回执摘要 + 坑档案选段；装配开销计入该单 token 预算。
35. 项目管理职位章程见 C 级《项目管理章程》；标准单型库与单元基准现值见 D 级惯例。
