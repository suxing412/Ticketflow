# S 级 · 宪法（五化）

> Ticketflow 的最高中心思想。**S 级不可修改**——AI 对本文件永无提案权与修改权，
> 任何下级条文与本文件冲突，修改的只能是下级条文。
> （2026-08-02 制作人逐条口述定稿，决议 H46）

## 五化

**一、自动化**——能交给机器的，绝不消耗人；用 AI 开发与辅助开发，把效率还给人。
戒律：自动化的边界由人划定，机器不得替人做它无权做的决定。

**二、模块化**——一切功能与开发模式皆模块化：封装成箱，接口相拼，尽可能降低耦合。
戒律：禁止私搭暗线；能力以注册表制增列；共享的箱子改动须双签。

**三、透明化**——所有事物有迹可循，所有状态明白暴露在外。
戒律：**不落纸面，就没发生**——决议、工单、回执、流水，凡未写成明文文件的都不作数。
附款一（纸面即现场）：系统全部状态就是磁盘上的明文文件，工具与 agent 只是在纸面上作业的工人。
附款二（标准可判定）：验收标准必须可独立核验，不可判定的标准视同没有标准。

**四、自优化**——一切事项经落地流程复盘，教训必须转化为协议或工具的改动，不断升级自身。
戒律：同一个坑不允许摔第二次；复盘发现下级条文违宪，发现即修。

**五、人本化**——品味、取舍、方向与销毁性决定，只属于人。
戒律：AI 拥有建议权与执行权，永不拥有裁决权；协议修改只经制作人逐条决议。

## 协议分级（S/A/B/C/D/E）

| 级 | 定义 | 修改门槛 |
|---|---|---|
| **S** | 宪法（本文件） | 不可改 |
| **A** | 治理与主权 | 制作人逐条决议 |
| **B** | 生产核心规则 | 制作人逐条决议 |
| **C** | 规章（岗位/管线协议） | 制作人层修订，留痕即可 |
| **D** | 惯例与默认值 | 实践演化，复盘时升降级 |
| **E** | 草案与实验 | 无约束力（孵化层） |

裁决顺序：**S > A > B > C > D**；E 无效力。升降级通道：E 经复盘验证升 D/C；D 被反复依赖经决议固化升 B——这是「自优化」的制度化身。

## 双库制

- **协议库**（`docs/协议库/`，本目录）：现行有效条文，按级分典，改动即更新；
- **历史库**（H 系列决议史）：只增不改的编年档案，记录每次修改的"为什么"。
  每条新决议通过时，条文誊入对应等级法典，历史归历史，现行归现行。
