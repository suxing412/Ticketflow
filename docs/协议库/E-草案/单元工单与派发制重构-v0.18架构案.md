## 一、模块化单元工单（标准）

- **1 单元 = 0.25h agent 实耗 / ≤50k token / 单一写区 / 恰好一个可核验产出**
  （基准值由报表实耗滚动校准；初值取自 2026-08-02 程序岗 15 单实测均值）
- 标准单 = 1 单元；顶格 = 2 单元；**估到 3 单元必拆**（母单+子单）
- frontmatter 三要素必填：范围边界（范围+不要做+写区）、工作量边界（预计token）、预期时间
- 切割纪律：范围 ≤5 条；验收标准全部可判定（GWT/勾选）；依赖显式；产出章节按职能规矩

## 二、派发制（取消工单池）

- **工单派发即拉起专属 agent，完成即销毁**——agent 一次性，一人一单一生命周期；
  概念模型对齐物理现实（CLI 本就按次拉起）
- 状态机十态 → **九态**：「池」退役，代之以项管台账中的**就绪列表（待起，隐态不占看板）**
- 必须活下来的三件（换名不换命）：
  1. **并发闸**：项管调配，**额度锁与全局并发上限为代码级保险丝，项管仅可在保险丝以内调**
  2. **就绪缓冲**：并发/预算咬合时就绪单在台账排队，依赖就绪+槽位空闲即拉起
  3. **人闸**：上移为支票制（见三）
- **确定性调度归执行器代码**（依赖检查/槽位计数/拉起销毁，零 token）；
  **判断性调度归项管**（切单/分诊/简报/并发策略），事件唤醒（单落袋/失败/新父单）
- H49 决议要点：D29 否派发制的立论是"派发制把制作人变成调度器"；
  今调度器为项管职能、人闸上移支票级，立论基础消失，故明文改判。历史库全程留痕。

## 三、支票制（人闸的完整形态）

- **父单 = 支票**，三要素缺一不收：内容边界 + 验收标准（标明保留项）+ **token 预算面额**
- 项管消费支票：拆子单预留额度、完成实耗结算，台账可随时回答"花到哪了"
- **预算纪律（制作人定稿）**：剩 20% 额度即报警呈报；**面额 +20% buffer 为硬停线**——
  烧穿 buffer 停机待批，续做 = 制作人批增补支票挂同父单
- 急刹权：制作人随时作废支票（在跑单跑完即止）
- 验收回归 D43 哲学：阶段末按父单验收；保留单品味终审照旧

## 四、项目管理职位章程（核心条款）

**常驻语义**：职位常驻=台账常驻+事件唤醒，非进程常驻。监制台启动即当班、湮灭即离班；
台账（支票账/就绪列表/在跑/排期/事件流水）全明文落盘，崩溃重启无缝续班。

**拆单能力栈（六件套，缺一不拆）**：
①仓况盘点（不盘点不许拆，TK-22 案入章）②调研先行判断（未知数超阈第一张必是调研单，D44）
③历史校准（报表基准喂估值）④协议选段（相关 C/D 条文写进子单）
⑤依赖建模（同写区串行/异写区并行/红链标定）⑥单元合规自检

**标准单型库（制作人定稿：可增不可写死）**：
初始五型——调研单/实现单/装配单/修复单/收口单，每型带模板与验收句式；
职能路由按产出物类型定死；品味类产出自动标保留；**方向性取舍不属于拆单，遇之上呈**。

**拆单审批流（制作人定稿）**：
项管拆完 → **呈 Claude 制作人层审批**（修复意见发回项管改，循环至过）→
**特殊情况（方向歧义/超预算预判/新单型需求）呈制作人**。日常拆单不打扰制作人。

**职权**：并发闸调配、就绪与拉起节奏、依赖与排期（关键路径+收口预测滚动修正）、
异常机械处置（失败重投/返工开单/依赖接续）、晨报与收口报告。

**上呈红线（必须上交，无裁量）**：支票报警与硬停、三振、同型连环失败、
方向含糊、需改协议、品味判断。

**自身消耗（制作人定稿）**：报表单列「管理费」行——雇它值不值，账面永远可见。

## 五、agent 模块化装配（拉起时的装配清单）

| 装配件 | 说明 |
|---|---|
| 编制协议 | 通用+职能章程（现有） |
| **协议选段** | 按职能/产出物类型挑选相关 SABCDE 条文（协议库需条文打标签支持机读选段） |
| **上游依赖回执** | 依赖单回执摘要随装配注入（修复现存缺陷：agent 不知上游产出细节） |
| 坑档案选段 | 同写区/同引擎历史坑（版本纪律、路径分裂等） |
| 工单本体 | 单元工单全文 |

约束：装配 token 开销计入该单 50k 预算——选段必须节制。

## 六、落地三步（每步独立可停）
