# 游戏开发管线总协议（E 草案 · v1）

> 覆盖 2D 与 3D 游戏、跨引擎（Unity / Godot / Unreal）的完整生产管线总纲。
> 与既有法典的关系：不改 B 级生产规则（状态机/拉取制/阶段化照旧运转），本协议解决的是
> **"同一套工单流水线如何吃下不同引擎、不同维度的游戏项目"**。
> 事实依据：《引擎适配调研报告》（同目录）；两引擎本机无头 E2E 已实证。
> 升级路径：制作人批准后主体升 B 级「十一、引擎适配」章 + C 级章程修订。

## 一、总原则

1. **引擎是可拔插的箱子**（宪法·模块化）：项目注册时声明引擎与版本；一切引擎操作走
   `enginectl` 通道注册表（探测/导入/测试/导出），协议与工单永远只认通道名，不认引擎命令行。
2. **每个项目一个引擎档案**：`项目.注册[名].引擎 = { 类型: unity|godot|unreal, 版本 }`；
   环境探针按引擎档案做全链自检（引擎在位、版本匹配、通道冒烟）。
3. **版本纪律**：引擎通道执行前强制校验工程版本 == 本机引擎版本，不符拒开
   （实证坑：Unity batchmode 对不匹配工程会静默升级 ProjectSettings）。
4. **冒烟即底线**：装配单的"能进能玩"以引擎通道冒烟出口码为准（Godot=测试脚本 quit 码、
   Unity=NUnit XML failed=0、UE=RunAutomationTests 结果）——出口码是可判定验收（宪法·透明化附款二）。

## 二、引擎适配矩阵（agent 写区按引擎特化）

| | Godot | Unity | Unreal |
|---|---|---|---|
| 程序写区 | `*.gd` / C# 脚本（全文本直写） | `Assets/**/Scripts`、asmdef（直写；.meta 由引擎生成，禁手编 guid） | C++ 源码 + Python 编辑器脚本（资产不可直写） |
| 美术产物落位 | `res://art/`（png/glb 直入，import 走通道） | `Assets/<项目>/Art/`（导入经 batchmode/编辑器触发） | 经脚本导入生成 .uasset，禁手写二进制 |
| 装配写区 | `.tscn/.tres`（明文场景直写——装配的天堂） | `.unity/.prefab`（YAML 可写但易碎，优先脚本化生成；拼接面独占不变） | 蓝图/关卡仅经 Python/commandlet 脚本化操作 |
| QA 核验通道 | `enginectl godot-test`（SceneTree 断言脚本） | `enginectl unity-test`（EditMode/PlayMode） | `-RunAutomationTests`（通道待实装） |
| 构建产物 | `godot-export`（preset 明文） | `unity-build`（工程内 static 构建方法，按项目落地） | `BuildCookRun -cook -pak`（待实装） |

**引擎选型默认建议**（拆单调研时可推翻）：纯 2D 项目优先 Godot（全文本工程 = agent 摩擦最小）；
3D/生态依赖重（如现有 TK）用 Unity；写实大世界/影视级才动 Unreal（体量与二进制资产使 agent
介入面收窄为程序单线）。

## 三、2D 游戏管线（新增专章）

1. **资产类型**：精灵/序列帧、Tileset/Tilemap、九宫格 UI、图标、背景分层——全部走 artgen
   t2i 通道生成（白底/透明底规范），风格 LoRA 纪律沿用《美术生产管线协议》。
2. **透明底约定**：精灵与 UI 件需要 alpha——SDXL 不产 alpha，管线补后处理位
   （背景移除通道 `bg-remove`，用户 ComfyUI 已有 birefnet 模型，待接入 artgen 注册表）。
3. **Tileset 两段式**：图集单（t2i 生成 tile 图集，尺寸=格数×格宽严格约定）→
   装配单（Godot: 直写 .tres TileSet；Unity: 脚本切片导入）。
4. **2D 阶段口径**（并入 阶段标准.md）：L0=灰盒色块+占位精灵可玩；L1=正式精灵+风格 LoRA
   一致；L2=动效/粒子/打磨。

## 四、3D 游戏管线

沿用《美术生产管线协议》三章（概念图→mesh-3d→装配落位）+ 引擎侧补充：
1. GLB 进 Unity 由装配职能导入（缩放/轴向/材质占位记回执）；Godot 原生吃 glTF 直入；
   UE 经 Interchange 脚本导入；
2. 贴图管线、角色专线维持路线图状态（不预置）。

## 五、职能章程增补（C 级修订清单，批准后落）

- **程序**：按项目引擎档案写代码；Unity 禁手编 .meta；Godot 优先 gd 脚本；UE 仅 C++/Python 写区。
- **装配**：引擎差异见适配矩阵；一切"能进能玩"结论必须附 enginectl 冒烟出口码。
- **QA**：核验走 enginectl 通道产出（XML/退出码），不再手工"我看了觉得能跑"。
- **美术**：2D 专章规范（透明底/图集尺寸约定）并入美术管线协议。

## 七、与既有法典的边界

- 不动 B 级：状态机、拉取制、阶段化、判官体系对任何引擎一视同仁——引擎差异全部被
  enginectl 通道和写区矩阵吸收在边缘；
- 美术管线协议（同为草案）作为本协议的资产生成分册；
- 本协议批准即升级：主体入 B 级新章，职能增补入 C 级章程，默认建议入 D 级惯例。
