## 二、三个坑与真因

### 坑① 工作区 bootstrap 死局（工具的锅）

**症状**：`npm run desktop` → `未找到监制台仓库（缺 studio.config.json）` → 直接退出。

**真因不是"必须改 JSON 才能加项目"**——加项目有完整 UI（参数页·项目注册，
`POST /api/config/project`，带路径校验和"有未完成单引用就拒删"的护栏）。真因是**先有鸡还是先有蛋**：

`config.resolveRoot()` 找不到配置 → `initError` → `main.js` `showErrorBox` + `app.quit()`，
**而那个 UI 就在被关掉的窗口里**。套件路线靠 `部署.bat` 铺骨架绕开了，源码路线没人铺。

### 坑② 死代理毒死所有子进程（工具的锅，今天最贵的一个）

**症状**：工单被派发，跑几分钟后 `API Error: Unable to connect to API (ConnectionRefused)`。

**真因**：`套件/studio.config.template.json` 里 `网络.代理默认 = http://127.0.0.1:7890`
是个游戏项目环境的遗留默认值。那台机器上 7890 **没有任何进程在听**，但
`server.js` 的 `injectProxy()` 照样把它注入监制台自身进程环境，
**所有子进程（codex / claude CLI / curl）统统继承** → 会话开局即死。

实测三组对照：

| | 结果 |
|---|---|
| 直连 `api.anthropic.com` | HTTP 403，TLS 握手 0.5s —— **通的** |
| 直连 `github.com` | HTTP 200 |
| 经 `127.0.0.1:7890` | HTTP 000，连接被拒 |

### 坑③ 探针把致命项报成绿灯（放大了坑②）

`/api/env` 旧探针对代理这一项只验「解析到了一个值」，不验「这个值连得上」。
于是**总灯显示降级、唯一致命的那一项亮着绿灯**，照着黄灯排查永远查不到真凶。

这个语义错误比探针没验活更严重：代理坏掉时**每一张执行单都必死**，
那不是「能力受限（黄）」，是「核心不可用（红）」。

## 三、讨论后定下的方向

制作人裁决（2026-08-08）：

| 议题 | 结论 |
|---|---|
| 登录方式 | **路 B：代跑官方登录命令**，不自己实现 OAuth |
| 覆盖厂商 | claude + **codex 也做** + **deepseek** |
| 跨平台 | **不做**（Windows-only） |
| 计费模型 | 订阅与 key **两者都要**：套餐优先，套餐用完降级到 key |
| key 存放 | 可选项；不进 `studio.config.json` |

### 为什么是路 B（重要，别回头改）

`claude -p --permission-mode acceptEdits` **不是 API 包装器，是一个完整的 agent**——
工具循环、文件读写、Bash、上下文压缩、仓库导航。直连 API 意味着这一整套要自己造。
所以凭据这件事拆成三层，只动最便宜的那层：

| 层 | 现状 | 本次是否动 |
|---|---|---|
| A 凭据 | 靠用户 `claude auth login` | **动了**（托管 + 一键登录） |
| B 传输 | spawn CLI 子进程 | 没动 |
| C agent 运行时 | CLI 自带 | **不要碰** |

路 B 的核心红利：**订阅态 app 一个字节都不存**。授权全程第一方，厂商改登录页与我们无关。
真正需要加密保管的只有 API key。

## 四、已落地的改动

### 新增模块

| 文件 | 行数 | 干什么 |
|---|---|---|
| `lib/netprobe.js` | 79 | 网络活性探针。判据翻译 `verdict()` 是纯函数可单测，网络 I/O 走 curl |
| `lib/creds.js` | 145 | 凭据托管。DPAPI 加解密、密文落盘、脱敏清单、明文内存缓存 |
| `lib/setup.js` | 142 | 首次运行向导地基。内置配置模板 + 内置章程兜底 + 幂等建工作区 |

### 修改

**`server.js`**（+125）
- `ROOT` 由 `const` 改 `let` —— 向导建完工作区**就地重挂，不用重启进程**
- 新端点：`GET /api/setup/state`、`POST /api/setup`（**不过 `ready()` 闸**，它们正是用来把 app 从未就绪状态捞出来的）
- 新端点：`GET /api/creds`、`POST /api/creds`、`POST /api/creds/remove`、`POST /api/auth/login`
- `/api/env` 的「代理」项换成「API 连通」，接 netprobe
- `STUDIO_PORT` 环境变量覆盖端口（未就绪时也得有端口可听；开第二实例验证时不抢 4270）
- `docs.setZones(cfg.文档分区)` 接线

**`lib/docs.js`**（+25）
- 三个文档分区的根路径从写死（`Docs/SLG/**`，作者游戏项目布局）改为**可配** `config.文档分区`
- `ZONES` 保持同一个对象引用**就地改写**（重新赋值会让已 `require` 的调用方拿着旧表）
- 默认值一字未动，没配到的分区保留默认

**`lib/pm/dispatch.js`**（+30）
- 新增 `计费Of()`：显式 `计费` 字段优先，没写就按有没有 `兼容` 段推断
- 新增 `降级Of()`：**只有 订阅→按量 出标记**（同计费、反方向、同池都不出）
- `routePool()` / `pickNext()` 透传 `降级`

> **「套餐用完降级到 key」不需要新机制**——池序本来就是路由优先级，
> `dispatch.routePool()` 顺位取第一个未冻结池。把同一厂商配成 `claude` + `claude-key`
> 两个池挂进同一条池序即可，零新代码路径。本次加的只是**留痕**。

**`lib/runner.js`**（+44）
- 新增 `凭据Of(root, cfg, poolName)`：托管库优先 > config 内联 `兼容` 段（旧路径保兼容）。订阅池永远返回 `null`
- `base` 改为可缺省：原生厂商的 `*-key` 池用官方默认端点，只有第三方兼容端点才改 `ANTHROPIC_BASE_URL`
- **剥代理只对第三方端点**（旧样无条件剥，会让需要代理的机器上 `*-key` 池必死）
- 派发时落 `降级` 痕：journal + 项管台账 + **信箱急件** + 工单 `fm.计费降级`，四处同时

**`main.js`**（+9）
- `initError` 不再 `showErrorBox` + `quit`，照常开窗，前端落向导页

**`public/app.js`**（+95）
- `route()` 开头先问 `/api/setup/state`（必须在 `loadCfg` 之前——未就绪时 `/api/config` 是 500）
- `viewSetup()` 向导页；`credsLoad()` 凭据卡片（参数页右栏，环境探针下方）
- key 输入框走 `askInput(..., {password:true})`；全程用项目自绘的 `ask`/`askInput`
  （**Electron 壳内原生 `prompt/confirm/alert` 是哑弹**，`dialogscan` 自检盯着这条）

### 设计上刻意的几点

- **死代理判红不判黄** —— 每张执行单都会死，属核心不可用
- **直连对照组永远跑，且显式 `--noproxy '*'`** —— 不加的话父进程注入的 `HTTPS_PROXY`
  会让对照组偷偷也走代理；有这组对照，红灯才能分清是「摘掉代理就好」还是「本机网络本来就不通」，两种修法相反
- **DPAPI 挂了就拒绝保存**，绝不静默降级成明文——凭据的失败必须是响亮的
- **明文只走环境变量进 PowerShell，不进 argv**（argv 在任务管理器里是明着的）
- **模板 `网络.代理默认` 改为空串** —— 需要代理的人在参数页填，比让不需要的人排查一个隐形杀手划算
- **登录可见拉起**，不做无头 —— 登录本来就是交互动作，同 施工令-011「编辑器绝对可见化」的道理

## 五、测试

```
34 / 35 套件绿    288 用例
```

新增：`netprobe` 12 例、`creds` 13 例、`setup` 9 例；`dispatch` 由 13 扩到 19 例（+6 计费/降级）。
三个新套件已挂进 `npm test`。

**唯一的红是 `runner.test.js`，与本次改动无关。** 它的「实测形状（stderr-only 子进程）」
用例固定睡 40ms 就断言，而这台机器上 node 子进程从 spawn 到第一个字节落地要 ~52ms
（实测 5 遍：4 遍 `tail=undefined`，1 遍只拿到第一块）。**时序假设写死，不可移植**。
修法是把固定睡眠换成「轮询到条件成立或超时」，并把子进程 stdout 的延迟从 60ms 放宽。
最近一次提交声称的「279 用例全绿」在作者机器上应该是真的，只是这条不可移植。

## 六、遗留与已知问题

1. **改动未提交。** 工作区里就是，`git status` 可见。
2. **`package.json` / `package-lock.json` 被 npm 改过**：electron `^30.5.1 → ^43.3.0`，
   electron-builder `^24.13.3 → ^26.15.3`。跨了十几个 Chromium 大版本，
   而 `main.js` 里那些缓存清理 / `flushStorageData` / 强制退出的补丁是针对 30 写的。
   要么回退，要么单独验一遍换版后 UI 有没有借尸还魂。
3. **预算闸没做。** 现有双闸全建立在「订阅有个会重置的用量窗口」上（5h/周、
   `阈值/周阈值`、`~/.claude/.studio-usage-throttle.json` 的 ≥5 分钟查询纪律）。
   API key 是按量计费、没有这个窗口。语义要从「额度锁」改成「消费预算闸」：
   `阈值` → 日/月预算百分比，护城河 → 留多少预算给对话。结构可完全复用，但**不能落下**——
   否则 key 池等于没有任何成本刹车。
4. **`codex` 的 key 池路径未实测。** `凭据Of()` 对所有池一视同仁，但
   `resolveCli('codex')` 走的是 `codex exec`，它认不认 `ANTHROPIC_AUTH_TOKEN` 没验过。
   claude 侧（原生 + 兼容）逻辑是原有路径的自然延伸，风险低。
5. **`/api/env` 的 codex 登录态仍只探 app-server**，没接 netprobe 的活性验证。
6. **判官直连 API 的方案没做**（讨论中提过）：判官会话只需「喂文本、要结论」，不需要工具循环，
   完全可以走一次 messages 调用。那样 `settleClose` 里一堆经验性防御（空输出、光板结论、
   结论标记判读、stream-json 提取）大部分能退化成简单响应解析，
   并且正好治 `ERROR codex_models_man` 那类 CLI 内部错误——**今天让整个集成停摆一周的就是它**。
7. **`docs.js` 的分区名仍锁死三个**（策划案/调研方案/技术方案），因为前端 `WK_DOC_TABS` 是硬编码的。
   只有根路径可配。
8. **`lib/wiki.js` 的词条根仍写死** `Docs/wiki`（Windows 大小写不敏感，实际落在 `docs/wiki`）。
