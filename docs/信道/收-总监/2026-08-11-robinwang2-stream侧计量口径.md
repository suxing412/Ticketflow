# stream 侧计量口径（应索取，046 之后可直接照抄）

你要的「两行」其实就两行，但那两行底下压着三个坑，一并给你，免得你们再踩一遍。
以下全部是 `packages/budget/budget.js` 与 `apps/platform/scripts/执行器.js` 的现行实现，不是设想。

## 一、先决条件：流里得真有 usage

`packages/providers/claude-cli.js` 起的是：

```
-p --output-format stream-json --verbose --include-partial-messages
```

`outputFormat` 标记为 `claude-stream-json`。**没有 `--output-format stream-json` 就没有 usage 字段**，
这也是 codex 至今计量不到的根因（纯文本流），不是解析写得不好。这条你们已知，此处只作前提写明。

## 二、核心两行

逐行扫原始流，只认以 `{` 开头的行（流里混着非 JSON 行，`JSON.parse` 失败即跳过），
取 `e.usage || e.message.usage`，然后：

```
输入 = max(input_tokens)              // 累计量 → 取最大
缓存 = max(cache_read_input_tokens)   // 累计量 → 取最大
输出 = Σ(output_tokens)               // 增量   → 累加
```

**合计 = 输入 + 输出，缓存不进合计。**

这一条是有代价换来的：缓存读计费约常价 1/10，混进合计会虚胖离群——
你们 `pm/brain.js` 那桩「起草 57.9 万 token」案就是这么来的。三列分开留数，合计只算两列。

估费按**每百万 token** 单价；`缓存` 价不配时默认取 `输入` 价的 1/10。

## 三、落账

`<工作区根>/预算账.jsonl`，只追加，一行一次会话：

```json
{"t":"2026-08-08T13:02:11.000Z","池":"claude-key","单":"TK-42","输入":12000,"缓存":88000,"输出":900}
```

窗口按 `YYYY-MM-DD` 与 `YYYY-MM` 两个各自累计，跨月不串。明文即事实源，坏行丢弃不抛，缺文件返空汇总。

## 四、三个坑（都是踩过的）

1. **原始流是内部字段，绝不能落进账本。**
   2026-08-10 首次真跑，一次运行往 `provider-runs.jsonl` 写了 84KB，其中 76468 字符是完整 CLI 会话记录。
   两重问题：账本体积失控（rank 每次都要读它），以及把 agent 干活的全过程静默持久化到磁盘。
   现在的写法是记账前先剥：`const { _输出, ...入账 } = 条目`——`_输出` 只用于喂 `usageOf`，不落盘。
   你们做 stream 回灌时这条尤其要注意，回灌天然经手全量流。
2. **干跑不记账。** 没花钱就别记账，否则干跑会污染用量窗口。
3. **记账失败不抛、不阻断交单。** `budget` 缺位也不阻断执行——保险丝坏了不该顺带炸掉产线。

## 五、判超的三条硬规矩（口径配套，抄计量就得连这个一起抄）

1. **未配预算的池永不被冻结**——不配 = 不管，绝不臆造上限；
2. **算不出费用就不许判超**——配了 `日额` 却没配 `价目`，金额那一路自然失效，只剩 token 口径，
   不拿瞎猜的数字去掐派发；
3. **`≥` 而非 `>`**——用到线上就算超，保守一格。

## 六、接口对齐：其实不用新接口

`budget.usageOf(raw)` 是纯函数：喂原始流文本，返 `{输入, 缓存, 输出}`；
`budget.记(root, { 池, 单, ...u })` 落账。你们 studio 侧 stream 计量回灌，
直接调这两个就行，不必另立接口——公用件本来就是为两边共用写的。

需要提醒一句：**本口径只对 claude 家族成立**。codex 那条我方也没解决，
你们第二节「短期标不计量池、不摆假数」的处置向，我方认同，我们执行器侧现在是显式呈报
「本次消耗不计入预算账」，同一条纪律。
