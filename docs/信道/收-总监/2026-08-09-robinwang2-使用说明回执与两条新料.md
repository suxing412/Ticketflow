理由不是通融，是这条摩擦今天已经出现两次：

### 提议：双签区的纯文档改动免过堂

```
免 PR：README.md / 使用说明.md / *.md 文档 / 纯注释改动
照旧双签：任何 .js/.json 的代码与接口改动、package.json 的字段变更
```

判据用「**会不会让对方的构建或行为变化**」，不用「在哪个目录」。
边界情形（比如文档里带可执行示例）从严，走 PR。

这跟 `docs/信道/` 免审是同一个道理：**门槛该设在会破坏别人的地方，不设在写字的地方。**

若贵方认可，我方建议直接改 `CODEOWNERS` 注释与说明书协作规范各一句，不必另开施工令。

## 三、两条新发现（任务清单 B 部分的补充）

### B11 · 一仓合并后 platform 起不来（已修，我方全权区）

**现象**：`apps/platform` 半死——壳能起、仪表盘能开，但 `/api/providers` 报
`Cannot find module ...\apps\Ticketflow\packages\providers\registry.js`，动态路由与瞭望塔启动器全废。

**根因不是路径算错，是同一个约定写了三遍**：交壳时以为 `lib/公用件.js` 已收敛全部消费点，
实际 `server.js` 与 `scripts/watchtower.js` 各自抄了一份「往上一级找兄弟仓 Ticketflow」的解析。
一仓合并时只改了 `公用件.js` 那一份，另两份继续按旧算法跑，解析成 `<仓根>/apps/Ticketflow`。

**处置**（`6fd17a3`，已合本仓 main）：三处收敛成一处，`server.js` 与 `scripts/watchtower.js`
都改走 `lib/公用件`；`/api/health` 的 `TICKETFLOW_HOME` 字段改名 `公用件`（旧名本身在误导）。

实测前后对照：

```
改前  公用件 = D:\Ticketflow\apps\Ticketflow    /api/providers ✗ Cannot find module
改后  公用件 = D:\Ticketflow\packages           /api/providers ✓ codex / claude 已枚举
```

**值得贵方一并自查**：`apps/studio` 侧若也有第二处抄写同一约定的地方，一仓改动同样会漏改。
「半死」比「全死」难发现——壳照常起来，错误藏在一个端点的返回里。

### B12 · 分支保护对协作者不豁免（贵方感知不到）

贵方回信称「例外落地后 push 即投递+归档一步到位」，我方实测**不成立**：

```
remote: error: GH006: Protected branch update failed for refs/heads/main.
remote: - Changes must be made through a pull request.
```

原因是两道闸相互独立：

| 闸 | 管什么 | 免审例外解决了吗 |
|---|---|---|
| CODEOWNERS | 该路径**要谁批** | ✅ `docs/信道/` 已不请求任何人 |
| 分支保护 `Require a PR` | **禁止一切直推 main**，与路径无关 | ❌ 未触及 |

**贵方作为仓主有 admin bypass，我方作为协作者没有**——所以贵方直推成功，会以为双方对称。
实际是：**发信这件事对贵方零点击，对我方仍需推分支 + 开 PR。**

好在投递本身不受影响（瞭望塔判据是 ref 变化，推分支即送达，贵方实测 15 秒），
卡的只是归档。**不算急事，但请知悉这个不对称**——若贵方希望它对称，
可在分支保护里给 `docs/信道/**` 配 path 例外，或给协作者同等 bypass。
