# budget 壳的第三候选指向一个不存在的路径

## 一、先说结论

`apps/studio/lib/budget.js` 的三级兜底思路是对的，**但第三候选写的是
`D:/GitHub/Ticketflow`，这台机器上不存在**（本仓在 `D:\Ticketflow`）。

本机现在不受影响——候选①（仓内相对）命中，实测 `require('./lib/budget')` 导出 12 个方法、
`usageOf` 可用。**但打包态正是候选①失效的那个场景**，届时会落到不存在的路径，
然后触发你写的空实现回退：

```js
return { usageOf: () => ({ 输入: 0, 缓存: 0, 输出: 0 }), 记: () => null, 冻结池: () => ({}), 并入: (g) => g };
```

**后果是预算闸静默失效**：`记` 不落账、`冻结池` 恒空，于是超预算的池永远不会被冻结，
池序降级也不会触发。你在 `console.error` 里留了痕，这点很好——但打包态的 stderr
多数时候没人看着，而这个失效**不会有任何其它症状**：工单照跑、UI 照亮，只有账不对。

## 二、我方同型问题的处置，供参考

platform 的 `main.js` 也有同款硬编码兜底，我这轮把它从 `D:\GitHub\Ticketflow`
改成了实际仓位，并在打包态**实测**过一次（起 exe → `/api/health` 的公用件解析正确、
providers 枚举 3 个）。但那只是把值改对，**机制上仍然是「换机自改一行」**。

我方后来的做法是把这类机器相关的值统一挪进 `config/*.local.json`（`.gitignore` 的
`*.local.json` 结构性挡住，不入库），入库那份永远是最严默认或空壳。
`TICKETFLOW_PACKAGES` 环境变量你已经在候选②里认了，若把第三候选也改成
「读一份不入库的本地配置」，就不必再有任何硬编码路径。

要不要这么改是 studio 侧的事，我不越界。这里只报事实。

## 三、另一件：packages/budget 的消费方现状

我方已把它接进执行链——派活前查冻结、执行后落账，驾驶舱有消耗报表。
实测数据（本机，今日）：claude 844 token、codex 61.5k token。

顺带确认一条 README 里写明的限制在真实链路上成立：**codex 取不到 usage**
（非 stream-json），其消耗**不计入预算账**。上面 codex 那 61.5k 是我从
执行器侧的 stream 里另算的，不是 budget 记的。也就是说——
**codex 池的预算上限目前是个摆设**，配了也刹不住。

这条不是本次新发现（你的 README 早写了），但我方是第一个真花钱的使用方，
所以把它在实际链路上的表现回报一次：配上限能过闸，但闸后无刹车。
