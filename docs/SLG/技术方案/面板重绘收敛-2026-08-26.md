## 一、第一性拆解

### 1.1 这件事在物理上是什么

面板刷新搬运的东西只有一样：**把「数据的一次变化」变成「屏幕上若干像素的变化」**。

这个过程里不可约的量只有一个：

> **Δ ＝ 本次数据变化中，落在「当前视界」内、且真正改变了呈现的那一部分。**

「当前视界」在本系统里有确定的定义，不是修辞：`location.hash` 决定哪张视图（`app.js:2823` 的 `ROUTES` 表），`localStorage['studio-proj']` 决定哪个项目（`app.js:101-105` 的 `curProj/projActive`）。两者合成一个可枚举的视界坐标。

一切别的东西——库里有多少张单、别的项目落了什么盘、上一次整页重建是几秒前——都是**实现细节**，不是这件事的物理内容。任何与 Δ 无关而与它们有关的开销，定义上就是浪费。

### 1.2 为何非有不可

监制台是**常驻不刷新**的桌面页：制作人打开它就一直开着，而数据由后台执行器、审检链、项管持续改写。没有自动刷新，屏幕上就是一张过期照片，而这张照片正是制作人做放行/验收决策的依据——**看着旧数据拍板**比看不见更坏。

所以自动刷新不是「体验优化」，是这块面板成立的前提。它不可裁撤，只能**收敛代价**。

### 1.3 谁是唯一所有者

| 事实 | 唯一所有者 | 锚点 |
|---|---|---|
| 「当前视界是什么」 | **前端**（hash + 项目选择） | `app.js:2823`、`app.js:101-105`、`app.js:4193-4203` `pulseTarget` |
| 「数据变了什么」 | **服务端**（状态目录即状态机） | `lib/core/store.js:10-15` `STATES`、`store.js:78-86` `list` |

两个所有者之间今天只有**一根一比特的电线**：`/api/pulse` 返回的那个全局令牌（`server.js:1876-1881`）——它只能表达"变了 / 没变"。

**这是全部病根的第一性来源**：一比特搬不动 Δ 的形状。接收端拿到"变了"之后，唯一安全的假设就是 **Δ ＝ 全部**，于是把整张视图重算一遍。施工令-048 治的是"重算之后怎么落地"（把 `innerHTML` 覆写换成 `morph` 逐节点对齐，`app.js:4143-4151` 那段注释是它的自述），**它没有、也不可能治"要不要重算"**——因为决定这件事的信息量在电线的那一头就已经被压成一比特了。

### 1.4 由此推出的四条不可约约束

- **约束甲（代价随 Δ，不随 n）**：一拍刷新的代价必须由 |Δ| 决定。今天由 n（库存单数）决定——`/api/pulse` 每次请求 stat 全库每一个文件（`server.js:1879`），`/api/board` 每次请求解析全库每一张单（`server.js:265` → `store.js:89-92` → `store.js:50-54`），视图函数每次重拼全部卡片（`app.js:538-541`）。
- **约束乙（Δ 的形状必须传，不许猜）**：产生方知道 Δ 的形状，消费方需要它。今天没传，消费方靠猜，而唯一安全的猜法是「全部」。
- **约束丙（三态是"没被碰过"的产物）**：滚动位/展开态/输入焦点之所以不丢，是因为承载它们的 DOM 节点**根本没被换过**（`回执-048.md` §零②的原话）。任何新增的快路径必须让「没被碰」更容易达成，绝不能引入一条"先拆后补"的路。
- **约束丁（换实现不换协议）**：`repaint`/`morph` 的对外行为一个字不改——三态不动、`data-live` 归自己的计时器、`data-morph-skip` 岛自管、CANVAS 不碰。新方案只许在它们**之前**加短路，不许改它们**之内**的语义。

## 二、目标

**一句话**：把「令牌变了 → 整张视图全价重算」这条唯一通路，拆成「谁变了 → 只重算受影响的那一块」，且在数据其实没变时**整拍零成本退出**；施工令-048 挣来的三态与三闸一条不还。

四条可判定的收敛目标（改后目标值一律写成数，验证法见 §六）：

| # | 目标 | 改后目标值 |
|---|---|---|
| G1 | 当前视界数据未变（含"别的项目落盘"）时，一拍的全部代价归零 | 视图渲染函数调用 **0** 次、fetch **0** 次、morph 触碰节点 **0** 个 |
| G2 | 视图数据未变但令牌变时（分片令牌尚未覆盖的残余情形），签名闸整拍短路 | 视图渲染 1 次、morph 触碰节点 **0** 个 |
| G3 | 数据真变时，触碰面收敛到变化面 | 看板新增/删除 1 张卡 ⇒ 触碰节点 ≤ **单卡节点数 + 2**（列头计数 + 段头计数两个文本节点）；未变卡片的节点身份逐个 `===` |
| G4 | morph 的序列化开销有上界，不再随树规模走 | 单拍 `outerHTML` 取值次数 ≤ **2 ×（顶层键块数 + 1）** |

**非目标**（明确划出去，防评审与实现越界）：不做虚拟滚动；不引入前端框架/虚拟 DOM 库；不改 `pulsePlan`/`pulseTarget` 的四动作语义；不改 30s 整页兜底与交互顺延两道闸；不动甘特岛内部（它已经是本方案要抄的成例）。

#### 病灶 1 · 全局令牌：一比特电线（病根）　【认 · 对应背景第 1 条上半】

- **锚点**：`apps/studio/server.js:1876-1881`
- **实测数字**：handler 共 **6 行**，读 `req.query` 的有 **0 处**（M1）；扫描面 **12 个状态目录**、每文件一次 `statSync`（M2）；轮询 **20 拍/分**（M3）。即：单客户端每分钟触发 **20 × N** 次 `statSync`（N ＝ 全库单数），且这 20 拍与"当前开着哪张视图、身处哪个项目"**零相关**。
- **病理**：令牌的粒度是"整库"，消费方的粒度是"当前视界的一个子集"；粒度不匹配的部分，全部由消费方以全价买单。
- **改法**：令牌**分片**。`/api/pulse` 收 `?项目=&视图=`，返回 `{ token, 片: { 工单, 排期, 闸, 知识 } }`；不带参数时返回**与今天逐字节一致**的形状（不变量 I15）。分片键的归属表写死在服务端一处（`lib/core/store.js` 旁新增 `lib/core/pulse-shard.js`），前端只比自己视界对应的那几片。归属拿不准的变更一律折进全局片（不变量 I14）。
- **判它好了的数字**：探针"只令牌变"输入下——当前视界分片令牌**不变** ⇒ `repaint` 调用 **0** 次、fetch **0** 次、morph 触碰 **0** 个（改前：表B ①③ 两格，非零）。

#### 病灶 2 · `repaint` 的 patch 路径整段重跑视图渲染函数　【认 · 对应背景第 1 条下半】

- **锚点**：`apps/studio/public/app.js:4262-4288`（`repaint`），落点 `app.js:4281` `morph(box, await ROUTES[tg.视图]())`；项管页 `app.js:3665-3854`（`viewRelay`），看板 `app.js:526-610`（`viewBoard`）
- **实测数字**：`viewRelay` 一拍 **13 口 API 并发全取**、返回模板**光源码就 3824 B**（M4/M9，且这 3824 B 里一个数据字符都还没填，`欠账区Html`/`ideaPoolHtml`/`项管行为Html` 三个列表函数的展开全在其外）；`viewBoard` 一拍 **2 口** + 每张卡 **448 B 模板**重拼（M5/M8）。代价与"变了什么"无关，只与 n 有关。
- **病理**：`repaint` 把"局部刷新"实现成了"整张视图重算 + 逐节点对齐落地"——**只优化了落地，没优化重算**。施工令-048 治的是"闪"（落地面），本条是"算"（重算面）。
- **改法**：在 `repaint` 里、渲染函数**之前**插一道分片判定：本拍变更片 ∩ 本视图关心的片 = ∅ ⇒ 直接 `return 'skip'` 并记日志（`app.js:4257-4261` 的 `记刷新` 已现成，加一个 `skip-片` 动作名，`window.__pulse日志` 里可查）。视图 → 关心片的映射表与 `ROUTES` 同处声明，防两表走散（同 `pulseTarget` 靠调用方传 `Object.keys(ROUTES)` 的成例，`app.js:4266`）。
- **判它好了的数字**：探针"只令牌变"输入下，**视图渲染函数调用次数 = 0**；"数据真变"输入下 = **1**（不许因为加了闸就变成 2）。

#### 病灶 3 · 缺视图级签名闸　【认 · 对应背景第 2 条】

- **锚点**：`apps/studio/public/app.js:4211-4225`（`morph` 全函数，14 行）；反例成例在 `app.js:568-578`（`fillBar`），其中 `app.js:571-572` 的 `gb.dataset.k !== key` 才画
- **实测数字**：全仓前端 `dataset.k` 式签名比对**命中 1 处**（M6），且这唯一一处在闸门条上，**主刷新路径 0 处**。`morph` 入口 14 行里没有一行做"本次 HTML 与上次是否逐字节相同"的判断。
- **病理**：同一招（存 key、变了才画）在 `fillBar` 上用了三年，从没上到主路径。于是"令牌变而当前视图数据没变"这一整类拍——本方案预期是绝大多数拍——仍付全价 morph。
- **改法**：`morph(dst, html)` 开头加三行签名闸：
  ```
  const 签 = 签名(html);                       // 见下方口径
  if (dst.dataset && dst.dataset.msig === 签) return;   // 整拍零触碰
  ...原逻辑...
  dst.dataset.msig = 签;                        // 收尾落签
  ```
  **签名口径（不变量 I13）**：签名必须是 HTML 串的全量函数。第一版直接用 `html.length + ':' + 廉价散列(html)`（散列碰撞概率可忽略，但为杜绝"数据变了签名没变"这类静默事故，实现单需在散列相等时**再做一次串比对**才短路——串比对本身是 O(len) 的 `===`，比 morph 的 O(n·d) 便宜一个量级）。
  **为什么闸开在 `morph` 而不是 `repaint`**：`repaint` 那一层已由病灶 2 的分片闸挡住大头；`morph` 这一层是**兜底**——分片令牌漏网、或某片确实变了但恰好不影响本视图呈现（如别的字段变化）时，这道闸是最后一关。两道闸职责不重叠：一道省"取数+重算"，一道省"落地"。
- **判它好了的数字**：同数据两拍 ⇒ **签名相等 ⇒ morph 触碰节点数 = 0**（改前：表B ③ 的两个"只令牌变"格）。

#### 病灶 4 · `morphNode` 的序列化开销：命中省钱，未命中加倍付　【认 · 对应背景第 3 条，并补一处工单未提的量纲】

- **锚点**：`apps/studio/public/app.js:4235-4248`（`morphNode`，14 行），核心在 `app.js:4241`
- **实测数字**：`grep -n outerHTML public/app.js` 全仓 **3 处**，morph 比对占 **1 处**；每次 `morphNode` 元素比较触发 **2 次**全子树序列化（`o.outerHTML` 与 `w.outerHTML` 各一次，M7）。未命中则 `morphKids`（`app.js:4226-4234`）逐子递归，每层再各 2 次。深度 d、节点 n 的树，根级不命中的最坏总代价 **O(n·d)**。
- **病理**：`o.outerHTML === w.outerHTML` 这一行是 morph 的**全部价值**（`回执-048.md` §零② 原话），但它同时是 morph 的**全部成本**——命中时省下整棵子树的比对，未命中时白付两次序列化再往下走。且新侧 `w` 刚从字符串 `parse` 出来（`app.js:4216-4218`），又被序列化回字符串，是一次纯粹的往返浪费。
- **补一处量纲（工单未提，但决定改法）**：这个开销是**自相似**的——顶层不命中时，代价不是"多花一次"，而是沿着不命中的那条路径**每一层都多花一次**。所以正确的治法不是"让序列化更快"，而是**让不命中的层数变少**：把长列表交给"键 → 节点 Map + 行签名"（病灶 5），morph 只在无键的散块上走，散块的深度是常数级。
- **改法**：不改 `morphNode` 本体（协议不变，约束丁）。三道减负：① 病灶 3 的签名闸把"整页没变"的拍整个挡在 morph 之外；② 病灶 5 的通用增量件接管长列表，morph 见 `data-keyed` 容器即整枝让路（复用 `data-morph-skip` 的成例语义，但用**新属性名**，不与甘特岛混用）；③ 新侧 `w` 的序列化可直接复用增量件持有的原始 HTML 串（生成时就有，不必回读 DOM）——这一条是纯收益，无行为变化。
- **判它好了的数字**：单拍 `outerHTML` 取值次数 ≤ **2 ×（顶层键块数 + 1）**（探针已内置该计数器，见附录 A `序列化` 变量）。

#### 病灶 5 · 增量重绘的成例只活在甘特岛里，没上提为通用件　【认 · 对应背景第 4 条】

- **锚点**：`apps/studio/public/gantt.js:733-758`（`画行`），签名短路在 `gantt.js:747-748`，摘除在 `gantt.js:755`；岛与宿主的边界自述在 `gantt.js:3-6`；宿主侧让路闸在 `app.js:4239`
- **实测数字**：岛内**行不变 ⇒ 触碰 0 个节点**（`gantt.js:748` 命中即 `continue`，只改 `style.top` 一个内联样式）；这套形制已由 `test/gantt-p0.test.js`/`gantt-p1.test.js`/`gantt-p2.test.js`/`gantt-viewpack.test.js` 四套件覆盖（`ls test/gantt-*.test.js`）。同期，宿主侧同类长列表（看板列 `app.js:530-543`、结束段 `app.js:562-567`、项管页欠账区 `app.js:3838`／想法池 `app.js:3845-3850`／项管行为区 `app.js:3851`）**0 处**用这套形制。
- **病理**：同一个仓里，一套已实战、已上测的增量形制被关在一个岛里；壳这一侧的列表照旧全量重拼。这不是"还没想到"，是"没上提"。
- **改法**：抽 `apps/studio/public/incremental.js`（新，纯函数 + 小状态，无框架依赖），对外一个入口：
  ```
  keyedList(容器, 项们, { 键: it => string, 签: it => string, 造: it => HTMLElement })
  ```
  实现照抄 `gantt.js:741-755` 的四步：`留` 集合 → 逐项比 `旧.签 === 新签` 命中即跳过 → 未命中 `replaceWith`/`appendChild` → 收尾摘除不在留集的键。容器打 `data-keyed`，`morph` 见之整枝让路（病灶 4 改法②）。焦点保全照 `gantt.js:760-771` 的 `记焦点/还焦点` 成例。
  **首批接入面**（按收益排序）：看板列的卡片（`app.js:538-541`）→ 项管页欠账区与想法池 → 结束段计数行。
- **判它好了的数字**：看板"数据真变"输入下（新增 1 张 TK 单），**morph 触碰节点数 ≤ 单卡节点数 + 2**，且未变卡片的节点身份逐个 `===`（改前：表B 看板"数据真变"格）。

#### 病灶 6 · 服务端每拍全库读盘 + 全库 YAML 解析　【新增 · 工单背景未列】

- **锚点**：`apps/studio/server.js:263-265`（`/api/board` → `store.snapshot`）→ `apps/studio/lib/core/store.js:89-92`（`snapshot` → `list`）→ `store.js:78-86`（`list` 逐文件 `parse`）→ `store.js:50-54`（`parse` = `readFileSync` + `gray-matter`）
- **实测数字**：一次 `/api/board` = **N 次 `readFileSync` + N 次 `gray-matter` 解析**（M10）。而 `/api/board` 被**两个视图都吃**：看板经 `loadBoard`（`app.js:131-132`），项管页在 13 口里也带着它（`app.js:3693`）。叠加 M3 的 20 拍/分：单客户端每分钟 **20N** 次读盘 + **20N** 次 YAML 解析，另加 `/api/pulse` 的 **20N** 次 `statSync`。
- **病理**：前端就算全治好了，服务端这一侧仍在按 n 收费。而且 `/api/pulse` 每 3s 已经把全库 mtime 扫了一遍——**这份扫描结果被扔掉了**，紧接着 `/api/board` 又把同一批文件从头读一遍。
- **改法**：`lib/core/store.js` 加一层 mtime 缓存：`parse` 的结果按 `文件路径 → { mtimeMs, fm, body }` 缓存，`list` 先 `statSync` 比 mtime，命中即复用（`statSync` 本来就要做——`/api/pulse` 的分片令牌顺带产出这张表，两处共用一次扫描）。缓存是**进程内、只读向**的：任何写路径（`store.move`/`store.update`/`create`）落盘后即失效对应键。
  **为什么放心做**：`store.js:1-2` 已明定"目录即状态机、明文即事实源"，mtime 是这套语义的天然版本号；且写路径全都收敛在 `move()` 一处（`store.js:36-40` 的移动钩子自述："所有目录迁移的唯一中心是 move()"），失效点唯一。
- **判它好了的数字**：同数据两拍 ⇒ 第二拍的 **`gray-matter` 解析次数 = 0**（探针在 `store.parse` 上挂计数器即可测）。

#### 病灶 7 · 项管页 13 口并发是"视图级"而非"变更级"　【认 · 背景第 1 条的落地面】

- **锚点**：`apps/studio/public/app.js:3668-3694`（13 口 `Promise.all`）
- **实测数字**：**13 口**并发（M4）；20 拍/分 ⇒ 令牌逐拍皆变时，单页每分钟最多 **260 次 HTTP**。这 13 口的数据源分属四类互不相干的账：工单目录（`/api/board`、`/api/relay`、`/api/pm/*`）、排期台账（`/api/schedule`）、闸与债（`/api/gates`、`/api/attn`）、结构实体（`/api/pipelines`、`/api/features`、`/api/specials`、`/api/ideas`）。
- **旁证（这一条已经在仓里被承认过一次）**：`app.js:3807-3808` 的注释原文——"3s 脉冲令牌只按工单目录 mtime 算，登记/重排一条待办一个字节都不会动到工单目录——不自己看着账，这页会一直停在打开那一刻的读数"。于是项管页**自己另挂了一条 30s 轮询 + 自算签名**（`app.js:3807-3817`，共 11 行，`ssig` 在 `3809` 逐粒折 `粒ID|状态|版本号`）来补令牌看不见的那一片。**同一页上，令牌既太宽（别家项目的单也触发全取）又太窄（本页关心的排期账它看不见）**——这正是"一比特电线"的两面。
- **病理**：13 口捆在一起，任何一片变化都触发全部 13 口重取，同时另有一片变化 13 口全都察觉不到。
- **改法**：13 口按上述四类分组，各组挂到病灶 1 的对应令牌分片上；`repaint` 只重取变了的那一组，其余组复用上一拍结果（结果缓存与分片令牌同期失效）。**副产品**：`app.js:3807-3817` 那条自建的 30s 补丁轮询可以退役（−11 行）——排期账进了分片令牌，它就不再是"令牌看不见的一片"。
- **判它好了的数字**："只令牌变"输入下 fetch = **0**；"数据真变（工单落盘）"输入下 fetch ≤ **4**（只重取工单片相关的口：`/api/board`、`/api/relay`、`/api/pm/ledger`、`/api/pm/chains`），改前 **13**（M4）。

### 5.3 职责归哪一层（三个边界问题的明确答案）

**问一：签名算在哪一层？**
答：**算在 `morph` 这一层，不算在视图函数里**。理由：视图函数有十几个，每个都自己算签名 = 十几处口径，必然走散（同 `pulseTarget` 靠调用方传 `ROUTES` 键、不自己抄一份表的道理，`app.js:4190-4191` 有自述）。`morph` 是唯一收口处，签名取自它已经拿到的 `html` 串，天然全量、天然一份。

**问二：分片令牌的归属表放前端还是后端？**
答：**后端一处**（`lib/core/pulse-shard.js`）。理由：它是"数据变了什么"的所有者（§1.3）；放前端就是让消费方去推断产生方的事实，正是今天这一整套病的形状。前端只做一件事：把自己的视界坐标（hash + 项目）翻译成"我关心哪几片"，这张表放前端（它是视界的所有者）。**两张表，各归各家，不许对方抄一份**。

**问三：`keyedList` 与 `morph` 谁先谁后？**
答：**`morph` 先，`keyedList` 后**。视图函数照旧吐一整串 HTML（包括 `data-keyed` 容器的**空壳**），`morph` 把壳对齐好、见 `data-keyed` 整枝让路，随后（同步收尾，照 `app.js:3759-3761` 用 `setTimeout` 不用 `rAF` 的成例）由视图函数注册的 `keyedList` 调用填内容。这与甘特岛今天的接线**完全同构**——壳归 morph、内容归岛（`gantt.js:3-6`），只是把"岛"泛化成"任意键控列表"。
