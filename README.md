# 监制台（Producer Console）· apps/studio

**把游戏生产流程交给 AI agent 流水线的驾驶舱。**
你只负责三件事——**拍板放行、争议裁决、品味终审**；拆单、派发、执行、质检、
委托核验、失败兜底、收口、记账、通知，全部自动。

[English](README.en.md) · [安装指南](套件/SETUP.md) · [设计与协议](docs/设计与协议.md)

```
你（制作人）          监制台（本工具）                     执行者（codex / claude / 兼容厂商 无头进程）
   想法 → 拍板 ─────▶  专项父单（人闸：边界 + 验收标准）
                        │
                        ├─▶ 项目管理 agent 自动拆单元工单 ──▶ 拆单简报呈审
   审批放行  ─────────▶  派发引擎（依赖就绪 + 槽位 + 额度闸）
                        │ 每 15s 一轮，确定性调度归代码
                        ├──▶ 派发即拉起专属执行者，完工即销毁 ──▶ 按岗位协议执行，写回执
                        ├──▶ QA 只读复核（通过 / 自修 / 三振上呈）
                        ├──▶ 委托单自动代核；不过则预生成返工草稿待审
                        ├──▶ 子单全完成 → 项管出收口报告 → 父单自动转待验收
   品味终审  ◀────────  决策台（一个专项只签一次）
                        └──▶ 失败单进独立分诊通道，绝不悬空
```

## ⚠️ 使用前必读（安全披露）

1. **实弹模式下 agent 对你注册的项目仓库有完全写权限**：执行器以
   `codex exec --dangerously-bypass-approvals-and-sandbox` / `claude -p --permission-mode acceptEdits`
   启动无头 CLI 并把工作目录指向你的项目仓库。请只注册你愿意让 agent 写入的仓库，
   并保持仓库有 git 历史可回滚。执行器**运行即实弹**（H81 常开单闸制），停手闸是启动页的「单闸」——
   合闸即全链停派发，页面顶部挂常驻红条。
2. **本工具会读写你的 CLI 凭据文件**：为显示订阅额度，会读取
   `~/.claude/.credentials.json` 并在 token 过期时自动续期（与官方 CLI 同一 OAuth 流程，
   续期结果写回该文件）；会读取 `~/.codex/config.toml` 获取模型配置。凭据永不上传、不离开本机。
3. **自动记账**：若安装目录在 git 仓库内，工单流转记录每 10 分钟自动 `git commit`
   （只 commit 不 push，可在配置关闭）。
4. 想暂停一切派发：启动页「单闸」点「停」——已在跑的单跑完为止，不再派新单。

## 快速开始

1. 从 [Releases](../../releases) 下载 `监制台-套件-vX.Y.Z.zip` 并解压
2. 双击 **部署.bat**：选安装目录 →（可选）注册第一个项目仓库 → 自动启动
3. **验收标准只有一条：总览右上角「环境」显示 就绪**（背后是四组全链路自检，
   降级/阻断时逐项写明修复动作）

前置要求（详见 [SETUP.md](套件/SETUP.md)）：Windows 10/11、codex CLI、
claude CLI（Claude Code）已登录、代理（如你的网络需要，自动解析注入）。

### 原始事件流存档

`事件流存档.根路径` 默认为工作区下的 `事件流存档/`；每次 stream-json 会话逐行原样写入
`<根>/<单号>/<runId>.jsonl`，没有单号时写入 `_unassigned/`。`事件流存档.开` 默认 `true`；关掉时不建目录、不写文件、不清理。

`事件流存档.保留天数` 默认 `30`，`事件流存档.总体积上限字节` 默认 `1073741824`（1 GiB）。执行器启动和每次归档收尾各清理一次：任一闸超限即按 mtime 从旧到新删除完整 `.jsonl`，并回收空单号目录；正在写入的 run 始终排除。

## 目录结构（安装后）

```
AI工作室/
  监制台 X.Y.Z.exe     ← 主程序（绿色，双击即用）
  studio.config.json   ← 全部配置（明文 JSON）
  草稿/ 待投/ 在途/ 质检/ 待验收/ 待定夺/ 执行失败/ 完成/ 已归档/
                       ← 目录即状态机：工单 = 状态文件夹里的 .md
  管线/                ← 域的常青树（P-1.md…），独立实体不入九态
  回执/                ← 每单的完工报告
  岗位协议/            ← 各职能 agent 章程（md 明文，改了下一单生效）
  项管台账/            ← 项目管理的就绪队列 / 成本归集 / 收口报告
  呼叫/                ← 需制作人层介入事件的结构化信箱（inbox.jsonl）
  journal/             ← 只追加的操作流水
```

## 核心概念

- **目录即状态机**：工单状态 = 所在文件夹，改状态 = 原子改名；明文 .md 是唯一事实源
- **派发制**：工单派发即拉起专属执行者，完工即销毁——一人一单一生命周期；确定性调度（依赖/槽位/闸门）归代码，判断性调度（拆单/分诊/排期）归项目管理 agent
- **三层结构**：管线（域的常青树，如「地图系统」）→ 专项（一次拍板圈定的有界目标）→ 单元工单（单写区 + 一个可核验产出）
- **人闸三点**：拍板（定边界与验收标准）· 放行（审拆单简报）· 终审（品味签字，一个专项只签一次）
- **双闸**：暂停闸门（手动）+ 额度锁（用量超阈自动冻结派发）；另有沟通护城河保留额度，保证人机对话永不被生产挤占
- **模型分级**：便宜模型干体力（执行），贵模型当裁判（QA 复核 / 委托代核 / 项目管理）
- **异厂对抗互审**：执行与核验可分属不同厂商模型（Anthropic 兼容端点即插即用），失效模式互不重叠，互为对方的审查者
- **执行失败态**：CLI 崩溃/超时的单进独立分诊通道（重投/上呈/废弃），绝不悬空
- **设计事实源 Wiki**：[[双链]] 组网的设计词条 + 关系图；agent 产出先落待审区，入册权在制作人
- **编辑器占用感知**：制作人打开引擎编辑器时自动挂起该项目派发，关闭即恢复

完整协议见 [docs/设计与协议.md](docs/设计与协议.md)。

## 已知限制

- 仅 Windows（依赖 Windows 路径/进程语义；exe 为 win-x64 便携版）
- 订阅额度端点有账号级限流：读数按 ≥5 分钟纪律刷新并标注时间戳，偶有陈旧属正常
- 无自动更新：新版本重跑 部署.bat 覆盖 exe 即可（配置与工单不受影响）
- 美术职能暂无图像生成接入（产出规格文档+占位资产）

## 卸载

删除安装目录即卸载（所有数据都在里面）。本工具不写注册表、不装服务。
