# propcheck — 传播核查（H78 八站的机判版）

## 它治什么病

**改了正本忘了副本**。这一族已复发三次：

- fable 文案三次不死案（正本改了，skill-templates / 项目副本里的旧文案照跑）
- billFee 两次失联案（同一个名字在两处各活各的）
- H100 打点退役，漏改 `packages/skill-templates` 与 TK 副本

H78「八站传播」把动作规范化了，但验证仍靠人肉 grep——**漏站与漏 grep 是同一种失误**。
本包把口头判据（「我改完了」）换成机器结论：给一个关键词，遍历八站，报「全库零活体命中」与否。

## 用法

```
node packages/propcheck/propcheck.js <关键词> [关键词2 ...] [选项]
```

| 选项 | 作用 |
|---|---|
| `--要求 零命中` | 任何一站还有活体命中 → 退出码 1（**退役类**改动的判据） |
| `--要求 全站命中` | 任何一个存在的站零命中 → 退出码 1（**新增类**改动的判据） |
| `--json` | 机器可读输出（含 `判据结论`） |
| `--明细 N` | 每站最多列 N 条命中（默认 8，0=只报计数） |
| `--只站 名` | 只扫站名含该子串的站 |
| `--站 名=路径` | 追加一个位置到某站（排查/测试用） |
| `--宽` | 不做退役标注过滤，所有命中都算活体 |
| `--含史料` | 零命中判据把史料站也算进去（默认豁免，见下） |
| `--含代码` | 取消代码站的注释豁免：注释里的旧词也算活体（原始面貌视图） |
| `--台账根 路径` | 记账落点的根（默认 `<协议仓>/监制台`），见「记账」 |
| `--不记账` | 只核查不留痕（排查态用；常规跑一律记） |

退出码：`0` 判据满足（或未给判据）、`1` 判据不满足、`2` 用法错误。

例：确认某条已退役的措辞真的全库死透——

```
node packages/propcheck/propcheck.js 拉取制 --要求 零命中
```

例：确认新决议号誊到了每一站——

```
node packages/propcheck/propcheck.js H104 --要求 全站命中
```

## 「活体命中」口径

命中行若带**退役标注**（删除线 `~~…~~`、已退役／已废止／已作废／已删除／已迁移）视为「留痕不是留活」，不计活体。

这张标记表**故意窄**：宁可多报一条让人再看一眼，不可把一条还在生效的旧文案判成「已经退役了」。
要扩它之前先问一句：这条命中要不要人动手改？要 → 不许进这张表。

### 两类豁免（都是为了不让判据变成「永远红」，但口径不同）

| 类 | 范围 | 理由 | 开关 |
|---|---|---|---|
| 史料站 | **整站**（1 决议史、7 跨会话记忆、8b 班次归档） | 历史记载里必然留着旧词，那是史实不是漂移。决议史里「H49 宣布拉取制退役」那句话本身就含旧词 | `--含史料` |
| 代码站 | **只豁免落在注释里的命中**（4 提示词接线、6 机制代码/config） | 保留回退分支的注释本就该提旧制度名（「拉取制这条路同样得堵」） | `--含代码` |

代码站原先是**整站**豁免，2026-08-22 体检 #44 收窄。案由：整站放行时
`public/app.js:104`（顶栏 tagline）与 `:884`（抽屉提示）里两条**真在跑的界面文案**
一起拿到了通行证——整站豁免不是豁免，是关掉判据。
收窄后实测：`拉取制` 在代码站的 11 条命中全落注释、归零（正当豁免一条不误伤），
`决策台` 残 2 条，正好是上面那两条真文案。

注释判定按 JS 家族（`.js/.mjs/.cjs`）逐行算掩码，**块注释状态跨行**——
`app.js:1123`、`:1146` 是 `/* … */` 的续行、行首没有任何标记，只看单行的写法会把它们误判成活文案；
字符串状态也跟着算，`'http://x/拉取制'` 里的 `//` 不是注释。
`.json/.md` 没有注释语法，那里的命中一律算活体。
判错的方向定死：**宁可把注释当活体多报一条让人再看一眼，不可把活文案判成注释。**

### 谁在调它

- `protocol-sync` skill（H78 八站传播）的收口动作：八站誊录完跑一遍 `--要求 零命中` / `--要求 全站命中`，退出码即结论；
- `apps/studio/test/propcheck.test.js` 里的活体判据：`拉取制` 现役站零活体命中、`决策台` 活体命中不出已知欠账清单。

## 记账（每次运行留一行流水）

**2026-08-22 体检 #55 前置件二**。本包原样零写文件动作——跑完即散，
于是「这道核查上次是什么时候跑的」全库无人知道。现在每次 `main()` 走完都往

```
<台账根>/瞭望塔/传播核查.jsonl        # 台账根默认 = <协议仓>/监制台
```

追一行 JSON Lines：

```json
{"时间":"2026-08-22T09:41:03.771Z","关键词":["拉取制"],"判据":"现役站零活体命中（史料站豁免；代码站只豁免注释里的命中）","通过":true}
```

三条口径：

1. **一行一次运行**。要挂的那道「传播核查断更」闸**只读最后一行**即可判断断更，
   绝不许把全语料扫描压进值守 tick。
2. **根可注入**（`opts.台账根` / `--台账根` / 环境变量 `PROPCHECK_台账根`）。
   测试一律写临时目录，绝不碰生产工作区。
3. **写不进不许炸**。核查是本职，记账是副产品：目录只读/盘满时如实回 `记:false`，
   判据结论与退出码一个字都不受影响——否则一次记账故障能把整条传播流水线打停。

判据红的那一次**照样记**：「上次跑是什么时候」与「上次跑过没过」是两件事，断更闸问的是前者。

> 挂闸的前提正是这行写口。**判据读一个没人写的文件 = 恒空假账**，
> 那正是 G13/G14 无人消费的成因；写口没落地之前不许注册那条闸。

## 站表从哪来

站名与 `protocol-sync` skill（H78）那张八站表逐条对应。协议仓位置按 `AI_GAMESTUDIO_ROOT` 环境变量 >
仓根同级 `AI-GameStudio` 的顺序找；项目侧 `.claude/skills` 扫仓根同级各目录。
**位置不存在的站会如实报「不存在」，不静默当成零命中**——否则一个路径写错就能伪造出一张满分答卷。
