# @ticketflow/review-panel · 异厂评审台

多厂模型**红队评审**（施工令-013 立项 · H88 配套；019 红队立场卷制 · H91 配套）：把一份技术方案 md 同时喂给多家厂商独立评审，产出意见合集 md + 一行 JSON 摘要。

## 用法

```
node review.js --file <方案md绝对路径> [--out <意见合集md路径>]
               [--config <studio.config.json>] [--timeout-min N] [--only 厂1,厂2] [--dry]
```

- **评审团自动发现**：codex 一席（`codex exec`，提示词走 stdin）+ config `执行池` 里每个带 `兼容` 段的条目一席（Anthropic 兼容 `/v1/messages` 直调）。新厂进 config 即自动入席，本文件零改动。
- **红队立场卷制**：三卷（可行性红队/不变量红队/成本红队）按席序轮换派发；单厂独领三卷，两厂甲领一三乙领二。行**击杀制**——每卷必须尝试构造具体失败场景，构造不出须明写「未能构造击杀」（该声明即通过证据）。
- **缺席如实记录**：单厂超时/失败只记缺席不拖垮全场；缺席致落空的立场卷在合集里标出。
- **密钥纪律**：key 只活在请求头一行；stdout/合集/错误栈全过 `scrub()`（已知密钥逐一抹除 + sk-*/Bearer/x-api-key 形状兜底）。

## 密钥从哪来（施工令-030）

兼容池的 key 按**三级**取值，逐级回落，取到即停：

| 级 | 来源 | 说明 |
|---|---|---|
| ① | **DPAPI 托管** | `<config 同目录>/凭据.json`，经 `apps/studio/lib/creds.js` 解密。托管库与 config 同工作区，`--config` 指临时副本时托管口跟着走，演练不会摸到生产托管库 |
| ② | config 明文 | `执行池.<池>.兼容.key`。施工令-029 迁移后现网这一格是空串，保留作回退兜底 |
| ③ | 环境变量 | `REVIEW_KEY_<池名大写>`（非字母数字转 `_`，如 `REVIEW_KEY_DEEPSEEK`） |

端点字段（`base`/`模型`）**独立兜底**：托管只存了 key 时，base 回落 config——base 缺省等于走 Anthropic 官方端点，那会把第三方 key 发给错误的收件人（必 401）。

`--dry` 的 `席位[].凭据` 列如实报出每席实际走了哪一级（`托管`/`config`/`环境变量`）——「在席」与「key 从哪来」是两件事，只报前者的话，托管挂了悄悄回落明文也看不出来。

**本包是公共包，不假设 `apps/studio` 在场。** creds 模块「找得到就用、找不到就算了」，加载失败 / DPAPI 不可用 / 非 Windows 一律静默回落下一级，绝不硬崩——评审台的价值是「能开评」，不是「必须有托管」。三级全空的池不入席（不猜、不报错），其余席位照常开评。

### `REVIEW_CREDS_MODULE`（可选）

指向一个自定义凭据模块的路径，**覆盖**内置的 creds 查找（设了就只认它，不再回落内置路径）。模块需导出 `has(root, 池)` / `getKey(root, 池)`，可选 `meta(root, 池)` 返回 `{ base, 模型 }`。

两个用途：

1. **协作者自带托管实现** —— 不用 Windows DPAPI 的机器可以接自家的凭据后端；
2. **测试假夹具** —— `test.js` 的凭据三态用例靠它替掉真 DPAPI，做到零真调、零 PowerShell、非 Windows 也能跑。

安全边界（2026-08-09 总监裁定保留现状）：**必须显式设置才生效**，默认不存在；它只改变「从哪读本机已有的 key」，不能凭空造出凭据、不能把 key 送出本机；读出来的 key 与其它来源一视同仁地进 `scrub()` 净化表；来源在 `--dry` 名册里透明可见。属本机信任边界内的注入口——但也正因如此，**不要在共享/多租户环境里把它指向不受信任的路径**。

## 测试

```
npm test   # 离线自测：只走 --dry 与参数校验路径，零网络、零厂商调用、零 token
```

覆盖：评审团发现（兼容池自动入席/缺 key 不入席）、立场卷派发三种席数、`--only` 过滤、argv 契约与退出码、dry 输出不泄密钥、**凭据三态**（托管命中/config 兜底/双缺失 + 端点字段级兜底 + 环境变量兜底 + 托管模块不在场不硬崩 + 托管 key 同样净化）。真实评审（花 token）不进测试，由方案单/调研单执行会话按 H88/H90 调用。
