# @ticketflow/review-panel · 异厂评审台

多厂模型**红队评审**（施工令-013 立项 · H88 配套；019 红队立场卷制 · H91 配套）：把一份技术方案 md 同时喂给多家厂商独立评审，产出意见合集 md + 一行 JSON 摘要。

## 用法

```
node review.js --file <方案md绝对路径> [--out <意见合集md路径>]
               [--config <studio.config.json>] [--timeout-min N] [--only 厂1,厂2] [--dry]
```

- **评审团自动发现**：codex 一席（`codex exec`，提示词走 stdin）+ config `执行池` 里每个带 `兼容` 段的条目一席（Anthropic 兼容 `/v1/messages` 直调）。新厂进 config 即自动入席，本文件零改动。
- **红队立场卷制**：三卷（可行性红队/不变量红队/成本红队）按席序轮换派发；单厂独领三卷，两厂甲领一三乙领二。行**击杀制**——每卷必须尝试构造具体失败场景，构造不出须明写「未能构造击杀」（该声明即通过证据）。
- **缺席如实记录**：单厂超时/失败只记缺席不拖垮全场；缺席致落空的立场卷在合集里标出。
- **密钥纪律**：key 只活在请求头一行；stdout/合集/错误栈全过 `scrub()`（已知密钥逐一抹除 + sk-*/Bearer/x-api-key 形状兜底）。

## 测试

```
npm test   # 离线自测：只走 --dry 与参数校验路径，零网络、零厂商调用、零 token
```

覆盖：评审团发现（兼容池自动入席/缺 key 不入席）、立场卷派发三种席数、`--only` 过滤、argv 契约与退出码、dry 输出不泄密钥。真实评审（花 token）不进测试，由方案单/调研单执行会话按 H88/H90 调用。

## 迁移与兼容
