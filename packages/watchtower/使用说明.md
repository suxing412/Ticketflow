# watchtower · 消费方使用说明

> 面向把瞭望塔接进自己工作流的人。案源：robinwang2 2026-08-09《求公用件使用说明》——三处坑全部来自「行为只存在于代码里」。本文把会咬人的语义写成大字。机制细节见 `接线说明.md`（怎么接）与 `README.md`；本文回答「接上之后它到底怎么想事」。

## 一、五信源的触发判据与首轮语义（最容易漏信的地方）

| 信源 | 触发判据 | 首轮语义 |
|---|---|---|
| ①流水（journal） | 文件尾新增行匹配规则表 | **只报增量**：上岗时记住文件当前长度，之前的内容视为存量**不报**。带 `--from-start` 才从头扫 |
| ②信箱（inbox.jsonl） | 同上（尾随读） | 同上，`--from-start` 同样生效 |
| ③时钟 | 规则表定点（本地时区） | 无存量概念，到点即触发 |
| ④心跳（HTTP 探测） | 连续失败 ≥ 阈值（默认 2 次）报失联；恢复 200 报复通 | 上岗即开始探测 |
| ⑤远端（git 侦察） | `git fetch` 后 **ref 变化**（任意远端分支的新提交/新分支/删分支），**不是「main 变化」** | **首见某仓只建基线不报事件**——基线时刻之前推上远端的一切都算存量，**一声不吭**。⚠ 这是漏信重灾区：守护重装/游标删除后重启，重建基线期间到达的信全部静默 |

**大字规则**：**担心错过存量就带 `--from-start`（管①②）；远端信源无从头选项——重建基线前，先人工 `git fetch && git log` 核一遍待收信件。**

## 二、远端侦察到底比什么

- 比较对象：`for-each-ref` 快照 diff（上轮 vs 本轮），**ref 级**——分支推送即触发，与是否合入 main 无关；
- 推论：**push 分支即投递，合入 main 即归档**（信道 README 已按此口径修订）；
- 轮询周期：默认 **5 分钟**（`远端.间隔毫秒: 300000`，可配到 60000 下限自定）；fetch 失败静默暂歇、恢复即续（状态翻转各记一行守望流水）；
- 信道文书判定：触及 `docs/` 下 交接/回执/信道 类 md 即标「信道文书」；信箱分拣规则再按 `收-<本方名>/` 决定弹不弹；
- 中文文件名依赖 `-c core.quotepath=false`（已内置，重构勿删——有测试守着）。

## 三、心跳戳与「守护自身存活」的标准接法（结构性盲区）

- 守护每 **30 秒**覆盖写 `<出口>/心跳.txt`（一行 ISO 时刻）；
- **戳是守护自己写的——它死了就不写，而「不写」和「一切正常」在流水里长得一模一样。** 靠流水判断守护存活是循环论证；
- **标准接法（三选一，至少落一个）**：
  1. **反向监视**（robinwang2 方案，收编为推荐姿势）：任意常驻方定期读心跳戳算秒龄，>120s 即告警——监视者不能是守护自己；
  2. **UI 在岗灯**：消费方界面读心跳戳，45s 阈值判红。**在岗情况（2026-08-22 体检实测，规格不许再替消费方吹牛）**：交钥匙壳已内置（`apps/platform/server.js` 读 `watchtower-out/心跳.txt`，阈值走 `platform.config.json` 的 `watchtower.freshMs`）；**监制台待建**——全仓 grep `心跳.txt` 在 `apps/studio/` 下零命中，即塔死了监制台这一侧看不见（排程台账 Q队列序 21「值守自愈」，需协调补 `GET /api/watchtower` 与 G18 闸）；
  3. **计划任务兜底**：`--install` 注册开机自启，进程死了下次登录自动复活（不解决「死了没人喊」，只解决「死了能复活」）。
- 判活口径：`--status` 的 `心跳戳.在跳`（秒龄 ≤ 45）比 `在岗`（pid 存在）更真——pid 活着不等于主循环没卡死。
- **下岗留痕（2026-08-22 起）**：软退出（`--once` / SIGINT / SIGTERM / SIGBREAK / SIGHUP / 正常 `process.exit`）会往流水追一行
  `急 瞭望塔下岗 | pid … · 因 … · 部署区 …`。判据：`packages/watchtower/test.js` E7。
  **但它救不了硬杀**——Windows 注销、`taskkill /F`、断电时 `'exit'` 钩子不开火，流水里仍只有上岗没有下岗。
  故「上岗数 = 下岗数」不是存活判据，只是**软退出的可观测性**；判塔死仍以上面的心跳戳为准（这两条不是并列，心跳戳是主干）。

## 四、未读账本的水位语义

- 每条弹过通知/记未读的事件追加进 `未读账本.jsonl`，**永不自动删除**；
- 「已读」是一根**水位线**（时间戳）：`--ack <ISO|毫秒|all>` 把水位推到该时刻，之前的都算已读——**粒度是时间，不是逐条**，没有「只销第 3 条」的操作；
- `--ack all` 水位推到现在；无守护在岗时 ack 会顺手压实文件；
- 消费口径：读账本时按 `t > 水位` 过滤即未读。

## 五、破坏性改动的通知义务（协作规范）

公用件走路径消费、无 semver 锁。**改本包公开行为（上表任何一格）的 PR，描述里必须列消费方影响面，合并后信道知会**；消费方以契约测试自卫（只断言真用的——多断言等于把内部实现钉成契约）。
