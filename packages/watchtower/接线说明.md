# 瞭望塔接线说明（写给协作者的一页）

> 目标：你那边也起一座瞭望塔，会话不在场时照样有人盯梢、有信必达。
> 下面就是我们现网的同款接法（部署区 = 监制台工作区，Windows + node，零依赖单文件），不发明新机制。

## 一、装守护（登录自启）

1. 备一个「部署区」目录（即被盯的工作区根，内含 `journal/`、`呼叫/` 两个子目录；没有就建空的）。
2. 配置二选一：
   - 简单：以后每条命令都带 `--root <部署区>`；
   - 省事：把本目录 `瞭望塔.config.template.json` 拷成 `瞭望塔.config.json`（与 watchtower.js 同目录或运行目录），改 `部署区` 一项即可。
3. 规则表：把本目录 `规则.json` 拷到 `<部署区>/瞭望塔/规则.json`（守护热载，改完存盘即生效）。
4. 注册登录自启并当场拉起：

   ```
   node packages/watchtower/watchtower.js --install --root <部署区>
   schtasks /Run /TN 瞭望塔
   ```

   （`--install` 只登记计划任务不当场启动，所以补一句 `/Run`；卸载用 `--uninstall`。）
5. 验收三连：
   - `node watchtower.js --status --root <部署区>` → `在岗:true`，且 `心跳戳.在跳:true`（`<部署区>/瞭望塔/心跳.txt` 每 30s 覆盖写一行 ISO 时刻，断更即守护不在）；
   - `node watchtower.js --toast-test` → 桌面弹出测试通知（BurntToast→气泡→msg 三档回落）；
   - 看 `<部署区>/瞭望塔/瞭望塔流水.log` 有「瞭望塔上岗」行。

## 二、常驻会话挂监听（人不在，会话在）

开一个常驻 Claude Code 会话，把**统一流水**当唯一 tail 对象挂上 Monitor（或等价的后台 tail），示意：

```
Monitor: tail <部署区>/瞭望塔/瞭望塔流水.log —— 出现「急」级行即唤起处置
```

- 流水一行一事件带信源标（`[流水] [信箱] [时钟] [心跳] [远端]`），急/常分级已由规则表定好；
- 会话不在场的积压去 `未读账本.jsonl`：回来先 `--unread` 看账，处理完 `--ack all` 清账；
- 只挂这一个文件就够了——五路信源（journal 流水/信箱/时钟/心跳/远端 git 侦察）全部收口到它。

## 三、信箱收发约定

- **本地信箱**（自己人/本机流程投递）：往 `<部署区>/呼叫/inbox.jsonl` 追加一行 JSON：
  `{"t":"<ISO时刻>","级别":"急|常","类型":"三振上呈","摘要":"一句话","单号":"TK-xxx"}`
  ——`级别=急` 默认弹通知，其余按规则表分档。
- **跨方信件**（两座塔之间，走 git，不加任何新信道）：给对方的信写成 md，落**对方在盯的仓**里
  `docs/信道/收-<对方名>/` 下提交推送。路径带「信道」，对方塔的远端信源（`git fetch` 侦察）自然把它认成
  「信道文书」弹通知。
- 精细分拣（可选）：`规则.json` 里有两条停用的「信箱分拣-*」模板——把 `<本方名>` 换成你的收件匣名并去掉
  `"停用": true`，即得「收-我的 → 急+弹通知；收-别人的 → 只记流水」。配置项 `本方名` 见 config 模板。
- 守护对被盯仓**只 fetch 不 pull/merge**，工作区零改动；断网自动暂歇、恢复即续，不用管它。
