# AI 工作室（监制台）安装指南

一个把通用软件项目交给多 AI Agent 流水线的驾驶舱：你只负责三件事——**投池放行、待定夺拍板、保留单终审**；
起草辅助、领单、执行、质检、委托验收、失败兜底、记账、通知全部自动。

新安装默认角色为 Orchestrator、Backend、Frontend、Reviewer、Integrator。角色不绑定厂商，系统会在
已启用的 Codex、Claude、Kimi 等 Provider 中按能力、配置评分和近期评审通过率动态选择。旧游戏流程
配置仍可使用 `studio.config.game.template.json`。

源码启动、Provider 接入、动态路由、worktree、完整生产流程和故障排查见
[部署、调试与完整使用手册](../docs/部署调试与完整使用手册.md)。

## 前置要求

| 项 | 说明 |
|---|---|
| Windows 10/11 x64 | 监制台是便携 EXE，内含 Electron/Node 运行时；不要求另装 Node.js |
| 至少一个 Provider CLI | 默认支持 codex CLI 与 Claude Code；安装后对应 `--version` 能正常输出 |
| Git | 推荐安装；Git 项目会自动使用独立 worktree。非 Git 项目可运行，但会降级为直接目录模式 |
| Provider 登录 | 按对应 CLI 的官方方式登录；Claude 示例：`"%USERPROFILE%\.local\bin\claude.exe" auth login` |
| 其他厂商 | 使用 `command-cli` Adapter 配置命令和模型参数；Kimi 默认预留但关闭，确认本机命令后再启用 |
| 网络 | 默认使用系统直连或 VPN；仅在明确使用本地 HTTP 代理时填写实际监听地址 |

## 安装

1. 解压本压缩包到任意位置
2. 双击 **部署.bat**，按提示：选安装目录 → （可选）注册第一个项目仓库
3. 监制台自动启动
4. 部署程序会在桌面创建“监制台”快捷方式，以后双击即可启动

若 Windows SmartScreen 显示“未知发布者”，是因为当前便携 EXE 尚未做商业代码签名。只应运行从本项目可信
Release 下载并校验过的安装包；确认来源后可选择“更多信息 → 仍要运行”。

**验收标准只有一条：总览右上角「环境」显示 就绪。**
它背后是四组全链路自检（运行时与 CLI / 凭据与额度 / 项目与目录 / 协议与配置）——
全绿即整个 app 可用。降级/阻断时悬停看原因，或进 设置（右上角 ⚙）看逐项详情，每项都写了修复动作。

## 多项目：一份监制台管所有项目

**新项目不用重装。** 在启动页点「＋ 注册新项目」（或参数页「项目注册」）加第二个项目仓库后，监制台启动会先落**项目启动页**：
每个项目一张监控卡（在途/待验收/待定夺计数 + 需处理红点），点卡进入该项目的驾驶舱，
所有视图只显示该项目的工单；点左上角 logo 随时回启动页换项目。
执行器、agent 编制、额度双闸是账号级共享资源，全局只有一套（全局配置入口 = 启动页右上角 ⚙）。
只注册一个项目时跳过启动页直接进驾驶舱。

## 首次使用（5 分钟上手）

1. **参数页（⚙）**：确认项目注册、角色编制、Agent 采用“自动择优”或你指定的 Provider
2. **工单池**：先给 Orchestrator 起草一张目标单。它会输出结构化 DAG，系统校验后生成 Backend、Frontend、Reviewer、Integrator 等待投子单
3. 执行器 15 秒内自动领单。**默认是试跑模式（零额度）**——全流程真实流转但不真调 AI
4. 走顺后再开实弹：参数页「实弹解锁」→ 执行模式切「实弹」——此后 Agent 调用实际 Provider
5. 你在 **决策台** 验收；委托单会由动态选择的 Auditor 自动代核

## 核心概念速览

- **目录即状态机**：工单 = 安装目录下九个状态文件夹里的 .md 文件，改状态 = 挪文件夹；明文即事实源，随时可手工检查
- **拉取制**：agent 干完自动领下一张（编制人数 = 并发上限，参数页直接调）
- **双闸**：暂停闸门（手动）+ Provider 额度锁；没有专用额度探针的 Provider 仍可手动暂停
- **执行失败态**：CLI 崩溃/超时的单进独立通道等分诊（重投/上呈/废弃），不会悬空
- **角色协议**：`角色协议/` 下的 md 是各角色 Agent 的章程，改了下一单立即生效
- **隔离工作区**：每张 Git 项目实弹工单使用独立 worktree 和分支，完工自动形成检查点；Integrator 按依赖合并
- **安全发布**：已完成的 Integrator 工单可在详情页人工发布；只允许 fast-forward，主项目有新提交或脏改动时会拒绝
- **自动记账**：若安装目录在 git 仓库内，工单流转每 10 分钟自动 commit（只 commit 不 push）

## 常见问题

- **使用 NordVPN 等系统 VPN** → 保持 `网络.代理默认` 为空；不要填写并不存在的 `127.0.0.1:7890`
- **claude 凭据红灯** → 终端跑 `claude auth login`（见前置要求第 4 行）
- **额度读数陈旧** → 正常现象：官方额度端点有账号级限流，监制台按 ≥5 分钟纪律查询并显示最近读数+时间戳，等下个窗口自动恢复
- **端口被占** → 配置里 `server.port` 改一个（参数页也能改），重启生效
- **想换机器/给同事** → 推荐在新机器重新运行套件，再复制旧安装目录中的工单、回执、journal 和配置；项目仓库路径变化后需重新注册

## 支持范围

- 正式支持 Windows 10/11 x64。
- macOS、Linux 和 Windows ARM 原生包尚未提供；不能承诺直接运行。
- 便携 EXE 自带应用运行时，但 Git、Provider CLI 及其登录状态必须在每台机器单独准备。
- Codex/Claude/Kimi 的账号、套餐、API Key 和系统凭据不会随安装目录迁移。
