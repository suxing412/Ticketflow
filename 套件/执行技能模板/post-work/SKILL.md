# 收工汇报（交单前必走，跳过=违纪）

## 一、测试证据（红线，契约分版：程序版 / 审检版）

职权切割（2026-08-06 决议）：**程序不跑测试，测试执行归审检**；装配走静态方法。按本单职能取对应一段，另一段不适用。

### 一·程序版（程序 / 装配单）

1. **静态自查代替跑测试**：`dotnet build`（或本工程等价编译命令）零错误、零新增警告，命令原文与输出结论写进回执。编译没过=不许交单。
2. 回执必列**「受影响测试类清单」**（测试类名），供审检 `--filter` 照单跑子集；漏列或写「跑不了所以没列」=空壳，判官直接不过。
3. 引用既有测试数字时只许**读**已落盘的 `enginectl-results.xml` / `enginectl-baselines/` 归档件并注明时间戳，不许自称跑过。

### 一·审检版（审检 / 质检单）

1. **先子集、后全量**：按上游清单 `unity-test --filter 类名1,类名2` 跑子集；子集绿了再全量定案，**全量必走净室**（`--fresh`＝请求活编辑器排空队列后自退、重新可见拉起再投递，「重启后首跑」即净室）。所有测试都在**带可见窗口的编辑器**里跑，无头启动已整族退役（`--no-attach` 作废）。
2. 全量测试**前台跑完再写回执**——把测试丢后台就交单=空壳，判官直接不过（见部署方坑档案）。
3. 记录 total / passed / failed / 套件时长，与开工基线对照：**新增红灯=不许交单**，修好再交或如实写未达标。
4. 取数口径：数字一律从 `enginectl-results.xml` 根节点属性取（**禁 tail 截尾推数**）；全量成功后 enginectl 输出行的 `baseline` 字段即本轮归档件 `enginectl-baselines/results-<UTC时间戳>.xml`（只留最近 10 份），回执写该文件名作下一轮对照线。

## 二、回执契约（通用章程）

1. **自测结果**：逐条对照工单「验收标准」打 ✓/✗，如实——达不到就写「未达标」，严禁把 ✗ 写成全绿（诚实的 ✗ 走裁决，说谎的 ✓ 记档）。
2. **实际消耗**：用时 + token 双报，必填（通用章程）。
3. **异议**：越界发现、上游问题、工单缺陷——如实记录不代修（历史正例：既往案例76 的异议直接催生了后续修复单）。
4. 返修单：本轮回执开头一行写「相对上轮改了什么」。

## 二a、工单评分（H69 仪表盘，必填）

回执加一节 `## 工单评分`：给**这张工单本身的质量**打 1-5 分并给一句引证理由（不是给你自己的工作打分）。锚定表：

- **5**：一次读懂，边界零歧义，验收标准全部可直接执行
- **4**：个别小瑕疵（措辞/字段级），不影响执行
- **3**：能做，但关键信息要自行推断或翻上游材料补齐
- **2**：边界模糊/验收标准不可判定，靠猜开工
- **1**：边界错配/自相矛盾/做不了（同时应走评估回呈）

裸打分无效，必须引证工单原文说明扣分点。此分供制作人层评估拆单质量，与你的工作评价无关——如实打。

## 三、收尾卫生

1. 临时诊断代码/日志清理干净；`git status` 只含声明写区内的改动。
2. 禁用语自查：回执中不得出现 "In progress" / "Waiting" / 「跑完后补数」类字样——这些字样=空壳标志（通用章程）。
