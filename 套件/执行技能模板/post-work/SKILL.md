# 收工汇报（交单前必走，跳过=违纪）

## 一、测试证据（红线）

1. 全量测试**前台跑完再写回执**——把测试丢后台就交单=空壳，判官直接不过（TK-84 案）。
2. 记录 total / passed / failed / 套件时长，与开工基线对照：**新增红灯=不许交单**，修好再交或如实写未达标。

## 二、回执契约（通用章程格式，缺项=不合格）

1. **自测结果**：逐条对照工单「验收标准」打 ✓/✗，如实——达不到就写「未达标」，严禁把 ✗ 写成全绿（诚实的 ✗ 走裁决，说谎的 ✓ 记档）。
2. **实际消耗**：用时 + token 双报，必填（通用章程 2026-08-04 补款）。
3. **异议**：越界发现、上游问题、工单缺陷——如实记录不代修（历史正例：TK-75/76 的异议直接催生了后续修复单）。
4. 返修单：本轮回执开头一行写「相对上轮改了什么」。

## 三、收尾卫生

1. 临时诊断代码/日志清理干净；`git status` 只含声明写区内的改动。
2. 禁用语自查：回执中不得出现 "In progress" / "Waiting" / 「跑完后补数」类字样——这些字样=空壳标志（通用章程：测试没跑完不许交单）。
